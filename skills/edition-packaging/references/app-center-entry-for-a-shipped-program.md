# An app center entry for a program the edition ships (ORDER 17, milestone 6)

CloudCompare was the first program shipped in stereo by a lane with no app center row. The row, the package that carries it and the proof are short; what they taught is below. Written 2026-11-18 on sparky-aptus-stereo-appcenter 0.1.12+lc1.

## Recipe

1. **The row.** One object in the fork's `stereo/catalogue.json`: `id`, `name`, `section`, `kind` `apt`, `package`. The page that says what the program is for the person decides `section` (`media` is "Stereo players, editors and tools": viewers and editors of stereo content, CloudCompare, F3D, Blender; `tools` is what the person may add from Debian; `vr`, `emulation` and `vpn` are what they say). Read Paweł's `9/` tree for the program first (the edition's app center follows his and the two stay alike): CloudCompare has no entry there.
2. **The test.** One case in `stereo/tests/entries.py`: section, kind, package; visible only when the sources offer the package; the exact `apt-get install name=candidate` command the action runs. The suite (`entries.py`, `tools.py`, `displaycal.py`, `zram.py`) needs python3-apt: run it in a container with `SPARKY_INSTALL_DOWNLOADS_LIB` naming sparky-stereo-apt's `install-downloads` folder of the build tree.
3. **The package.** In the build tree: `VERSION` in `build.sh`, a CHANGELOG entry, and the gitlink `sparky-os/sparky-aptus-stereo-appcenter` moved to the fork commit (`git update-index --cacheinfo 160000,SHA,sparky-os/sparky-aptus-stereo-appcenter`). Build with `OUT=... APTUS_SOURCE=<fork checkout> bash build.sh` after `sparky_provenance_init` (`SOURCE_DATE_EPOCH` = the recipe commit's time), then `python3 -m lean.release check-debs`. The standalone recipe leaves no `.buildinfo`: write it with `dpkg-genbuildinfo --build=binary` and `dpkg-genchanges --build=binary` in the unpacked source (copy the debs into its parent first), then run check-debs once more so the build record is complete.
4. **The comparison.** `dpkg-deb -c` of both versions: the same file names; only `catalogue.json`, the CHANGELOG and the two `dpkg-stereo/lc/*/all.json` manifests (they hold file hashes) differ.
5. **The proof, in one container.** Install the staged deb with apt (dependencies come from the edition repository, `deb-multimedia` and Sparky's own `core`/`tiamat` suites), the program's staged deb as a flat repository (`dpkg-scanpackages`, `Pin: origin ""`), then: `actions/entry status ID` in two languages (`LC_ALL=pt_BR.UTF-8`), `appcenter --render` for the card inside its section (the heading is the translated section title), `catalogue.route('aptus://stereo_entry_ID_install')` for the click's command, `apt-get -s install PACKAGE` for what it would install and its size, and the action itself in the throwaway container.

## Traps, symptom first

- **Symptom:** the build tree's gitlink for the app center is older than the changelog says. **Cause:** an unrelated commit (ORDER 108's toy package) moved the pointer back from 59cc9bb (0.1.11) to 27f99a2 (0.1.10) when it staged its files. **Fix:** every app center version sets the gitlink itself and the review compares it with the fork commit. **How found:** `git log -- sparky-os/sparky-aptus-stereo-appcenter` while reading what 0.1.11 had pointed at.
- **Symptom:** `apt-get install` of the staged deb: "sparky-aptus-appcenter ... not installable". **Cause:** Paweł's package lives in Sparky's own suites (`repo.sparkylinux.org` core and tiamat, key `/etc/apt/trusted.gpg.d/sparky-repo.asc`), and `sparky-stereo-hardware` wants `nvidia-detect` from Debian's non-free. **Fix:** add both sources to the rig.
- **Symptom:** the keyring package fails to unpack in the rig. **Cause:** the key file was bind-mounted read-only at the path the package installs. **Fix:** mount it elsewhere and copy it, and remove the rig's own deb-multimedia source after the install (the package brings its own, and apt refuses two Signed-By).
- **Symptom:** `tests/catalogue.py` and `tests/handler.py` of the recipe fail. **Cause:** both fail on the previous version's source too (handler.py asserts the same way; catalogue.py names `sparky-stereo-mime-models` and `sparky-stereo-plasma-theme-studio`, which the lists do not know); handler.py wants the path of the `handler` file, catalogue.py the catalogue and the lists folder. **Fix:** none here; say it, and compare with the previous version.
- **Symptom:** `dpkg-genchanges` cannot find the buildinfo or a deb. **Cause:** it looks in the parent of the source. **Fix:** copy them there.
