# Carrying a package Debian removed

**For** a packager asked to bring back a piece that Debian testing no longer has: how to read why it left, which source to take, the version that sorts right, how to prove a toolkit theme in the edition's session, and the traps met.
Learned on the whole Oxygen suite (queue row 59, 23 November 2026): the Oxygen fonts, KDE's Oxygen engine for GTK 2, the Oxygen style for Qt 5 and KDE's Oxygen engine for GTK 3.
The general carry rules (britney, RC bugs, retirement) are in [carried from Debian unstable](carried-from-debian-unstable.md); this page adds what a removed piece needs before them.

## The recipe

1. **Read the indexes, not the web pages.**
   Fetch `InRelease`, `main/binary-amd64/Packages.xz` and `main/source/Sources.xz` of testing at a dated instant (`https://snapshot.debian.org/archive/debian/INSTANT/dists/testing/...`, `curl -L`), of today's testing and of unstable, check each `InRelease` with `gpgv --keyring /usr/share/keyrings/debian-archive-keyring.pgp`, and each file against its `SHA256` line.
   Then report every name by binary and by source, in every suite: a binary can leave while its source stays (the Qt 5 style left Debian's `oxygen` source, which is still in testing).
2. **Read Debian's reason from `removals.txt` and every `removals-YEAR.txt`, by whole block.**
   A block is `[Date] [ftpmaster]`, `Removed the following packages from SUITE:`, the package lines, then `Reason` and the bugs.
   Only a removal **from unstable** is the reason; `from experimental` with `[auto-cruft] NVIU` is housekeeping of experimental and says nothing (the Qt 5 style had seven of those).
   Sort what you find:
   - `ROM; ...` is the maintainer's request, with the words that matter after it ("Abandoned upstream", "broken with GTK >= 3.16");
   - `[auto-cruft] NBS (no longer built by SOURCE, ...)` means the source stopped building the binary: read that source's `debian/changelog` for the entry that did it (oxygen 4:6.6.3-1: "Drop Qt5/KF5 support"), then check upstream before calling it upstream's decision.
3. **Read every bug the removal closed** over the BTS SOAP interface (`get_status`): a removal closes open bugs with a `+rm` version without fixing them.
   The GTK 2 engine's removal closed ten, four of them crashes; each is either fixed by a later upstream commit, about a program that no longer exists on that toolkit, or work to do before shipping.
4. **Read the suite history:** `https://sources.debian.org/api/src/SOURCE/` names the last release that has it (bookworm for the fonts and the GTK 2 engine, jessie for the GTK 3 engine, trixie for the Qt 5 style).
5. **Read upstream's state from the forge's API,** not from a news page: the project's path (KDE moves dead trees to `unmaintained/`), `archived`, `last_activity_at`, every branch, the tags, and the commits after the last release (`/repository/commits?ref_name=BRANCH&since=DATE`).
   A build option is read from the tag's own `CMakeLists.txt` (`curl https://invent.kde.org/GROUP/PROJECT/-/raw/TAG/CMakeLists.txt`): KDE's oxygen keeps `option(BUILD_QT5 "Build Qt5 style" ON)` at v6.7.4 and on master, so Debian's drop was Debian's.
6. **Check SparkyLinux's own suites** (core, tiamat, orion, sisters) with Paweł's key: a piece SparkyLinux hosts is not ours to carry.
7. **Measure who uses the toolkit** before carrying a theme for it: the image lists and the base ISO's package list against the dated `Packages`, direct `Depends` on the toolkit's library (GTK 2: no program of the edition, and only pidgin, pidgin-plugin-pack and cdebconf-gtk in all of testing; Qt 5 widgets: 47 names of the edition).
8. **Decide by the reason** (Daniel, 2026-11-17: "it's missing there for a good reason? if not, we keep it if sparkylinux itself won't host it"):
   | Found | Do |
   | --- | --- |
   | Upstream ended it with a successor, or it cannot work on today's toolkit (measured) | Do not build it; quote the reason and the measurement, and name what takes its place |
   | Abandoned upstream, no defect that today's programs meet, nothing of the same kind replaces it | Carry Debian's last source with upstream's later commits |
   | A distribution dropped a build option upstream still supports | Build upstream's release with the option, from the distribution's last packaging of it, under a source name of its own |
9. **Take the source:** Debian's last `.dsc` from snapshot.debian.org (`/mr/package/SOURCE/VERSION/srcfiles?fileinfo=1`, then `/file/SHA1`), its signature checked with `debian-keyring.pgp` and, when the signer's key has left the keyring (a 2018 NMU did), the `.dsc`'s SHA-256 found in the signed `Sources` of the release that had it.
   Upstream's commits after the last release are carried as DEP-3 patches with `Origin: upstream`, the commit's URL, the author by name and `Applied-Upstream: master, COMMIT`; leave out commits that only rewrite licence headers, and say why each other one is left out.
10. **Version it:** `+stereo3dN` is for stereo changes; a plain carried package takes `+sparkyN`, as the edition's other non-stereo carries do (dkms, snmptt, urfkill, xfsprogs, command-not-found).
    The new version must sort above the last version a machine can still have, not only above the source's: the Qt 5 style's last binary was `4:6.5.4-1+b1`, so `4:6.7.4-1+sparky1`; the fonts `4:5.4.3-4+sparky1` (above bookworm's `4:5.4.3-4`, below a Debian `4:5.4.3-5`).
    Keep the epoch of the binary you replace.
11. **Build, then prove it red and green:** Debian's unchanged source on today's testing first (it may no longer build at all), then the recipe; the stage holds the source closure as [rebuilt packages](rebuilt-packages.md) and the Lean Code pages ask.

## A build option a distribution dropped: a source of its own

Debian's oxygen 4:6.7.4-1 builds only the Qt 6 style.
The Qt 5 style is KDE's same release built with `-DBUILD_QT5=ON -DBUILD_QT6=OFF`: upstream's Qt 6 block alone installs the colour schemes, cursors, decoration, look and feel, wallpapers and translations, so a Qt 5 only build installs only the style, its library and its settings library, and nothing collides with Debian's Qt 6 packages.
The recipe takes Debian's current `.dsc` for the orig tarball and its signature (renamed to the new source's name, the bytes unchanged), Debian's current `debian/` reduced by a script to the Qt 5 stanzas and `.install` files of the last Debian release that built them, and the Qt 5 build dependencies from that release.
The Qt 5 settings library's catalogue moved to Debian's `liboxygenstyleconfig-data` in 4:6.6.3-1, which `Breaks` the Qt 5 library only below that version: leave the catalogue out of ours and depend on Debian's.
A source name of its own (`oxygen-qt5`) leaves Debian's `oxygen` untouched, so the pin generator blocks only the three Qt 5 names.

### The second one: Plasma's platform theme for Qt 5 (`plasma-integration-qt5`)

The same shape, with two things the style did not have.
- **Keep Debian's binary name, at a version that escapes Debian's own Breaks.** Debian's last Qt 5 build was `plasma5-integration` 6.5.4-2 (removed from unstable on 2026-04-08, `[auto-cruft] NBS`; trixie still has 6.3.6-1+b3). Debian's current `plasma-integration` 6.7.4-1+b1 ships the 55 `plasmaintegration5.mo` catalogues and `Breaks`/`Replaces: plasma5-integration (<< 6.5.90~)`. So the edition's build is `plasma5-integration` 6.7.4-1+sparky1+lc1: above every binary a machine can have, and above 6.5.90, so Debian's package does not break it. A machine upgraded from trixie gets it as an upgrade of the package it has.
- **Install only what the Qt 5 block builds.** Upstream installs the translations in its Qt 6 block only (`ki18n_install(../po)` in `qt6/`), so a `-DBUILD_QT5=ON -DBUILD_QT6=OFF` build has no catalogue, and Debian 6.5.4-2's `.install` line for `plasmaintegration5.mo` would match nothing. The Qt 5 plugin carries no translation domain (`strings -a` of Debian's own 6.5.4-2 `KDEPlasmaPlatformTheme5.so` finds no `plasmaintegration`), so nothing is lost by leaving the catalogues to `plasma-integration`.
- **Read the dependencies at the instant you build on:** the 26 build packages (KF5 5.116, Qt 5.15.19, `libkf5wayland-dev`, `qtwayland5-dev-tools`, `plasma-wayland-protocols` and the rest) were all in testing on 2026-11-19, 2026-11-21 and 2026-11-23. Debian's last binary named `qtbase-abi-5-15-17`, which no longer exists (Qt 5.15.19 provides `qtbase-abi-5-15-19`): the old binary cannot install today, a rebuild takes the right name from shlibs.
- **What it gives a Qt 5 program** (upstream's `qt5/src/platformtheme`): the style named by `kdeglobals [KDE] widgetStyle` through KF5's KConfig cascade (the look's `kdedefaults`, then the person's file), the palette, the fonts, the icon theme and icon engine, KDE's key bindings and button texts, KDE's file dialog or the portal's, the tray icon, the global menu, the Qt Quick Controls theme. It loads under the platform theme key `kde`, which Qt 5 picks in a session with `XDG_CURRENT_DESKTOP=KDE`.

## A successor whose only fault is a file upstream already removed

Debian's `oxygen-icon-theme` 5:6.32.0-1 (source `kf6-oxygen-icons`) installs with no `icon-theme.cache`: `gtk-update-icon-cache` rejects the cache it generates while three entries with a space in their names are present (`simbolicActions/22x22/actions/go-first copy.svg`, the same at 24x24, a symlink at 48x48). KDE removed them after the 6.32.0 tag (commit 5bfe4322, Nuno Pinheiro; KDE bug 528955; Debian bug 1154120).
The recipe (`packages/kf6-oxygen-icons`):
1. **Build on a dated instant that has Debian's version** (Frameworks 6.32 reached testing between the published tree's instant and 2026-11-21: snapshot 20261121T150000Z), in a builder image made at that instant, with the link gate's archive at the same instant.
2. **Debian's source, one upstream commit, nothing else.** The source had no `debian/patches`; the recipe starts the series with the commit as a DEP-3 patch. GNU patch applies a git diff that deletes files and a symlink whose names contain a space, as long as each `---` line ends with a tab.
3. **The version keeps Debian's epoch** (the source itself is `5:`): `5:6.32.0-1+sparky1+lc1` sorts above the last binary and below Debian's next upload, which is the retirement. The recipe's README says when it is retired: when Debian's own fix reaches testing.
4. **Red and green are install rows, not build rows:** Debian's package in a clean testing container (the cache absent, apt's lines read), then ours by apt over it (the cache's size, `gtk-update-icon-cache --validate` exit 0), then ours on a fresh container; the file list against Debian's leaves only the three entries.

## The toolkit theme, proved in the session

A theme is selected by something different in each toolkit; name it in every row.
- **GTK 3 engines are gone:** GTK 3.24 says `The 'engine' property is ignored` and `Theming engine 'oxygen-gtk' not found`, never maps the engine library, and a theme whose drawing was all in the engine draws no frames, buttons, slider or progress bar (KDE's oxygen-gtk GTK 3 branch, built on GTK 3.24.52, measured beside Adwaita).
  So a GTK 3 look is CSS only; the edition's Oxygen look for GTK 3 and 4 is `Sparky-Stereo-Oxygen` and `-Dark` (Breeze GTK's shapes in Oxygen's colours, picked by `sparky-stereo-gtk-sync`).
- **Plasma's Qt 5 platform theme is not in Debian any more:** Debian's plasma-integration 6.7.4 ships `KDEPlasmaPlatformTheme6.so` only (`-DBUILD_QT5=OFF`), while upstream still builds the Qt 5 one; a Qt 5 program in a Plasma session then takes Qt 5's own KDE theme.
- **KDE still selects a GTK 2 theme:** the GTK settings module (`kde-config-gtk-style`, its kded module) still has `setGtk2Theme` and reads `GTK2_RC_FILES`.

Measured in a real Plasma login of the edition (row 59), each program alone, its own report of what it loaded:
- **Qt 5:** with the Qt 5 style installed, a Qt 5 program wears Oxygen by itself (`oxygen5.so` mapped; Fusion before), and keeps it after the person picks Fusion on Application Style (`kdeglobals [KDE] widgetStyle=Fusion`): Qt 5's own KDE theme chooses, not the setting. Following the person's choice needs plasma-integration's Qt 5 platform theme.
- **GTK 2:** Plasma's session sets `GTK2_RC_FILES=/etc/gtk-2.0/gtkrc:~/.gtkrc-2.0:~/.config/gtkrc-2.0`, and GTK 2 takes the session's one theme name; a theme with no `gtk-2.0` part gives GTK 2's own plain look. KDE's GTK page (`qdbus6 org.kde.kded6 /modules/gtkconfig org.kde.GtkConfig.setGtkTheme oxygen-gtk`) writes `gtk-theme-name="oxygen-gtk"` to `~/.gtkrc-2.0` and the engine loads, but the same call renames the GTK 3 theme, and GTK 3 programs then draw Adwaita. A `gtk-2.0/gtkrc` in the edition's own theme with `include "/usr/share/themes/oxygen-gtk/gtk-2.0/gtkrc"` gives GTK 2 the engine under the session's theme name and leaves GTK 3 unchanged.
- **oxygen-gtk 1.4.6 draws Oxygen's light colours** in a session with a dark scheme: it reads KDE 4's configuration paths, which Plasma 6 does not write.

The rig: one fresh `startplasma-wayland` login per case ([stereo-proof-rig, a real login](../../stereo-proof-rig/references/login-splash.md)), KWin on a card through CDI, the output in its side by side 3D twin, the cases run as `DESKTOP_PROBE` inside the session, captures with ScreenShot2; the person's depth limits saved at 0 for the eye check (`kwinrc [StereoDepth]` `SunkLimit`, `PoppedLimit`, `ElementLimit`), and then every capture has 0 differing pixels between the eyes.

## Traps, symptom first

- **Symptom:** a source from 2014 or 2015 stops at configure with `CMake Error at CMakeLists.txt:3 (cmake_minimum_required): Compatibility with CMake < 3.5 has been removed from CMake.` **Cause:** CMake 4 (testing has 4.3.4) dropped compatibility below 3.5. **Fix:** carry upstream's own raise when it exists (oxygen-gtk a8798db8, Nicolas Fella, 3.16); where it does not, raise it the same way in a patch of ours that names that commit as the technique (the Oxygen fonts). **Found by:** building Debian's unchanged source first, the red run.
- **Symptom:** the recipe's source builds, then `dpkg-checkbuilddeps: error: unmet build dependencies: node-acorn nodejs`. **Cause:** Lean Code's prepare step adds `gcc node-acorn nodejs perl python3 python3-yaml` to the lean source's `Build-Depends` (`lean/debian_prepare.py`). **Fix:** the runner installs them with the source's own dependencies. **Found by:** the build log's last lines.
- **Symptom:** `dh: error: Hook target execute_before_dh_auto_clean is only supported in compat 10 or later` at the clean step of the lean source. **Cause:** Lean Code's prepare step adds `execute_before_dh_auto_clean` and `execute_before_dh_auto_configure` to `debian/rules`, and an old package's `debian/compat` says 9 (debhelper 14 also warns that levels before 10 are deprecated). **Fix:** raise `debian/compat` to 10 in the recipe, after checking that it says 9; for a CMake build, compat 10 only makes `--parallel` the default. **Found by:** the build log's last lines (the GTK 2 engine, Debian 1.4.6-1.1).
- **Symptom:** a probe started in the session prints `Authorization required, but no authorization protocol specified` and `cannot open display: :0`. **Cause:** a program the person starts inherits Plasma's environment, and the probe had only `DISPLAY`, not `XAUTHORITY` (nor `XDG_CONFIG_DIRS` with the look's `kdedefaults`). **Fix:** read plasmashell's `/proc/PID/environ` (its PID from `pgrep -x plasmashell`) and export it before each program. **Found by:** the probe's log, then KWin's `xauth_` file named in plasmashell's environment.
- **Symptom:** every capture of the desktop differs between the eyes in about 600,000 pixels. **Cause:** the edition's desktop depth is on (wallpaper sunk, windows and panels on their planes). **Fix:** save the person's limits at 0 before the login; 2D programs then give equal eyes. **Found by:** the difference box covering the whole screen, the empty desktop included.
- **Symptom:** `docker: Error response from daemon: invalid mount config for type "bind": stat PUBLISHED_TREE: permission denied`. **Cause:** the Docker socket the lane is given does not serve the published tree's path. **Fix:** a partial mirror in the lane's scratch: the tree's `InRelease` and `Packages` checked with the edition's key, then the pool files a throwaway container's `apt-get --print-uris` names, each copied (never linked) and checked against the index; deb-multimedia frozen the same way when the tree's FFmpeg needs it. **Found by:** the rig image script's first line of output.
- **Symptom:** a `.dsc` from snapshot.debian.org says `Can't check signature: No public key`. **Cause:** the uploader of a 2018 NMU is no longer in `debian-keyring.pgp`. **Fix:** find the `.dsc`'s SHA-256 in the signed `Sources` of the release that shipped it (bookworm's `InRelease` checked with the archive keyring). **Found by:** gpgv's last line.
- **Symptom:** a carried commit's patch would put a person's address into the build tree. **Cause:** the commit adds a file whose copyright block names its authors with their addresses, or its message has a `Signed-off-by` line. **Fix:** a converter that keeps the author's name and drops the address from the header and the description, and refuses a diff that carries one; leave such a commit out when it changes nothing today, and say so (oxygen-gtk b1ee5fb8 moves the Mozilla program names, and no Mozilla program is a GTK 2 program any more). **Found by:** a check for addresses over every written patch.
- **Symptom:** a removal log search finds the package only in `from experimental` blocks. **Cause:** the binary left unstable as `[auto-cruft] NBS` when its source stopped building it, recorded under the binary's own name in the year it happened. **Fix:** search every year's file for the binary names, read the whole block and the source's changelog. **Found by:** `removals.txt` of 2026, block of 2026-04-08.
- **Symptom:** a recipe stops right after `dpkg-source: info: applying ...patch` with no message. **Cause:** the recipe's own check that no name with a space is left (`find . -name '* *'`) counted quilt's backups of the removed files in `.pc/`, and a bare `[ -z ... ]` under `set -e` exits silently. **Fix:** prune `./.pc` with `./debian`, and make the check print what it found before it exits. **Found by:** `find` in the failed build tree.
- **Symptom:** an install that should run offline from archives downloaded in an earlier step says `Temporary failure resolving 'snapshot.debian.org'` for packages the download step fetched. **Cause:** the Debian container image's `/etc/apt/apt.conf.d/docker-clean` (`DPkg::Post-Invoke { "rm -f /var/cache/apt/archives/*.deb ..." }`) empties the archive cache after every dpkg run, so the first offline install deletes the rest; and an epoch is written `%3a` in an archive's file name (`oxygen-icon-theme_5%3a6.32.0-1_all.deb`), so a glob without it finds nothing. **Fix:** remove `docker-clean` in the download step, before `apt-get --download-only`, and name the archive with `%3a`. **Found by:** the red row's install log, then the base image's `apt.conf.d`.
- **Symptom:** `apt-get install sparky-stereo-look` (Recommends on) on the published edition installs the newly recommended `fonts-oxygen` and `gtk2-engines-oxygen` but not `kde-style-oxygen-qt5`, which apt does not even list as recommended. **Cause:** the published look already recommended it while no archive had it; apt acts only on Recommends that an upgrade adds, never on one the installed version already had. **Fix:** a piece a designed default needs is a `Depends` (the house rule with design-check-every-default); a Recommends that could not be met before never arrives on upgraded machines. sparky-stereo-look 20261123.2 Depends on `kde-style-oxygen-qt5`, `plasma5-integration`, `fonts-oxygen` and `sparky-stereo-gtk (>= 20261123~sparky9~0+lc1)`, which brings `gtk2-engines-oxygen`; a bare `apt-get dist-upgrade` on the published edition then brings all four. **Found by:** the install proof's `simulate.txt` (no "Recommended packages" line) against the published look's `Recommends`.
- **Symptom:** the new `sparky-stereo-gtk` is not upgraded by `apt-get install sparky-stereo-look`, and `apt-get dist-upgrade` says `The following packages have been kept back: sparky-stereo-gtk`. **Cause:** the look's `Depends: sparky-stereo-gtk` is unversioned, so the installed old version satisfies it; and the published Kubabbar Glass 20261104.1 Depends on `sparky-stereo-gtk (= 20261104.1~sparky9~0+lc1)`. **Fix:** a versioned Depends where a feature needs the new version, and Kubabbar Glass's successor built by the same script with the GTK successor (`build_packages.sh` with no flag; its Depends is `>=` since 562abdd8d), so the round carries both. **Found by:** the install proof on a rig with the published Kubabbar Glass installed first.
- **Symptom:** `dh_install: warning: Cannot find (any matches for) "usr/lib/*/qt5/plugins/platformthemes/KDEPlasmaPlatformTheme5.so" (tried in ., debian/tmp)` and `dh_install: error: missing files, aborting`, though CMake printed `-- Installing: .../debian/plasma5-integration/usr/lib/...`. **Cause:** a source reduced to one binary package: debhelper then installs straight into `debian/PACKAGE`, and the `.install` file carried from the release that built two packages looks in `debian/tmp`. **Fix:** no `.install` file for the single package, and a check after the build that its payload is what the reduced build should install (here the plugin, its two docs and Lean Code's manifest). **Found by:** the build log's `Installing:` line against the dh_install warning.
- **Symptom:** after a probe "puts the person's choice back" with `kwriteconfig6 --file kdeglobals --group KDE --key widgetStyle --delete`, a Qt 6 program draws Breeze, not the look's Oxygen. **Cause:** `--delete` writes `widgetStyle[$d]`, KConfig's deletion marker, which also hides the value of the files below it (the look's `kdedefaults`), so Qt 6 falls back to its built-in default; it is not what System Settings writes. **Fix:** emulate the person's pick with the same line as the first pick, `--key widgetStyle Oxygen`. **Found by:** the probe's `kdeglobals` after the step (`widgetStyle[$d]`) against the Qt 6 program's style.
- **Symptom:** a GTK 3 program's capture differs from the published edition's in about 21,000 pixels after a change that does not touch GTK 3. **Cause:** a band at the screen's bottom edge under the panel varies from one login to the next: two logins of the unchanged published edition differed there in 20,984 pixels and nowhere else. **Fix:** compare toolkit captures above the panel strip (the bottom 40 rows of each eye), between logins that ran the same cases; then the edition with the GTK successor and the published one differ in 0 pixels. **Found by:** locating the differing rows (760 to 799 only), then a second login of the published edition.
- **Symptom:** a script package built by a recipe that calls `lean.standalone` itself has its `.dsc` and debs but no `.buildinfo`, `.changes` or `*.sparky-build.json`, so its stage is not a source closure. **Cause:** only some recipes run the two steps after it (`repo/rebuild-script-source.py` on the `.dsc`, then `lean.release check-debs` with the provenance facts of `build-provenance.sh`); `kubabbar-glass/tools/build_packages.sh` did not. **Fix:** run both in the recipe's `build()`, as `sparky-stereo-look/build.sh` does, and pass `SPARKY_PROV_ARGS` into the container that runs it. **Found by:** comparing the two recipes' `build()` before the first GTK build.
- **Symptom:** the first `git add` in a freshly cloned sparse build tree runs for minutes with `folio_wait_bit_common` in `/proc/PID/wchan`. **Cause:** after a clone, files written in the same second as the index are racily clean, so git hashes them again, here under a station's heavy disk pressure (`/proc/pressure/io`). **Fix:** let it finish once; the next commands are quick. **Found by:** the process's open files and wait channel.
