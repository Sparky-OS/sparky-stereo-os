# Packaging a third-party KTextEditor plugin (Katemark, ORDER 51)

Written 2026-11-20 from ORDER 51: Katemark 0.4.7 (Olivier Booklage's Markdown preview for Kate, a fork of uwuclxdy's Katdown; Qt 6.5 or later, KDE Frameworks 6, QtWebEngine), built as `katemark 0.4.7-1+lc1` for Kate 4:26.08.2 from Debian.
The recipe is `sparky-os/packages/katemark/` in the build tree; it copies headsetcontrol's form (an orig tarball pinned by SHA-256, commit and git tree id; `debian/` tracked beside it; `release/build-dh-lean.sh`).

## Recipe, as run

1. **Reconcile first.** Debian: `apt-cache policy NAME` and `apt-cache search` in a clean `debian:testing` container with the edition's repository at pin 1001 (Debian had no katemark; Kate itself is Debian's own `kate`, not an edition build, built against the edition's Qt). Upstream: the releases API for the newest tag, the tag's commit (the codeload tarball's pax `comment` header names it), the issues that mention building or loading, and the repository's AI rule (`.github/CONTRIBUTING.md`, the issue and pull request templates).
2. **The plugin's place and the ABI.** `kcoreaddons_add_plugin(... INSTALL_NAMESPACE "kf6/ktexteditor")` installs `usr/lib/x86_64-linux-gnu/qt6/plugins/kf6/ktexteditor/katemark.so`; Kate's own log line `kf.coreaddons: Checking for plugins in ("/usr/bin/kf6/ktexteditor", "/usr/lib/x86_64-linux-gnu/qt6/plugins/kf6/ktexteditor")` (`QT_LOGGING_RULES=kf.coreaddons.debug=true`) names the folders it reads. `dh_shlibdeps` writes the ABI as `libkf6texteditor6 (>= 6.28.0)`, `libqt6core6t64 (>= 6.11.2)` and the WebEngine libraries; add `Depends: kate` yourself, since a plugin needs a host.
3. **Build dependencies are Debian's names, not the author's.** The author's `build.sh` lists KDE neon's names (`kf6-ktexteditor-dev`); Debian's are `libkf6texteditor-dev`, `libkf6coreaddons-dev`, `libkf6i18n-dev`, `libkf6config-dev`, `libkf6xmlgui-dev`, `libkf6widgetsaddons-dev`, `libkf6syntaxhighlighting-dev`, plus `qt6-base-dev`, `qt6-webengine-dev`, `extra-cmake-modules`, `gettext` and `poppler-utils` (the export test reads a PDF back). Check every name with `apt-cache policy` before it enters `Build-Depends`.
4. **The upstream tests run in the build.** Five Qt Test programs drive QtWebEngine; with their own `--disable-gpu --no-sandbox` and the offscreen platform they pass in a build container with no display (5 of 5, about 25 s).
5. **The link and start gate needs deb-multimedia in its archive list** (trap 3), then reports `archive-qualified link check passed for 1 packages` and a build record with `recipeDirty` false and `unrecorded` empty. The same source built three times gave the same `.deb` bytes (the orig tarball is made by `make-orig.sh` byte for byte).
6. **Vendored JavaScript.** Upstream compiles twelve minified libraries into the plugin through a Qt resource file (markdown-it 14.1.0 and seven plugins, markdown-it-texmath, KaTeX 0.19.0, Mermaid 12.1.0, highlight.js 11.10.0, js-yaml 4.1.0) and a stylesheet that embeds the KaTeX fonts. Read each file's own banner for its version and licence; Mermaid's bundle ends with a "Bundled license information" block that names what else it holds (DOMPurify, lodash-es, cytoscape and a few small ones), and the licence headers of the libraries the minifier stripped cannot be read from the file: say so in `debian/copyright`. Debian's copies (`libjs-katex` 0.16.10, `node-mermaid` 9.2.2, `libjs-highlight.js` 10.7.3, `node-markdown-it` named 22.2.3 but at markdown-it 10 in its changelog) are older than what the plugin was tested with, and the plugin has them inside its binary: using Debian's means changing the resource file and retesting four major versions, so keep upstream's and say why in `debian/README.Debian`.
7. **What the plugin can fetch**, found by grepping the source for `http`, `QNetworkRequest`, `QWebEngineSettings` and the request interceptor: the settings page's "Check for updates" button (one HTTPS request to the releases API of the author's repository, only when clicked) and the off-by-default "Load media previews from remote URLs" setting. Nothing else; list both in the package description and in the proof.

## Proving a QtWebEngine preview with no network

- A throwaway image from the red container plus the package (`tests/rig-image.sh` makes `-red` without and `-green` with the staged package), run with `--network none` (the container's `ip -brief addr` shows only `lo`, and `getent hosts` of a public name exits 2).
- A virtual Stereo KWin in the container, Kate on Wayland with `QTWEBENGINE_CHROMIUM_FLAGS="--disable-gpu --no-sandbox"`, keys and clicks through the rig's `fakeinput` ([the rig](../../stereo-proof-rig/SKILL.md)), plain PNG captures through ScreenShot2.
- Drive the person's way in, not a guessed config: Ctrl+Shift+comma, Plugins, the Katemark row (listed, unticked), tick it, OK, Ctrl+Shift+M. Captures: the plugin list with the row, the preview with a heading, a table, a rendered Mermaid diagram and a KaTeX formula, then the editor moved and the preview following it.
- Scroll sync is the preview following the editor's visible lines: moving the cursor inside the visible lines moves nothing. Use Ctrl+Down to scroll the view, Ctrl+End and Ctrl+Home; the preview back at the start must equal the first capture (0.000 of its pixels differ).
- Red: the same image without the package has no Katemark row between "Kate Debugger" and "Keyboard Macros", and Ctrl+Shift+M does nothing.

## Traps (symptom, cause, fix, how found)

1. **Symptom:** the build stops with `builddeps:/work/lean-source:amd64 Depends kf6-ktexteditor-dev but none of the choices are installable: [no choices]`. **Cause:** the names came from the author's neon-based build script. **Fix:** Debian's `libkf6...-dev` names (step 3). **Found by:** `apt-cache search -n 'kf6.*texteditor'` in a clean testing container.
2. **Symptom:** `tar: debian/changelog: time stamp ... is 1933 s in the future` and `$SOURCE_DATE_EPOCH: Numerical result out of range`. **Cause:** the changelog's trailer date was later than the machine's clock; the recipe's source date is the changelog's. **Fix:** date the entry in the past.
3. **Symptom:** the build finishes its compile and tests, then `archive case-...-solve failed ... libavcodec63:amd64=10:9.0.2-dmo1+stereo3d15+lc1 Depends libaom3 (>= 1:3.15.3) but none of the choices are installable`. **Cause:** Kate's libraries pull Qt Multimedia, whose edition build depends on deb-multimedia's FFmpeg, and the gate's `sources.json` listed only Debian and the edition. **Fix:** add deb-multimedia (`https://www.deb-multimedia.org`, suite `forky`, components `main` and `non-free`) with the keyring of the edition's `deb-multimedia-keyring` package (`dpkg-deb -x` it, copy `usr/share/keyrings/deb-multimedia-keyring.pgp` under `/archive/keyrings`). The proof image needs the same source: an install of Kate on the edition's pin fails with the same `libaom3` line without it. **Found by:** the gate's own `case-...-solve.log`.
4. **Symptom:** `E: Unable to locate package qt6-webengine-data` building the proof image. **Cause:** the name was from memory. **Fix:** drop it; `libqt6webenginewidgets6` pulls what runs.
5. **Symptom:** every ScreenShot2 call says `Screenshot got cancelled (36)`, and `kwin.log` says `Failed to open drm node /dev/dri/renderD129` and `Configured compositor not supported by Platform. Falling back to defaults`. **Cause:** the virtual KWin had no render node. **Fix:** give the container one (`--device /dev/dri/renderD128 --group-add GID`); a QPainter compositor is not supported by the virtual platform.
6. **Symptom:** Kate runs and shows the Markdown file, but Ctrl+Shift+M does nothing and the Tools menu has no Katemark entry, though `kate.log` says the plugin file was found. **Cause:** the plugin is off until ticked; two guessed `[Kate Plugins]` keys in `katerc` (`katemark`, `katemarkplugin`) did not enable it. **Fix:** tick it in Configure Kate, Plugins (the proof does that through fake input). **Found by:** the Tools menu capture, then the Plugins page capture showing the row unticked.
7. **Symptom:** the preview is a narrow column and the diagram and formula do not fit; double-clicking the title bar does nothing. **Cause:** the rig's KWin has no decoration plugin, so the double click is not a maximize. **Fix:** click the window's maximize button.
8. **Symptom:** lintian's errors on the first source: `build-depends-on-build-essential-package-without-using-version g++`; and on the binary, `bugs-field-does-not-refer-to-debian-infrastructure`, `unknown-field Sparky-Lean-Code` and `non-debug-file-in-debug-package` come from the edition's provenance and Lean Code steps, not from the recipe. **Fix:** drop `g++` from `Build-Depends` (`build-essential` is assumed); the same error for `gcc` on the `+lc1` source and the other lines are the edition's own steps (the Lean Code source step adds `gcc`) and are left. Pedantic notes about the minified JavaScript (`source-contains-prebuilt-javascript-object`) are the vendored libraries again.
9. **Symptom:** `docker run` lines of a recipe you do not own lack `--pull=never` or use `-v` where the lane's rules ask for `--mount`. **Fix:** put a `docker` wrapper first in `PATH` that rewrites `run` (adds `--pull=never`, `--ulimit core=1`, `--cpus 4`, turns each `-v SRC:DST[:ro]` into `--mount type=bind,src=SRC,dst=DST[,readonly]`, writes a `--cidfile` and appends its ID to the lane's `.container-ids`); the recipe stays untouched.
