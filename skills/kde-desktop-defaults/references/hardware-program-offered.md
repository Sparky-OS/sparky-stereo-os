# A program that needs hardware: offered, not installed (ORDER 575, 2026-11-15)

DisplayCAL measures a display with a colorimeter or a spectrophotometer, so it is not on the image (Daniel, 2026-11-14: "keep it off by default, it requires the hardware").
The Info Centre's "Stereo 3D and Deep Colour" page used to say "DisplayCAL is not installed" and offer nothing.
Check freshness first: written on 2026-11-15 from kinfocenter `4:6.7.4-1+stereo3d3`, Stereo APTus 0.1.10 and Debian testing's `displaycal` 3.9.19-3 (source displaycal-py3, ArgyllCMS 3.5.0 in its Depends).

## Recipe

1. **Say what it requires, beside the action, once for the page** (not once for each display: a block inside the per-display row repeated for every screen) ("DisplayCAL requires calibrator hardware: a colorimeter or a spectrophotometer to measure the display"), on the page and on the app center card, in the ten languages. Do not detect a device unless you really do.
2. **Offer the install through the app center's own entry action**, never a second mechanism: the page runs `pkexec /usr/lib/sparky-aptus-stereo-appcenter/actions/entry displaycal install` and reads `actions/entry status displaycal` (JSON: installed, visible, the sizes sentences) first. The row is `{"kind": "apt", "package": "displaycal", "section": "tools", "sizes": true, "note": "displaycal_note"}`; `sizes` makes `tools.py` simulate the entry's own program with the options its action uses (Recommends included), so the sentence on the page is what apt then does ("Packages apt installs for this: 105, from Debian, Sparky Stereo OS, Unofficial Multimedia Packages. Download: 81.0 MiB. More disk space: 392.8 MiB." on a published set).
3. **Never make it a dependency.** The role tasks (`make-meta.py`) put their programs in `Recommends` and `sparky-stereo` pulls every role task, so naming DisplayCAL in `roles.tsv` would install it everywhere. A role names it in `lists/suggests.tsv` (task `Suggests`); `lists/tests/suggests-test.py` fails when a suggested program is also in a list, a role or an integration.
4. **Every failure says what failed and what to do:** apt busy, no network, a package no source offers, the exit status, Stereo APTus missing, authorization cancelled. The page shows the action's own sentence: the last line of its output that does not start with the package's name, because the problems engine adds its own generic lines after it (two in a translated session, one an English copy) and apt's lines come before it.
   The reason never comes from apt's wording, which follows the session's language: the action tries the dpkg and apt lock files itself (a non-blocking `fcntl` lock) for "apt busy", runs a `--download-only` step first so its failure is "no network", and a later failure is apt's exit status.
5. **Where the line lives:** the Info Centre page is the KInfoCenter fork's patch series (`sparky-os/upstream/kinfocenter`), not `sparky-stereo-info`; a change is a code patch plus a translations patch built by `packages/catalogue-rebuilds` (`CODE_PATCH`, a delta `.po.patch`).

## Traps

- **Symptom:** the Info Centre page is English in a German or Japanese session although `kcm_stereo3d.mo` ships. **Cause:** the QML's default translation domain is not `kcm_stereo3d`, so `KI18n.i18nc` finds nothing (the page's older strings are affected too). **Fix:** `KI18n.i18ndc("kcm_stereo3d", ...)` for new strings. **Found by:** a German session at 125 % where the sidebar was German and the page's own sentences English; `msgunfmt` showed the catalogue held the translations.
- **Symptom:** `dpkg-source` refuses the translations patch ("fuzz which is not allowed"). **Cause:** the published patch has eight languages and the build tree's has Spanish too. **Fix:** the delta patch creates the missing `po/es` file (`--- /dev/null`) and appends to the others; check against the tree the published patch makes, not the build tree's.
- **Symptom:** `catalogue-rebuilds` stops "Build-Depends starts with the lc1 build dependencies" or "Missing toolkit input: packages/dpkg-stereo/LICENSE". **Cause:** a wrong `plain-from-lc` option (none is needed for a `+stereo3d2+lc1` source) and a sparse clone without `packages/dpkg-stereo`. **Fix:** no option; add the folder to the sparse checkout.
- **Symptom:** a killed build leaves root-owned files and the next run stops "not empty". **Fix:** remove the folder with a container, by literal path.
- **Symptom (rig):** `kwin_wayland` says "Could not load the Qt platform plugin wayland-org.kde.kwin.qpa even though it was found". **Cause:** the plugin is compiled into the binary and fails from a copy under another name. **Fix:** run `/usr/bin/kwin_wayland` with `--cap-add SYS_NICE`.
- **Symptom (rig):** KInfoCenter "No shell integration named xdg-shell" and "module org.kde.kquickcontrolsaddons is not installed". **Fix:** `qt6-wayland` and the `qml6-module-org-kde-*` packages; a lean `--no-install-recommends` image lacks them.
- **Symptom (rig):** KWin "Failed to open drm node: Permission denied" for the session user. **Cause:** `runuser` drops the container's `--group-add`. **Fix:** a group with the render node's gid and `usermod -aG` before `runuser`.
- **Symptom (rig):** the last screenshot is "The screen locker is broken". **Cause:** the idle lock after a long wait. **Fix:** `kwin_wayland --no-lockscreen`.
- **Symptom (rig):** a click on an action ends "sparky-stereo-problems: The system journal could not be reached". **Cause:** no journald in the container. **Fix:** start `systemd-journald` with `/run/systemd/journal` made.
- **Symptom (rig):** "apt busy" is not reproduced. **Cause:** `flock` on `/var/lib/dpkg/lock-frontend` does not conflict with apt, which takes `fcntl` locks. **Fix:** hold both lock files with `fcntl.lockf`.
- **Symptom (rig):** `apt-get` refuses everything with "Unmet dependencies" after `dpkg --ignore-depends`. **Fix:** apt checks the whole set, so a package that cannot be installed needs a named empty stand-in in the rig only (here `sparky-apt`, `sparky-aptus-appcenter`, `sparky-stereo-hardware`), said in the report.
- **Symptom:** the page's displays come from a fixture, not hardware. **Fix:** `sparky-stereo-info/tests/fixture.sh` with `SPARKY_STEREO_INFO_DRM` and its `bin` first in `PATH`; the DisplayCAL line, the status call, the install and apt are real.
- **Symptom:** a failure ends "falhou (saída do apt: 100)" or "fehlgeschlagen (apt-Exitcode 100)" instead of the network or busy sentence in a non-English session. **Cause:** the action matched apt's English lines ("Could not get lock", "Failed to fetch"), and apt speaks `LANGUAGE`. **Fix:** no sentence depends on apt's words: try the lock files with `fcntl.lockf(LOCK_EX | LOCK_NB)`, run the `--download-only` step first, and treat its failure as the network; keep apt's exit status for the install step. **Found by:** the coordinator's rerun with `LANG=pt_BR.UTF-8 LANGUAGE=pt_BR` and `--network none`, then `de_DE` with both lock files held by `fcntl`; the unit tests now run the download step with a Portuguese apt line.
- **Symptom:** the requirement sentence, the sizes and "Install DisplayCAL" appear once for each display. **Cause:** the block sat in the `ColumnLayout` of one display's row. **Fix:** one block after the `Repeater`, hidden when the page shows an error; each colour-profile row keeps only "Measure this display". **Found by:** a fixture with two displays in a window tall enough to see both (`kwin_wayland --height 1700`).
- **Symptom (rig):** a click at the English page's button position misses in another language. **Cause:** the page scrolls and wraps differently (pt_BR, de). **Fix:** take a picture first and read the button's position from it; never reuse a coordinate across languages.
- **Symptom:** in a pt_BR session a failed install shows "Falha ao alterar o Stereo APTus: ... (en) Changing Stereo APTus failed" and not the sentence that says what failed. **Cause:** the page took the last one or two lines of the output, and the engine prints two lines after the action's sentence in a translated session. **Fix:** take the last line that is not the engine's (its lines start with the package's name). **Found by:** the pt_BR page picture after a click with `--network none`; in English the same rule had looked right.
