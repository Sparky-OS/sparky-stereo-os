# kde-desktop-defaults: lessons from the lanes of 25 October to 6 November 2026

Harvested by ORDER 429 from the accepted lane reports; each line names the lane it came from.
A trap gives its symptom, its cause, its fix and how the cause was found; a recipe gives the commands and the result to expect.

## Recipes that worked

- Discover AppStream cache: `appstreamcli` compile of the Flatpak pool with --datapath; on failure Discover logs "Could not compile the AppStream cache, AppStream will compile it in this process" and the engine keeps a record (severity degraded, message id b329c1b8...), cleared when a good compile follows. Resident memory 1,056 to 368 MiB after a catalog change (lane discover-review-386)
- Shortcut change proof with real key events through KWin: Ctrl+Alt+Del, Ctrl+Esc, Ctrl+Shift+Esc open System Monitor; Ctrl+Alt+Esc opens the logout greeter; Meta+Ctrl+Esc kills the selected window while a control survives; saved Log Out assignments (Meta+Ctrl+F12, the old Ctrl+Alt+Del) tested; look package Depends on the matching workspace so a partial upgrade cannot leave a clash (lane time-shortcuts-359)

## Traps: the symptom, the cause, the fix, how it was found

- Symptom: a KAuth policy built by kauth-policy-gen has an empty polkit `<message>` for some languages. Cause: the `.actions` file is parsed as QSettings INI, so an unquoted value with a comma is a list. Fix: quote such values (German and Polish needed it). Found by: lintian-free build output showing empty messages in de and pl (lane publish-kwin36-289)
- Symptom: about one lock in eight showed only the wallpaper's colour (5 failures in 42 runs). Cause: plasma-workspace TransientImage drops its picture once it is a texture, and the texture belongs to the window it was made for; moved to another window it drew nothing. Fix: read the picture again when the texture is released (red/green test; 0 in 15 runs after, 0 in 37 final cases) (lane wallpaper-depth-fix-291)
- Symptom: a Kirigami FormLayout with Repeater delegates inserted dynamically shows the problem/actions group out of order. Fix: give the group a stable parent layout, test visual geometry in more than one locale (real Portuguese LANG). Also a uid 1000 bubblewrap gate inside Docker may need unmasked /proc paths to mount its own proc (lane memory-kcm-protection-353)
- Symptom: a Plasma widget shows "Output 0.00 W", blank temperature, 0 RPM. Cause: the service returned an empty PSU (powerOut 0, volts/amps/watts {}) because its log said "Unable to get PSU temperature." every 3 s; the widget turned an empty answer into a real zero and never showed the "cannot reach" error. Fix: a hasData flag, "No PSU readings" note, clear the list on connection error (lane icue-link-widget)
- Symptom (video wallpaper): changing the wallpaper's Video setting from a playlist to a single video never starts the selected file (only `clip red.webm` opens, QML test `player.source` stays red). Cause: a Qt/QML derived binding: the synchronous URL change handler runs before `isPlaylist` updates and enters the playlist branch. Fix: correct main.qml ordering and ship a regression in the session smoke that copies a clip to `single.webm` and requires its decoder open trace (original exits 1, corrected exits 0). (lane video-port-278)
- Symptom: CI prints "all checks passed" and exits 0 although the linter exited 42 without JSON. Cause: a loop reading a process substitution under `set -euo pipefail` does not get the producer's status. Fix: capture the producer status, require one complete JSON document with the expected file count, accept qmllint exit 255 only with diagnostics (warning limit), reject crashes (controls: exit 42 and malformed JSON exit 5). (lane video-port-278)
- Symptom: the session smoke fails with an empty `played` string on Qt 6.8; plasma5support QML executable engine "missing" on Debian 13. Cause: older Qt emits no FFmpeg file open messages by default; trixie ships the executable dataengine in plasma-workspace while newer Debian ships it in libplasma5support6. Fix: set `QT_FFMPEG_DEBUG=1`; check which package provides the engine before calling a missing engine a product defect; D-Bus tests in containers need a passwd entry for the uid. (lane video-port-278)
- Symptom: a "Scan for viruses" entry would open ClamTk's window without scanning, or scan a path called "--". Cause: /usr/bin/clamtk has no options and reads only `$ARGV[0]`; a path that does not exist opens the window instead of scanning, and a "--" would be taken for the path. Fix: the worker checks that the one path exists, passes it as it is (`./` before a name that starts with a dash), and the entry is offered for one selection (`X-KDE-RequiredNumberOfUrls=1`). Found by: reading the last 60 lines of /usr/bin/clamtk (lane image-joins-252c)
- Symptom: Dolphin has no ClamTk entry although clamtk-kde is installed. Cause: it installs a Plasma 5 `kservices5` service menu, which Plasma 6 does not read. Fix: a pack in `/usr/share/kio/servicemenus`, with the types ClamTk's own file names (`MimeType=inode/directory;application/octet-stream;`). `all/allfiles` is also seen in the wild but `desktop-file-validate` refuses it as an unregistered media type (lane image-joins-252c)
- Symptom: `desktop-file-validate` reports four errors on every KDE service menu. Cause: it validates Type=Application files; a service menu is Type=Service with Actions and MimeType (the KDE tutorial still recommends it). Fix: do not use it as a gate; check each MimeType against `/usr/share/mime/types` and `/usr/share/mime/aliases` (`application/x-ms-dos-executable` is an alias of `application/x-msdownload`, which also holds `.dll`, so the pack names the executable types one by one) (lane image-joins-252c)
- Symptom: `debsums` calls every Lean Code file changed. Cause: dpkg-stereo projects the files, so they are not the package's md5sums by design. Fix: `dpkg-stereo --debsums` checks the projected files by their lean hashes and drops them from debsums' answer. debsums facts: `-s` writes "changed file P (from PKG package)", "missing file P" and "no md5sums for PKG" to stderr, exit 2 for changed or missing files, 1 for an unknown package; dpkg writes the md5sums a package lacks when it unpacks it, so `debsums -l` lists nothing until the `.md5sums` file in `/var/lib/dpkg/info` is deleted in the test (lane image-joins-252c)
- Symptom: a test appended a line to /usr/bin/debsums and every later call died with "Bareword not allowed" (exit 255). Cause: the file is the program. Fix: tamper with a file that is data, such as a documentation file (lane image-joins-252c)
- Symptom: `ufw allow ... app NAME` in a container prints iptables "Permission denied" and exits 0. Cause: no CAP_NET_ADMIN, and no firewall is on. Fix: nothing to fix; ufw still writes `/etc/ufw/user.rules` and `user6.rules` ("Rules updated"), and those are what a test reads. Tip: a profile that arrives after the package is the normal order, so a dpkg trigger on `/etc/ufw/applications.d` runs the package (`interest-noawait`), and a handled profile is recorded so a rule the person deleted stays deleted (lane image-joins-252c)
- Symptom: after `dpkg -i --force-depends`, every `apt-get install` ends "Unmet dependencies". Cause: the half-satisfied package stays in dpkg's status. Fix: put stand-ins for the package's Depends in a local flat repository (`dpkg-scanpackages`, `[trusted=yes] file:`) and install the .deb through apt (lane image-joins-252c)
- Symptom: `sparky-stereo-locales --add ja` installs nothing. Cause: by design a language with any package on the system is not filled again, so what a person removed stays removed; `--keep` records what it removed and `--add` brings those back. Fix in a test: prune the language entirely first (`--keep pl,de`). `--restore` runs apt per package in bash and takes minutes with 195 packages: build the stand-in repository once into an image (lane image-joins-252c)
- Symptom: `lean.standalone` stops with "No such file or directory: 'dpkg-source'" while building a script package. Cause: the build image lacks dpkg-dev. Also: the provenance step needs the tree committed (it dates the source from the last commit), and the build record says "NOT complete, unrecorded: buildinfo" for every standalone script package, as the lane that built sparky-stereo-kernel-settings saw (lane image-joins-252c)
- Symptom: the AppCenter fork's `stereo/tests/entries.py` fails with "No module named sparky_install_downloads" or a missing `/usr/lib/sparky-aptus-appcenter/index.html`. Cause: the page imports sparky-stereo-apt's reader and reads Paweł's pages. Fix in a container: mount the installed `/usr/lib/sparky-aptus-appcenter` read-only and set `SPARKY_INSTALL_DOWNLOADS_LIB` to `sparky-os/packages/sparky-stereo-apt/install-downloads` (lane image-joins-252c)

## Measured facts

- The old restricted-interfaces check was bypassable: a user program writes ~/.local/share/applications/x.desktop with Exec=<its executable> and the key, and KWin grants the whole executable (every Python program) live or at next start; System Settings (Exec=systemsettings, no path) could never pass. This is why upstream dropped it (commit text: user can modify or override the desktop files) (lane kwin-screenshot2-0ea31ae7-330)
- Shift-drag frees both alignment and edge contact like wdisplays; a gap makes Apply show KScreen's "Gaps between displays" message. Upstream c7b9b8b5 carried as s11-0001 with author kept, its number-badge hunk left out because the badge (1993fe12) is master only (lane kscreen-wdisplays-parity)
- sparky-stereo-look sets cursorTheme=Oxygen_Black (KDE 4 name) while Debian's oxygencursors names its themes oxy-black, oxy-white; nothing provides the old name, so KWin falls to the x-cursor-theme alternative (oxy-steel) (lane displayxr-audit)
- Measured contrast failures that hit everyone: Oxygen Dark's negative, positive and link text at 2.4 to 2.6:1 on the view background; Konsole Breeze intense red (192,57,43) at 2.8:1, which is the red root prompt. Recommendation: colour-safe schemes as a switch for hue changes, the two contrast fixes as defaults. Keyboard: plasma-keyboard with the Fcitx 5 bridge because Debian's Qt Virtual Keyboard has no Japanese or Chinese conversion (lane accessibility-study)
- Plasma's launcher cannot route browsers and other menu programs by kind without one hook in KIO's ApplicationLauncherJob; saved choices tests: write, read from a fresh object, Defaults removes keys, invalid values refused, unknown GPU kept, hand edits show (lane graphics-page-227)
- Symptom: a failure test passes on the lane's machine and fails on the installer image (`test_languagepacks_engine_missing_stops_the_installation`: the step ended 0). Cause: the case "the engine is missing" only deleted the mock from the test's path, and `/usr/bin` stayed on it, so a real `sparky-stereo-problems` was found wherever the engine is installed. Fix: give the case a path of symlinks to every `/usr/bin` tool except the engine. Found by: running the test in a container that had the engine, which is the installer image's state (lane review-252c-437)
- Symptom: an AppCenter row for a package that Debian testing no longer has (`network-manager-vpnc`, `hplip`) is never shown, and the lane's report listed a candidate version for it. Cause: `visible()` hides a row whose package has no candidate, and the version in the report was not read from today's archive. Fix: before a row or a Depends is written, `apt-cache policy NAME` in a container made today must show a candidate; the catalogue test now refuses the vpnc row. Found by: `apt-cache policy` of every name in the report's dependency list (lane review-252c-437)
- Symptom: removing an AppCenter entry would take the system task with it. Cause: the entry named `testdisk` and `gddrescue`, which `sparky-stereo-system` Depends on (`system.list` is not optional), and the entry's remove runs `apt-get remove` on every package of the entry; apt removes what depends on them. Fix: a Tools entry names only what the image does not install (the catalogue test checks the packages and the `also` companions against `apps.list`, `image.list` and `system.list`). The VPN page keeps the plugins the image carries, as designed. Found by: reading the entry against `system.list`, then `apt-get -s remove` on stand-in packages with that Depends (lane review-252c-437)
- Symptom: "Run with Wine" says nothing when Wine cannot start the file. Cause: the worker started each file in a background subshell and never read its status, so it exited 0 and Wine's message went to Dolphin's invisible stderr. Fix (sparky-stereo-wine 0.1.1): keep each background pid, `wait` for it one by one, and on a non-zero status call the pack's own `fail` with LOCAL4 (the file and Wine's status, in the person's language, through kdialog or the terminal), then exit 1. Recipe for the same shape in another pack: add the message to the one table in `gen.py` (all nine languages, marked as a first draft pending review by native speakers in the CHANGELOG), and test with a stand-in `wine` that prints to stderr and exits 3: red with the old worker (exit 0, nothing said), green after (exit 1, the file and "status 3" named, German and Traditional Chinese checked). Found by: a stand-in wine that exits 3 (lane review-252c-437)
- Symptom: the link gate for the AppCenter or the Locale tool stops at "Depends sparky-remsu ... [no choices]" or on a Qt library. Cause: the gate solves a package's Depends only from the archives in its JSON, and Sparky's packages need more than Debian. Fix: list Debian forky, Sparky's `tiamat` and `core` suites, the edition's repository (`mashtabba`, with `--add-host` for the LAN), deb-multimedia and NVIDIA's flat CUDA repository (suite `/`, empty components, both of its public keys in one keyring), each with its dearmored public keyring copied under the gate folder; the edition's published `sparky-stereo-apt`, `-hardware` and `-keyring` debs go in the siblings file. The Locale tool needs only Debian and Sparky. NVIDIA's CDN sometimes serves a Packages.gz of another size than its Release ("unexpected size"): run it again after half a minute. Found by: reading the solver's last "Reached two conflicting assignments" block for the next missing name (lane review-252c-437)
- The metas (`task-sparky-stereo-developer`, `sparky-stereo-system`, `sparky-stereo-integrations`, `sparky-stereo-integration-catalogue`) name the staged packs without versions, so rebuilding them from an index that holds a newer stage changes only their version and hash. Only the index-pinned names (the stereo stack, the OS developer stack) take versions from it, and `dpkg-stereo (>= 0.1.7)` in the OS developer task is a fixed floor (lane review-252c-437)
