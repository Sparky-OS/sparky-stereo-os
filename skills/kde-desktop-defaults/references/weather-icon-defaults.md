# Weather icon defaults and the Weather Icons page

## Recipe

1. `sparky-stereo-hardware` runs `sparky-stereo-weather-default` after package installation and at early graphical startup. Use the PCI display class and device IDs from sysfs, `MemTotal` from procfs, and the AMD VRAM attribute when the driver supplies it. This path can run before a Vulkan or OpenGL client starts.
2. For the row 78 candidate, below 7 GiB of reported RAM the machine gets Photoreal. Above that floor, the edition's modern NVIDIA IDs, Cezanne and AMD cards with at least 4 GiB of reported VRAM are capable. The A10 notebook's Carrizo and Hainan IDs are lighter. A machine with no qualifying classification gets Photoreal, with one `LOCAL115` entry in `sparky-stereo-problems` until a subsequent run classifies it. The memory and device cutoffs are proposed policy. Three forecast samples per look with Plasma on llvmpipe and a separate NVIDIA virtual KWin showed Photoreal and Real Weather using similar CPU time.
3. The writer owns the `HardwareLook` key in `/etc/xdg/sparky-stereo-weatherrc`. Its state records the hash of the entire generated file. A pre-existing file, a replacement, or any edited bytes belong to the administrator. A local `Look` wins over Automatic. The launch path measures no display dimensions and applies no stereo depth.
4. In System Settings → Appearance & Style → Themes → Weather Icons, Apply writes the person's `~/.config/sparky-stereo-weatherrc` through KConfig. The page makes Automatic's inherited machine choice visible and permits a local override. The same file also carries `PanelIcon`, `Shade` and `Animation`. Defaults removes the page's own local keys so the system defaults can take effect again. KDE's regular Icons page uses the same `themes` category. The widget's location and provider choices stay in its own settings.

## Proof

In a throwaway container, unpack the published hardware package and show that its desktop hardware default command does not create a weather settings file. Run the successor against fake PCI/procfs trees for Carrizo and Hainan, Cezanne and RTX 3060, a known-RAM low-memory machine and an unknown machine. Run the unknown fixture twice and count the persisted problem. Change it to a known card and check that the problem clears. Modify only the generated `HardwareLook` line and hash both the administrator's file and the user's preferences before and after a repeat.

Start the installed System Settings page and an offline Weather Report applet under Stereo KWin. Use the controls to save all four explicit looks, switch to Automatic with a different local machine choice, darken the night icon, enable one-colour panel ink, disable the animation and restore defaults. Check the same plasmashell PID and both eyes through the whole run. Crop the painted symbol inside the box when checking motion: the tooltip can cover part of the surrounding panel.

## Traps

- **Symptom:** the machine default appears to go away when a person changes only the panel colour. **Cause:** a reader treats the user's file as a complete replacement. **Fix:** read the KConfig cascade key by key. **How found:** the live icon kept the same Real Weather look across the one-colour Apply while the local look and machine overrides remained readable on the page.
- **Symptom:** running the hardware writer erases an administrator's changed value. **Cause:** a marker alone still looks owned after a same-file edit. **Fix:** compare the entire file with its last recorded generated digest. **How found:** the fixture changed only the value and compared the resulting bytes after a new detection.
- **Symptom:** the page opens but the first synthetic selection yields no configuration file. **Cause:** a process PID and first frame do not prove that the module and its combo box are ready, and the rig's keyboard steps did not select the dropdown. **Fix:** wait for the preview icons and the page's first painted frame. Keep one fake pointer connected and select the displayed items with pointer input. **How found:** the preview logged before the compositor showed the page. The negative capture after the first selection showed Automatic still chosen and the dropdown open.
- **Symptom:** the night shade seems ineffective when checking only the sun. **Cause:** the test did not pick a picture with a darker companion. **Fix:** use the full Moon and measure both eyes before and after selecting Darker while the panel is still in colour. **How found:** the day crop produced the identical RGB samples, while the night crop changed on the same applet PID.
- **Symptom:** the software compositor yields no ScreenShot2 result in the headless rig. **Cause:** the virtual backend fell back to QPainter. **Fix:** leave the virtual KWin compositor on its known renderer and force llvmpipe in the client after KWin starts. Log the renderer in both processes and name the distinction with the results. **How found:** KWin's support information and Qt's RHI log identified each actual renderer.
