# lean-code: lessons from the lanes of 25 October to 6 November 2026

Harvested by ORDER 429 from the accepted lane reports; each line names the lane it came from.
A trap gives its symptom, its cause, its fix and how the cause was found; a recipe gives the commands and the result to expect.

## Recipes that worked

- Test the exit status of verify, not only its text: unit test with 12 cases (0.1.36 fails 3, 0.1.37 passes 12); real damage stays counted (changed projected bytes, an old form whose owner does not list the path, a conffile in an old form, a changed projected manifest row) (lane dpkg-deep-verify-398)
- Conffiles on a lean system: the edition's native dpkg advertises capability 2 (Provides dpkg-lean-code) and recognises the lc1 mark: a conffile is accepted as unmodified only when (1) the owning package's original hash matches, (2) the current bytes exactly equal an independent re-render of the original, (3) the running binary's capability signal; a record cannot select a handler or executable. Proof set: conffile-verifier-test.py 17, conffile-events-test.py 16, conffile-transactions-test.py --installed 9 (names: unchanged_projection_upgrades_silently, split_unpack_configure_keeps_old_record, remove_then_reinstall_no_prompt, purge_after_unpack_removes_records, renderer_changed_same_run, renderer_changed_earlier_run, renderer_changed_conf_old, missing_verifier, forged_projection_cannot_hide_edit). Reviewer rerun in clean containers: green 9 of 9, red baseline `Ran 9, FAILED (failures=6, errors=1)` with the forged edit replaced without a prompt (lane dpkg-lean-conffiles-376)
- Perl quote-like operators (qr{...}x, q, qq, m, s) must be projected as checked code: all five formerly preserved dpkg Perl modules now use normal checked projection with comments in the HR companion. Proof chain: red on old renderer (124 failing subcases), green 60 methods, authored and projected `sq` matched comparison both 12,790, `check-debs` and `check-identity` on all 12 .debs, then the link gate, stage rechecked before and after (18 hashes unchanged) (lane lean-perl-quotelike-372)
- Make two Multi-Arch: same twins coexist when one is lean-projected: the edition's dpkg accepts only recorded projections of the twin's exact bytes and otherwise refuses with Debian's own message (Policy 5.6.34.3: "must either install no file there, or a bit-identical file"). Package Pre-Depends on the dpkg build (apt unpacks the Essential dpkg first by default; Immediate-Configure off needs Pre-Depends) and a virtual `dpkg-lean-code` Provides (lane dpkg-stereo-multiarch-363)
- Restore needs the original .deb: order cache, then sources, then a snapshot service query by file hash, with checks and then APT's `partial/` name; `--deb` is all or nothing and is read in place. Snapshot JSON: `result[{architecture, hash}]`, `fileinfo{sha1:[{archive_name, first_seen, name, path, size}]}`; one hash appears for both debian and debian-ports; percent-encoded epochs and `+` work; file names drop the epoch. `apt-helper download-file` errors look like `E: Failed to fetch URL 404 Not Found` or `Unable to connect`/`Could not resolve`, it runs as `_apt` and retries about 3 times (lane dpkg-stereo-restore-365)
- The link gate applies the APT preferences that supplied edition packages ship in /etc/apt/preferences.d (named by conffiles or md5sums), after its own exact pins, for every case; reads flat repository sources (suite ending in "/", components []) and an optional per-source architectures list. Install the new archive configuration only after the code is in main; the old code refuses it. With 5 sources the refresh needs 17 GiB free at the default floors (lane nvidia-dkms-link-gate-329)
- Running the lean gate (bubblewrap) inside a Docker container needs `--security-opt seccomp=unconfined --security-opt apparmor=unconfined --security-opt systempaths=unconfined` (nested bubblewrap needs the proc mount; also user namespaces with SYS_ADMIN); the gate needs SPARKY_LC_ARCHIVE_CONFIG and SPARKY_LC_SCRATCH, the preparation system needs bc and perl, and the archive config must list the edition's repository with its public key when a package depends on an edition package. A minimal bubblewrap preflight catches this before a long build (lane libc-dev-cross-256 / dp-stereo-257-m4c / dpkg-lean-conffiles)

## Traps: the symptom, the cause, the fix, how it was found

- Symptom: `dpkg-stereo --verify --deep` exits 1 with 27 problems on a healthy system. Cause: it counted two harmless classes as damage: files still in an earlier renderer's form (15, which restore takes back) and non-projected files rewritten after install (12). Fix (0.1.37): OLDFORM and AFTERINST are information, named in the summary but not counted; MISMATCH and LCCHANGED stay damage; incomplete checks exit 2. A missing shipped file stays counted. Found by: rerunning an upgrade case and listing the 27 paths (lane dpkg-deep-verify-398)
- Symptom: 11 lean tests fail (suite: 11 failed, 398 passed, 37 skipped) after a validation was added to restore. Cause: restore demanded that the current renderer reproduce the older projection, but migrations restore earlier renderers' forms and re-project them. Fix: for a non-conffile, the owning package's md5sums identify the original and the recorded sha_lean must equal the installed bytes; conffiles keep the exact-render rule. Found by: the lean suite plus the installed c-drop-lines test that showed `original-mismatch` on real 0.1.19-era records (lane lean-test-baseline-397)
- Symptom: restore refuses every record written by dpkg-stereo before 0.1.27 (`original-mismatch`). Cause: those versions wrote `md5_orig` EMPTY for any file that is not a conffile (`md5(data) if is_conf else ''`); the full md5 came with 0.1.27. The fixtures had set md5_orig, so tests passed. Fix: treat an empty md5_orig as "the owning package's md5sums decide"; a recorded md5 must agree; test fixtures must carry what real old records hold (empty). Found by: running the installed proof with an old tree on real old records, not the fixture (lane lean-test-baseline-397)
- Symptom: a person's edit to a conffile is silently replaced when a record carries a hash equal to the edit (forged or wrong sha_lean). Cause: pre_invoke and restore trusted the hash alone. Fix: the third predicate (exact independent render) in both. Found by: the lane that fixed removal logic read pre_invoke 1193-1198 and restore 2262-2287 and wrote a forgery test (lane dpkg-lean-conffiles-376)
- Symptom: fresh installs show /etc/gprofng.rc as "changed by the person". Cause: the conffile map was merged across packages and binutils-common's `newconffile remove-on-upgrade` placeholder overwrote binutils' hash. Fix (0.1.22): judge a conffile only by its owner, the package whose file list holds it: that package's first Conffiles entry that is not remove-on-upgrade, and its own md5sums. One station check: 3 of 27 recorded person edits were false (nis, libcufile-13-4, mime.types). The upgrade corrects such rows once (marker conffile-owner-v1) (lane dpkg-stereo-gprofng-325 / privacy)
- Symptom: the cohort link gate fails with a missing linux-libc-dev although the feature is unrelated to the kernel. Cause: round cohorts used with the edition's only-ours pins must include required development siblings; a passing runtime-package gate does not qualify its -dev sibling. Fix: refresh the cohort so the edition's linux-libc-dev is supplied; rerun. Found by: m2/link-gate.log (lane lean-perl-quotelike-372)
- Symptom: the lean build of dpkg fails on Perl modules with qr{...}x patterns that carry comment lines. Cause: the B::Deparse check refuses those projections and the toolkit treats a refusal as a build failure. Fix at the time: payload-preservation route (reasons in the lc1 manifest), later removed by the quote-like handling. Found by: the build log refusal (lane dpkg-stereo-multiarch-363)
- Symptom: post-invoke results flip between runs. Cause: a racy rule that depends on the clock second (fixed in 0.1.28); test traps: the problems engine forgets a package without a dpkg list unless a catalog environment variable names its catalogs; its Python wrapper keeps one level of nested message arguments (`@KEY` renders at any depth); every lc1 package breaks dpkg-stereo before 0.1.6. Fix: settle runs need a 2 s gap in tests (lane dpkg-stereo-restore-365)
- Symptom: `__FILE__` or error paths differ in a symlink-forest build. Cause: GCC prints a system header's shorter real path, so symlinked layouts change `__FILE__` and `-H` output. Fix: real folders or `-fno-canonical-system-headers`. Found by: comparing includes under a forest. Also: `perf` needs CAP_SYS_ADMIN on a host with kernel.perf_event_paranoid=3; a user-1000 container works with file capabilities on perf plus `--cap-add SYS_ADMIN --cap-add PERFMON`; real dpkg upgrade tests as a non-root user via docker export plus `bwrap --unshare-user --uid 0`. Installed lc1 packages still carry build-time `#line` until rebuilt (16 packages, 9,111 C/C++ files, 155,684 #line on one machine) (lane lean-c-linebreaks-303)
- Symptom: reading `apt-cache show a b c` by position or exit status gives wrong answers. Cause (apt 2.6.1, 3.0.3, 3.3.3): an absent argument is skipped silently with exit 0; exit 100 `E: No packages found` only when nothing is found; an absent version exits 0 with no output; an absent name containing '.' falls back to an unanchored regular expression and prints other packages. Fix: one `apt-cache show` per case, records keyed by identity and SHA-256, never positional. Found by: measuring all three apt versions on a fixture (lane link-gate-batch-320)
- Symptom: the host's `debian:sid` or `debian:testing` local tag is an i386 image (apt 3.3.3 i386). Cause: stale local tag. Fix: use the pinned amd64 digest tagged locally. Found by: architecture line in the test log (lane link-gate-batch-320)
- Symptom: an exact versioned dependency on an older driver version is refused by apt although the version exists. Cause: apt 3.3.3 solver3 strict pinning: "Reject all non-candidates outright for strict pinning" (2.9.17), so an exact dependency cannot pick -2 while -1 of a newer version is the candidate; `--no-strict-pinning` (2.9.3) would solve it but an installed system solves strictly, so the gate would pass what a person's apt refuses. Fix: honour the driver-lock package's pin file in the gate (NVIDIA's own pinning package ships /etc/apt/preferences.d/nvidia-driver-pin as a conffile, `Pin: version 615.71.09-*`, priority 1000, and says to install it before the driver). Found by: probing the fixture with and without `--no-strict-pinning` (lane nvidia-dkms-link-gate-329)
- Symptom: a lane gate stops with "supplied input changed after its universe was frozen" at a random time. Cause: an official publish-tree on a `cp -al` copy unlinks superseded files in its pool step, which moves the ctime of inodes shared with the live cache that the lane gate reads through symlinks. Fix: lane gates read copies made by reading (freeze-copy.py), not symlinks to the live cache; candidate copies are made with `cp -a` on the build disk (no shared inodes, 1856 files in 51 s, 15 GB) (lane nvidia-dkms-link-gate-329)
- Symptom: the link gate fails on an ELF file in an `Architecture: all` package under /usr/share (emulator guest data, firmware blobs). Cause: the gate traced every ELF as the host's. Fix (lean 0.1.22): first ask whether the ELF is the host's; foreign ELF in an Arch: all package under /usr/share is guest data, noted, never traced (follows Lintian binary-from-other-architecture, which skips Arch: all, and the FHS); a static-pie program counts as static (file(1), ldd, Lintian #1068304). Still failing by design: foreign ELF in Arch: all outside /usr/share, and in architecture-dependent packages (lib32 multilib, valgrind's i386 tools). Found by: gating QEMU's 20 archives (lane lean-linkcheck-foreign-elf-340)
- Symptom: after a gate fix only some blockers are reported. Cause: the predecessor message prints `[:5]` findings (hid 3 of 8 files) and `check_link` stops at the first failing package, so later packages are never gated. Fix: after any gate fix rerun the whole cohort; proposed "and N more" and gating every package before stopping (lane lean-linkcheck-foreign-elf-340)
- Symptom: a container disk guard reports the wrong free space. Cause: it checked the overlayfs parent of a bind mount. Fix: stat the exact bind root. Also: zig's CMake zig2 core lacks version/ast-check, so the Lean Zig consumer needs the full source-built bootstrap compiler; recipes must declare intentional generated installed forms through the released API (neither content guessing nor skipping all empty files proves anything); the engine catalog-language test needs a generated de_DE.UTF-8 locale (lane cgm-zig-package-161)
- Symptom: a re-projected package reproduces the old build's mistakes. Cause: re-projecting a published package from its HR companion reproduces that build's staging. Fix: fresh-build when the payload restore was by content hash (no source map) or the payload carries .sparky-lc/source.json; re-project only when the restore was by path (the kernel). Lean-only rebuilds keep +lc1 and take the recipe's next number. (lane lc-linebreak-rebuilds-311)
- Symptom: the Lean link gate fails in Docker at namespace creation ("bwrap" cannot create namespaces; masked /proc). Cause: Docker's default seccomp, AppArmor and path masks. Fix: run with `--cap-add SYS_ADMIN --security-opt seccomp=unconfined --security-opt apparmor=unconfined --security-opt systempaths=unconfined`; the gate's own `--unshare-all` and `--cap-drop ALL` stay unchanged. Record the flags in every reproducer script. (lane zfs-restore-385)
- Symptom: a repository holding a submodule gitlink cannot be a Lean Code `--authoring` root. Cause: the gitlink is not a tracked tree. Fix: keep a recipe's authoring folder small and tracked. Found by: the build refusing the root. (lane no-fallbacks-drivers-346f1)

- Symptom: `publish-tree.sh` refuses a package the build's link gate passed: "link check failed: ... stereo imports lost: NAME (the previous build called them)".
  Cause: a stereo call retired on purpose was declared only where the build could see it (the source tree), and the publisher has only the archives.
  Fix: a stereo call retired on purpose is declared in `debian/sparky-lean-retired-stereo-imports` (symbol as `nm -D` prints it, white space, reason); `lean.debhelper` writes it into the lc1 manifest of every archive as `retired_stereo_imports`, bound by the control mark, and `linkcheck.compare()` reads it only from the archive, at the build and at publication alike: each recorded symbol becomes a note in the log, every other lost import still blocks.
  A record with a row without a reason, or a name that is no stereo symbol, is refused wherever a manifest is loaded; a record edited after the build fails its mark. No environment variable opens the gate.
  Found by: the publisher's own checks run on a throwaway-key copy of the live tree with the round's packages (skill edition-packaging, references/lessons-2026-11.md, "A stereo call retired on purpose").

- Symptom: one test of the suite fails when the tree is mounted into a container, `test_appstream_off_publishes_what_main_published`: "Command '['git', 'show', '<commit>:sparky-os/repo/publish-tree.sh']' returned non-zero exit status 128", with "fatal: detected dubious ownership in repository at '/tree'" in the captured output.
  Cause: the test reads an earlier `publish-tree.sh` from the repository's history, and git refuses a repository owned by another user (the container's root against the mount's owner).
  Fix: mark the mount as safe for that container only, through its environment (`-e GIT_CONFIG_COUNT=1 -e GIT_CONFIG_KEY_0=safe.directory -e GIT_CONFIG_VALUE_0=/tree`); never change the host's git configuration for it.
  Found by: running the one test again with its captured output shown; the summary line alone names neither git nor the ownership.

## Measured facts

- dpkg facts: the status file is rewritten at every write run; a same-version reinstall leaves status bytes unchanged but changes the info directory; configure compares conffiles only from "unpacked"; remove and purge never compare; apt's `--no-triggers` leaves interested packages triggers-pending between runs. dpkg-stereo 0.1.28 and older lost records of packages left in those states (378 rows on one machine: systemd 313, udev 50) (lane dpkg-stereo-hook-cost-367)
- Python 3.14 startup costs measured on a 5600G: compiling a 2,900-line script at every run 28 ms; concurrent.futures pulls logging, traceback and _colorize 15 ms; hashlib loads OpenSSL's binding 3 ms; parsing the whole status with the strict parser at each projection costs 50 to 120 ms per change run (lane dpkg-stereo-hook-cost-367)
- Measured on a 47,360-record C migration: restore() 55.11 s to 0.55 s; no-op dpkg run with 38 unavailable versions 39.5 s to 0.191 s; upgrade from 0.1.16 121.5 s to 17.6 s; large migration 834 s with 17 progress lines (longest silence 75 s). Also: 0.1.17 marked every package as seen when its migration ran inside a hook (`project_packages(record=False)` fix). Lean suite 286 passed, 5 skipped (lane dpkg-stereo-0118-315)
- Link gate after batching: round of 28,597 `apt-cache` calls became 12, 23,313 s became 6,293 s; unpack is now 75 to 96% of a case (1,188 archives, about 3.5 GB re-extracted per case). SHOW_ARGUMENTS 1024 split the largest case (1,047 identities) into 2 calls; 4,096 stays under a 128 KiB bound. Lean toolkit ships inside dpkg-stereo, so a change to a lean module ships only in a new dpkg-stereo version and bumping lean VERSION changes the renderer identity (lane link-gate-batch-320)
- Discover's resident memory depends on AppStream cache state: 201 MiB without Flathub, about 600 with Flathub parsed from XML, 968 observed with stale caches plus a fresh Flathub, 233 to 340 with fresh caches and a user cache. Any measurement must record cache file mtimes, rebuild caches (`appstreamcli refresh-cache --force`) and let Flathub refresh first. Discover pulls Flathub's catalog at launch through flatpak-system-helper into the real /var/lib/flatpak whatever FLATPAK_SYSTEM_DIR says. Only 28 Discover-read files are projected (Kirigami QML), so the projection costs no memory (lane discover-lean-memory-379)
- Measured on kernel headers and libstdc++: with the line-break form a kernel-module compile costs 1.6 to 2.1% more instructions than with the `#line` form, preprocessing costs 1.8 to 2.1% fewer; the base headers keep 40,710 more lines. Neither form keeps the column of code after a removed comment (DW_AT_decl_column, -E indentation). modpost's srcversion hashes `//` comments. (lane lc-linebreak-rebuilds-311)
- Symptom: a local rebuild of a Lean Code source stops in `override_dh_builddeb` with "check-link needs --archive-config / --scratch (or SPARKY_LC_ARCHIVE_CONFIG / SPARKY_LC_SCRATCH)". Cause: the gate (`lean.release check-link`, called by `lean.debhelper`) reads those two variables and nothing else; a build outside the edition's builders has neither. Fix: the helper builds archive.json from the computer's own apt sources and gives the build a private scratch (sparky-stereo-ffmpeg-fdk, link-config). A small architecture: all package reaches the same call in seconds: without the variables the message above, with link-config's archive.json "archive-qualified link check passed for 1 packages" (ORDER 462). Found by: reading the call in release.py, then running it on a package of one file.
- Symptom: a fix reached the machine but the failed build is never tried again. Cause: the update check skipped a version that had failed ("not tried again for the same version") and the failure record (migrated from an older helper) did not say which helper failed. Fix: record the helper's version with the failure and retry once when it differs or is missing. Lesson: a deterministic failure is retried when its cause may have changed, never on a timer.
