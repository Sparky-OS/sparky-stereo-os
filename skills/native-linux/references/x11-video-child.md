# Declaring an X11 child window: a player's video window

Learned on VLC Stereo's Qt interface (ORDER 265 and 265b, November 2026).
The recipe first, then the traps with their symptoms.

## Recipe: each view at its own resolution

1. The 3D area of the interface is a native child window of its top-level window (Qt's `WA_NativeWindow` widget, a toolkit's GL area). The toolkit reads that window's size and owns its geometry. Do not resize it and do not draw on it.
2. Find the managed top-level: walk `XQueryTree` upwards from the child to the nearest ancestor that carries `WM_STATE` (ICCCM 4.1.3.1; the window itself counts), else the last ancestor below the root. If it is the child itself, the child is a window of its own: declare it with `stereo_declare_x11()` as before and Stereo KWin makes it hold both views (step 7).
3. Before the GL surface exists, make a window of your own inside the child: `XCreateWindow(display, child, 0, 0, 2 * view_width, view_height, 0, CopyFromParent, InputOutput, CopyFromParent, CWEventMask, &attributes)` with an event mask of 0 (the pointer and the keys go on to the child by X's propagation of events nobody selected: no `XShape` is needed), then `XMapWindow`. The GL visual must be the child's, hence `CopyFromParent`.
4. Draw on that window instead of the child. In VLC the OpenGL modules read it from a variable of the video window (`gl-x11-window`, helper `x11-window.h`), because they create their surface from the video window's id.
5. Draw the two views side by side at the resolution they have, in a window that is twice a view wide, and resize that window (`XResizeWindow`) whenever the views' size changes. Letterbox bars are inside the window, as on Wayland.
6. Declare it: `stereo_declare_x11_child(display, toplevel, own_window, STEREO_SBS_FULL, STEREO_CLASS_VIDEO, STEREO_VIDEO_CURRENT, shown_width, shown_height)`, where shown width and height are the size one view is shown at, the child's own size in display pixels, and update them with `stereo_declare_x11_one_view_size()` when the child is resized. It needs `stereo_supported_x11(display) >= 8` and libstereo-declare 1.7.0 (write `libstereo-declare1 (>= 1.7.0)` into Depends: the symbol is newer than the shlibs minimum). Stereo KWin shows each view once, at the shown size, at the own window's position, which follows the child. Nothing else is needed for the position.
7. Where the desktop announces 5 to 7, declare the child itself with `stereo_declare_x11_child(..., 0, 0)` and draw one view in each half of the child: Stereo KWin gives the left half to the left eye and the right half to the right eye, each stretched once to the child's rectangle. That halves the horizontal resolution of a full side by side source, so say so: a message in the log and a dialog ("3D video shown at reduced width").
8. Where the desktop announces less than 5, or any call fails, the 3D video is not shown in 3D: say so in the log, with the reason, and in a dialog ("3D video shown flat"). Never show it as if it worked.
   Show each dialog once per session, each kind once (Daniel, 2026-11-07: "once per session (your choice was right)"): the flat and the reduced-width dialogs are separate kinds, so a reduced-width dialog after a flat one still shows, while the log line is written for every video. In VLC the first time of a kind is a boolean variable on the session object (`vd->obj.libvlc`), created when the dialog is shown, with a debug line that says so, which is what a test counts.
9. When the video closes, or a 2D video takes its place in the same window: `stereo_remove_x11_child(display, toplevel, own_window)` (the format, the class, the shown size and the list entry go), then release the GL surface, then `XDestroyWindow` the own window, and only then close the display.
10. Wrap the calls in an Xlib error handler that ignores errors (set and restore it around `XSync`): the windows can be gone already, and Xlib's default handler ends the process.

## Proof

Column-coded clip, `stereo-proof-rig/scripts/make-barcode-fixtures.sh`: two 960 by 540 views, each column's number in ten bands of luma rows (lossless H.264 in 4:2:0, grey only, so chroma subsampling cannot touch it). Make the interface window `960 x (540 + chrome)` so the video is shown at its own size (the chrome is the menu bar and the controls: read the child's size and position with `x11_props.py`), capture, and read each eye's 960 columns with `scripts/columns.py`. Every column of each eye carries its own number when nothing resamples: VLC Stereo +stereo3d18 gives 960 of 960 in each eye, the half layout of +stereo3d17 gives 480 of 960 (the odd columns are lost) and is the negative control.

## Traps

- **Declaring only the child.** Symptom: the capture is one picture (`stereo` false, one output wide), the video area shows one colour, both eyes the same. Cause: Stereo KWin reads the children a top-level lists, and `stereo_declare_x11()` on a child lists nothing. Found by walking the window tree with `x11_props.py`: the child had `_KDE_NET_WM_STEREO_CONTENT` and its top-level had no `_CHILDREN`.
- **Both eyes show the left view (red and red).** The child is declared and listed, but the program drew the second view beyond the window's right edge, as it would for a top-level window that the compositor makes twice as wide. Stereo KWin does not widen a child.
- **Resizing the toolkit's child to twice its width.** Qt's video widget reads the real size of the X window on every `ConfigureNotify` (`VideoWidget::physicalSize()` in VLC), so the child reports twice its width back and the program cannot tell its own doubling from the person's resize. This is why step 3 uses a window of the program's own: the toolkit never sees it.
- **A child that is wider than its parent still shows whole.** The own window is twice as wide as the interface's video window, which clips it for X's own drawing, and Stereo KWin still shows the whole of both views: measured, 960 of 960 columns in each eye.
- **The window's visual.** GLX and EGL pick the framebuffer configuration from the window's visual: a window made with another visual than its parent's does not match.
- **The library version.** The plugin that calls `stereo_declare_x11_child()` loads against 1.0 and fails at run time with an undefined symbol: write the minimum version into Depends yourself.
- **The Lean Code link gate refuses a build that loses a stereo import its predecessor had** (`stereo imports lost: stereo_declare_x11, stereo_remove_x11 (the previous build called them)`). Keeping the old call for the window that is a top-level is the correct design and keeps the import. The gate also needs its configuration: a folder with `sources.json` (Debian forky, deb-multimedia forky and the edition's published tree as `file:/repo`) and the public keyrings it names, `SPARKY_LC_ARCHIVE_CONFIG` and `SPARKY_LC_SCRATCH` passed into the container and on to `dpkg-buildpackage`, `bubblewrap` installed, and `--security-opt seccomp=unconfined --security-opt apparmor=unconfined --security-opt systempaths=unconfined` on the build container; without them the gate stops with `check-link needs --archive-config / --scratch`.
- **An apostrophe inside `${VAR:?message}`** in a build script ends the script with `unexpected EOF while looking for matching` (bash reads the quote inside the expansion): leave apostrophes out of those messages.
- **A failed container build leaves root-owned files in the bind-mounted output folder** (the script stopped before its `chown`): remove them from a container as root before the next run.
- **Once per session is a property of the process, not of the plugin's lifetime.** A static flag in the video output module would also work while the plugin stays loaded, but the session object is the one place VLC itself ties to a session. Prove it with two 3D videos in one session (one dialog, a log line for every video, here three per video because the video output is opened three times while the GL modules are tried), then a fresh session (the dialog again), then a reduced-width case after a flat one in the same session (both dialogs). VLC's own Errors window keeps "Hide future errors" ticked by default, which is a different, per-person setting.
- **A desktop that announces less than 8 or 5.** Test both paths with a preload that returns the number from `stereo_supported_x11()` (`scripts/support-shim.c`, `STEREO_SHIM_SUPPORT`): the capture must show the half layout at 5 to 7 and one view at 4, and the program must have said so each time.
