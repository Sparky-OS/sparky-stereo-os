# Where a themed icon is drawn, and how a pair reaches each place

**For** whoever makes stereo icons reach the screen: which code draws a themed icon in each place of the desktop, how a window comes to be drawn once per eye, where one picture per eye travels, the recipe that proves it in both eyes, and the traps met on the way.
Check freshness first: written on 2026-11-22 (queue row 77, milestones 1 to 3) from KIconThemes 6.32 with the edition's patches up to `+stereo3d3`, plasma-integration 6.7.4 with the edition's `+stereo3d2`, Kirigami 6.32 with the edition's `+stereo3d1` (packaged with Lean Code 0.1.32), Qt 6.11.2 with the edition's per-eye drawing, KIO 6.30, Plasma 6.7.4 and Stereo KWin `+stereo3d64`.

## The rule each place follows

A stereo icon theme carries each pair as one picture, `2N x N`, left view first, in folders listed under `X-StereoDirectories`, each with `X-StereoSize` and `X-StereoLayout=sbs-left-first` ([Icon Theme Specification](https://specifications.freedesktop.org/icon-theme-spec/latest/), `X-` for extensions).
On a 2D screen every place draws the plain icon, exactly as without stereo; on a screen that shows two eyes each eye gets its own view, drawn as the theme carries it: no shift, no scaling by the icon's size, no depth of our own.

## The map

"An eye pass" is the edition's Qt drawing a window once per eye while the window's `QWindow` has `_q_stereo_depth`: Qt Widgets paints the window twice into a backing store twice as wide and names the eye on the window (`_q_stereo_eye`, 1 the left, 2 the right) while it paints it; Qt Quick sets the eye, then polishes, synchronizes and renders each eye in a pass of its own; the Wayland platform hands the double-wide buffer to Stereo KWin as a full side-by-side pair marked as the desktop's own depth.
Qt Widgets reads `_q_stereo_depth` when it paints, so whoever sets it repaints the window; Qt Quick reacts to the property change itself.

| Place | Who loads the picture | How a pair reaches it |
|---|---|---|
| Dolphin's file view | `KStandardItemListWidget` asks `KIconLoader::loadStereoIcon()` | Dolphin's own declared layer below the view, the view rendered once per eye with holes at the pairs, only on a stereo screen; inside a window that is also drawn once per eye it stays one pair |
| Dolphin's Places panel, the KDE file dialog (Places and file list), menus, any `QIcon::fromTheme()` in a Qt Widgets program of a KDE session | The KDE platform theme makes a `KIconEngine`; KIO's delegates and the style call `QIcon::pixmap()` while they paint | The engine gives each eye its view during an eye pass (KIconThemes `+stereo3d2`); the window is drawn once per eye by the platform theme's trigger (below) |
| The desktop folder view, the panel (Kickoff, the task manager's launchers, the system tray's items, the wastebin) | Kirigami's `Icon` makes an image from `QIcon::pixmap()`; in plasmashell the icon comes from the Kirigami theme plugin's `KDE::icon()`, a `KIconEngine` too | The Icon asks again for each eye inside the eye's pass and marks its window (Kirigami `+stereo3d1`); the trigger draws plasmashell's windows once per eye |
| GTK programs | GTK reads `Directories` only | Not yet: it needs GTK's icon theme to read the stereo folders and a GTK window drawn once per eye |
| Qt without the KDE platform theme | Qt's own icon engine | Not without a change in Qt: Qt's icon loader would read the stereo folders and Qt's platform side would hold the trigger |
| Qt 5 programs | KDE Frameworks 5's `KIconEngine` | Not yet: the edition's Qt 5 has no per-eye drawing |
| `KIconLoader::loadIcon()` called directly, a widget that keeps a pixmap it got once (`QLabel::setPixmap`) | The loader, no engine around it | Not yet: the picture is chosen once |

## The engine, as built

- **The eye:** `KIconEngine::paint()`, `pixmap()` and `scaledPixmap()` look for the eye first on the application (`_q_stereo_icon_eye`, set by an item that draws itself once per eye, only while it asks), then on the widget window being painted (`QGuiApplication::topLevelWindows()`, the one `QWidgetWindow` whose `_q_stereo_eye` is 1 or 2). Anywhere else, and off the GUI thread, the eye is 0 and the icon is the plain one.
- **The view:** `KIconLoader::loadScaledIcon()` takes the eye from a thread-local the engine sets around the load; an icon whose first theme with the icon (in the order of inheritance) has a stereo picture gives that eye's view, cut first and scaled on its own, with the plain icon's state effect and overlays, cached under its own key.
- **A drawing is counted (`+stereo3d3`):** while the engine draws on the GUI thread, the loader also says whether the icon it gives has a stereo picture, in either eye or as the plain icon outside an eye pass; the engine then adds one to the application's `_q_stereo_icons_drawn`. The check is remembered under the plain icon's cache key, and skipped with no lookup when no theme in the tree has stereo folders.
- **A refused folder is told:** a stereo folder whose section has no `X-StereoSize`, a size that is not a number of pixels, no `X-StereoLayout` or another layout is reported as a warning in the `kf.iconthemes` category, naming the index file, the section and the key, for example: `The icon theme file /usr/share/icons/NAME/index.theme lists the stereo folder stereo/places/64 in X-StereoDirectories, but the loader does not use it: its section [stereo/places/64] has no X-StereoLayout key; add X-StereoLayout=sbs-left-first (both views side by side, the left view first).`

## The trigger, as built (plasma-integration `+stereo3d1`)

The KDE platform theme is loaded into every Qt program of a KDE session and is what creates `KIconEngine`, so a window learns there to draw itself once per eye; KIconThemes stays free of the stereo layer.
- On Wayland only, it watches property changes. When `_q_stereo_icons_drawn` changes, the widget window being painted at that moment drew the icon: it is the top-level widget that has a widget with `Qt::WA_WState_InPaintEvent` (Qt sets it around each paint event), and it is marked `_q_stereo_icon`. A Qt Quick item marks its own window.
- A marked window follows the stereo layer's `Stereo::ScreenMode` for its screen (one per screen, made only when a window is marked, so a session whose theme has no stereo folders never reads the screens' modes): on a stereo mode, a stereo pair of outputs or anaglyph it gets `_q_stereo_depth` and a repaint; on any other output the property is taken away again, unless something else (a depth style such as Union) had set it. A window moved between outputs switches with it (`QWindow::screenChanged`).
- A window that never drew a stereo icon is never touched; a marked window stays marked while it lives, so its per-eye drawing follows its screen, not each frame's content.
- When KScreen cannot give the screens' modes, `Stereo::ScreenMode` keeps them unknown and the window is drawn once with the plain icon; `+stereo3d2` makes one KScreen read of its own when the first marked window meets a screen and, if it fails, says so once per screen in the log: `The mode of screen Virtual-0 cannot be read (KScreen: REASON), so a window on it that shows an icon the icon theme has in stereo is drawn once, with the plain icon, even if the screen shows two eyes.` (The layer's own read could report its failure instead; then this read goes.)
- Qt Quick under NVIDIA's own EGL (a person who picks `opengl=nvidia` on an NVIDIA desktop) gets one view, because that EGL has no `EGL_EXT_multiview_window`; the edition's Qt tells the person through the problems engine (`one-view:opengl:NVIDIA`, package libqt6waylandclient6, naming the program). The edition's NVIDIA session (Mesa's EGL with zink) draws the pair. The repair would be in Qt, not staged without Daniel's word: give Qt Quick's per-eye pass the one buffer twice as wide, declared full side by side, that widgets painted on the GPU already get on that EGL (qt6-base's `QWaylandEglWindow`, patch of 2026-11-13), each eye drawn into its half.

## Kirigami's Icon, as built (Kirigami `+stereo3d1`)

- Every load of the Icon's image compares `_q_stereo_icons_drawn` before and after: when it moved, the icon has a stereo picture, and the Icon marks its window (`_q_stereo_icon`) and listens to the window's `_q_stereo_eye`.
- Qt Quick sets the eye before it polishes the window for that eye. On each change the Icon makes its image again for that eye, naming the eye on the application while it asks (`_q_stereo_icon_eye`), and calls `update()`, which the eye's own pass draws; it does not go through `updatePolish()`, so no crossfade animation starts between the eyes.

## Recipe: prove a place in both eyes

1. **The rig:** a throwaway container per case, `SOLID_FAKEHW` naming an empty machine (`<machine></machine>`) so that the Places model holds no real drive (trap below), with Stereo KWin (`kwin_wayland --virtual --width 1920 --height 1080` under `KWIN_VIRTUAL_STEREO_MODES=1`), the KDE platform theme, one render node (the AMD card, or the NVIDIA card through CDI, with the session's environment for programs on an NVIDIA desktop, trap below), `--network none`; [the proof rig](../../stereo-proof-rig/SKILL.md) has the session.
2. **A 3D output:** `kscreen-doctor output.1.mode.2` picks the virtual output's first 3D twin (`3D-SBS`); with two outputs read the mode id from `kscreen-doctor -o` (trap below).
3. **Stereo icons on screen:** for Qt Widgets, a Places bookmark drawn with the icon (`~/.local/share/user-places.xbel`, `<bookmark:icon name="user-trash"/>`) and a folder whose `.directory` says `Icon=user-trash-full`; for plasmashell, apply the look (`QT_QPA_PLATFORM=offscreen plasma-apply-lookandfeel -a LOOK`, then `XDG_CONFIG_DIRS=$HOME/.config/kdedefaults:/etc/xdg`), copy `/usr/share/kio_desktop/directory.trash` to the desktop folder, and through `org.kde.PlasmaShell.evaluateScript` add the wastebin (`org.kde.plasma.trash`), give Kickoff the icon (`writeConfig("icon", "user-trash")`), give the task manager a launcher whose `.desktop` file names the icon, and start a program with a `QSystemTrayIcon` of it (kded6 running: it holds the tray's watcher).
4. **The program unmodified:** nothing in it sets a property; the trigger does. The Wayland log shows one `kde_stereo_content_v1.set_content(3)` and `kde_stereo_depth_v1.set_desktop_depth(1)` per window that showed a stereo icon on the 3D output, none on a 2D output and none in a session whose theme has no stereo folders.
5. **Each eye against its own control, pixel for pixel:** three sessions of the same case: the predecessor build (its left eye is the left eye's control when the theme's plain icon is its left view, as in Kubabbar Glass, byte for byte), the predecessor build with a copy of the theme whose plain icons are the right views and which has no stereo folders (its right eye is the right eye's control), and the build under test. Both eyes of the build under test equal their controls in every pixel: this covers every size, every scale, a shadow or highlight the window draws from the icon's shape, a popup that Stereo KWin pops, and Dolphin's own layer, with no model of the background. Cut the control theme's views with Qt, so that a 16-bit picture stays 16-bit.
6. **Other controls:** the same session on a 2D output against the predecessor (0 differing pixels, nothing declared); the noise (one build captured twice); a session from a look whose theme has no stereo folders (the edition's own look, Oxygen) against the predecessor on a 3D output (0 differing pixels, nothing declared); a window moved from the 3D output to a 2D output, against the predecessor there.
7. **The cost:** a library preloaded into the unmodified program that repaints each top-level window a fixed number of times (`QWidget::repaint()`, or `QQuickWindow::update()` after each `frameSwapped`) and prints the median frame time and the process's processor time per frame, per eye against once.

## For the next Frameworks rebase

Upstream KIconThemes reads GTK's `icon-theme.cache` since 2026-11-18 (3931164f and 4df9c7d8, Chinmoy Pradhan): the cache indexes only `Directories`, so the stereo folders must stay out of the cache lookup, or the stereo lookups, the probe of `+stereo3d3` among them, stop finding them.

## Traps

- **Symptom:** no stereo icon was ever drawn as a pair, in any place. **Cause:** the loader dropped every stereo folder whose section lacked `X-StereoLayout=sbs-left-first` with a debug line nobody reads, and the theme had no such line. **Fix:** the theme carries the key, and the loader now tells the author (above). **How found:** a capture of Dolphin's view with the key added by hand drew pairs, without it identical eyes (queue row 752).
- **Symptom:** KIconThemes stops compiling: `kiconengine.cpp: fatal error: QWidget: No such file or directory`. **Cause:** the library under `KIconEngine` links Qt GUI only; the widgets live in KIconWidgets. **Fix:** find the window being painted from `QGuiApplication::topLevelWindows()` (`inherits("QWidgetWindow")` and its `_q_stereo_eye`); the platform theme, which links Qt Widgets, finds the widget being painted. **How found:** the build log.
- **Symptom:** at 125 % the left eye differs from the plain drawing in a few pixels along the icon's right edge (22 in the file dialog's Places entry). **Cause:** the pair was read as one picture with `QImageReader::setScaledSize()`, so smooth scaling blended the last column of the left view with the first of the right view. **Fix:** read a raster pair whole, cut it, and scale each view on its own with `QImage::scaled(..., Qt::SmoothTransformation)`, as `QImageReader` scales a plain icon; draw a vector pair at twice the view's width. **How found:** comparing the successor's left eye with the predecessor's at 125 %, in a theme whose plain icon equals its left view.
- **Symptom:** a 3D capture of the KDE file dialog has identical eyes although its window is declared a pair. **Cause:** no stereo icon was on screen: a fresh account's Places panel has no Trash. **Fix:** recipe step 3. **How found:** looking at the capture.
- **Symptom:** the 2D control differs from the predecessor in 18 pixels, one vertical line in the file dialog's Name field. **Cause:** the text cursor blinks. **Fix:** the test program sets the cursor flash time to 0 (`QGuiApplication::styleHints()->setCursorFlashTime(0)`), and a noise row (one build captured twice) runs first. **How found:** the bounding box of the differing pixels, one column 18 pixels high.
- **Symptom:** a correct eye of a 64 px icon matches its view with a mean error of 10.7 of 255, the same in both eyes. **Cause:** the matcher looked only two pixels around the centred region. **Fix:** try every placement that covers the region, or compare with a control session (recipe step 5). **How found:** a wider search gave 0.28 for the same capture.
- **Symptom:** a test theme with refused stereo folders still shows a pair. **Cause:** the test theme inherits a stereo theme, and the loader rightly takes the first theme in the order of inheritance that has the icon. **Fix:** fill the refused folders with swapped pairs (right view first) and require the inherited theme's correct pair. **How found:** the row expecting identical eyes failed while the warning lines were present.
- **Symptom:** a matcher cannot tell the left eye from the plain icon. **Cause:** a theme may ship the left view as its plain icon (Kubabbar Glass 20261122.1 does, byte for byte, at every size). **Fix:** the predecessor's drawing is then the left eye's control, and the right eye gets its own (recipe step 5). **How found:** comparing the theme's files.
- **Symptom:** a rig image refuses to install the look: `libheif-plugin-x265 ... Depends libx265-217 (>= 1:4.3) but none of the choices are installable`. **Cause:** the look depends on the stereo layer, the layer on the edition's KImageFormats, which uses the edition's libheif built on deb-multimedia's x265. **Fix:** give the rig deb-multimedia's source and keyring, with the edition's pin above it. **How found:** apt's "two conflicting assignments" block.
- **Symptom:** plasmashell started in the rig after `plasma-apply-lookandfeel -a kubabbar-glass` draws another icon theme, and nothing is declared. **Cause:** the command writes the look's defaults into `~/.config/kdedefaults`, which `startplasma` puts in front of `XDG_CONFIG_DIRS`; a rig that starts plasmashell itself does not. **Fix:** `export XDG_CONFIG_DIRS=$HOME/.config/kdedefaults:/etc/xdg` before plasmashell. **How found:** `~/.config/kdeglobals` had the colours and no `[Icons]`; `kdedefaults/kdeglobals` had `Theme=kubabbar-glass-stereo`.
- **Symptom:** `plasma-apply-lookandfeel` ends with `Could not load the Qt platform plugin "xcb"`, and plasmashell stops at once. **Cause:** the command ran before the compositor, with no display; and `kactivitymanagerd` is not on `PATH` (it lives in libexec), so plasmashell had no activity manager. **Fix:** `QT_QPA_PLATFORM=offscreen` for the command; start `/usr/lib/x86_64-linux-gnu/libexec/kactivitymanagerd`. **How found:** the case's logs.
- **Symptom:** a context menu opened by a test program is declared a pair, then gone before the capture. **Cause:** on Wayland a popup opened without an input event is dismissed. **Fix:** open it as a person does, a right click through KWin's fake input (`fakeinput m:X,Y b:273`). **How found:** the Wayland log had the popup's `set_content(3)`; KWin's window list had no popup.
- **Symptom:** a popup menu's eyes differ everywhere, so eye against eye finds no icon. **Cause:** Stereo KWin pops the popup surface, a parallax of the whole surface. **Fix:** compare each eye with its control (recipe step 5). **How found:** the differing region was the menu's outline.
- **Symptom:** the desktop's Trash in the right eye matches no reference view better than 5.5 of 255 at any size, though the panel's icons match at 0.2. **Cause:** the desktop draws a soft shadow from each icon's own shape, and a reference picture over an estimated background has none. **Fix:** recipe step 5 (0 differing pixels). **How found:** a crop of both eyes beside the reference view.
- **Symptom:** the right eye against the right-view control differs by at most 3 levels at every icon. **Cause:** the control's views were cut with Pillow, which reads Kubabbar Glass's 16-bit PNGs as 8 bits, while the loader reads 16. **Fix:** cut them with Qt (`QImage::copy()` and `save()` keep the depth). **How found:** the largest difference was 3, at the icons only.
- **Symptom:** with two virtual outputs, `kscreen-doctor output.1.mode.2` turns the other output to 3D, and by name it says `Output mode 2 not found`. **Cause:** kscreen numbers outputs and modes in its own order (Virtual-1 was output 1; Virtual-0, where windows open, output 2 with modes 6 to 10). **Fix:** read the id of the `3D-SBS` mode on the wanted output from `kscreen-doctor -o` and set it by the output's name. **How found:** the captures' widths after the move.
- **Symptom:** a plasmashell comparison differs in a few pixels at the panel's right end, in both eyes. **Cause:** the digital clock showed another minute. **Fix:** remove the clock in a measuring case (`widgets("org.kde.plasma.digitalclock")`, `remove()`). **How found:** the region's place.
- **Symptom:** a recipe's build stops at `cp: cannot create regular file 'source/debian/patches/': Not a directory`. **Cause:** Debian's plasma-integration 6.7.4-1 has no patches. **Fix:** make `debian/patches` before adding ours. **How found:** the job log.
- **Symptom:** a recipe's build fails with `Failed to fetch file:/pool/./Packages File not found`. **Cause:** a builder image made with a mount at `/pool` keeps the empty folder after `docker commit`, so a test for the folder is true. **Fix:** pass whether a pool was given instead of testing for the folder. **How found:** the apt log.
- **Symptom:** the Lean Code link gate stops a successor: `Depends libkf6iconthemes6 (>= 6.32.0-1+stereo3d3~) but none of the choices are installable [no choices]`. **Cause:** the dependency is another successor staged with it, which the archive does not have yet. **Fix:** give the gate the sibling's packages: `SPARKY_LC_SIBLINGS_FILE` lists their paths (the recipe's `SIBLINGS_DIR`). **How found:** the build log's apt block.
- **Symptom:** on the NVIDIA card plasmashell's windows are never declared and show the plain icon in both eyes, while Qt Widgets programs on the same card are pairs. **Cause:** the rig ran plasmashell on NVIDIA's own EGL; the edition's session on a desktop drawn by NVIDIA gives its programs Mesa's EGL first with zink (`sparky-stereo-hardware`'s `plasma-workspace/env/sparky-stereo-opengl.sh`: `__EGL_VENDOR_LIBRARY_FILENAMES` Mesa then NVIDIA, `__GLX_VENDOR_LIBRARY_NAME=mesa`, `MESA_LOADER_DRIVER_OVERRIDE=zink`, `LIBGL_KOPPER_DISABLE=1`), and Qt Widgets hands over shared-memory buffers, which no EGL touches. **Fix:** give the programs of an NVIDIA case that environment (not KWin in the rig: exported before `kwin_wayland --virtual` it fails `eglInitialize` with `EGL_NOT_INITIALIZED`). **How found:** the same staged case declared both windows once the variables were set.
- **Symptom:** at 125 % one sample of the desktop Trash's glass differs by one level (117 against 118) from its control in some runs only, on both cards. **Cause (in part):** the sample flips per session, not per eye: over six fresh runs on AMD it read 118 in all six sessions of the round's build, 117 in one of six right-view control sessions and 117 in three of six sessions of the staged build, where both eyes flip together; milestone 2's case was in its control session. What makes a session take one value or the other is not found. **Fix:** none yet; compare the control sessions of several runs with each other (`rows3.sh` takes five fresh runs per card at 1.25), and next dump the Icon's image made in each eye's pass across runs to tell the image from the GPU's sampling. **How found:** the pixel read in every session of six runs side by side.
- **Symptom:** a test run reports `kiconengine_stereotest (Not Run)`. **Cause:** a build tree was mounted at another path than the one it was configured at. **Fix:** mount it where it was configured. **How found:** ctest's verdict with no test output.

- **Symptom:** a row of the Places panel or the file dialog differs between two sessions of the same build by a few pixels at a drive's free-space bar, and a run passes only while the station's disk stands still. **Cause:** Solid's fstab backend lists overlay mounts, and a container's root is an overlay on the host's disk, so the Places model shows the container's root with the host disk's use. **Fix:** run every case with `SOLID_FAKEHW=FILE`, FILE an empty machine for Solid's fake backend: Solid then loads that backend only, and no drive is listed. **How found:** a crop of the capture (an unnamed device under Devices with a red bar); proved by capturing Dolphin before and after a 6 GB file on Docker's disk: 10 pixels differ with the real backends, none with the empty machine.
- **Symptom:** the Kirigami package stops at the Lean Code payload step: `ListSectionHeader.qml: check failed: acorn could not tokenize the authored file`. **Cause:** QML's annotation token `@` is no ECMAScript token. **Fix:** Lean Code 0.1.32 reads a `.qml` file as QML ([lean-code lessons](../../lean-code/references/lessons-2026-11.md)). **How found:** acorn's message for the file.
- **Symptom:** the file-by-file comparison of the edition's Kirigami with Debian's shows `/usr/share/kdevappwizard/templates/kirigami6.tar.bz2` with other contents: its `src/app.h` and `src/main.cpp` without their comments. **Cause:** Lean Code's build-input stage projected `templates/kirigami6/` before `kde_package_app_templates` packed it; KDevelop copies the template's text into a person's new project. **Fix:** the recipe's `preserve-source.tsv` keeps `templates/kirigami6/*` authored (`lean.debian_prepare --preserve-source`). **How found:** unpacking both tarballs and `diff -r`; check every KDE source with `kde_package_app_templates` the same way.
- **Symptom:** a successor's build stops in the link gate: `plasma-integration=...+stereo3d1+lc1 is selected for install ... Depends libkf6iconthemes6 (>= 6.32.0-1+stereo3d3~) but none of the choices are installable [no choices]`. **Cause:** the gate also installs the predecessor, and its dependency is a staged sibling that no archive has; `SPARKY_LC_SIBLINGS_FILE` serves only the new build. **Fix:** put the sibling's runtime packages in the predecessor folder too: every `.deb` there joins the predecessor case's inputs. **How found:** the apt block in the build log, then `release.check_link`'s `previous_inputs`.
- **Symptom:** nothing says why a window's icons are flat on a 3D output when KScreen cannot answer. **Cause:** `Stereo::ScreenMode` drops a failed `GetConfigOperation` (`if (!operation->hasError())`). **Fix:** plasma-integration `+stereo3d2` says it once per screen (above). **How found:** reading the layer's `screenmode.cpp`; in the rig a program run with `KSCREEN_BACKEND` naming no installed backend cannot get the modes (libkscreen 6.7.4 finds no backend and has no fallback), while KWin and kscreen-doctor keep theirs.

## Perks

- `_q_stereo_eye` on a `QWindow` is the whole interface between Qt's per-eye drawing and anything that draws per eye, and `_q_stereo_icons_drawn` on the application the whole interface from the icon engine to what draws windows once per eye: no private header is needed for either.
- `Qt::WA_WState_InPaintEvent` tells, from outside, which widget is being painted.
- `kiconfinder6 NAME` takes no size: it says which file the theme gives at the default size only.

## The cost on a small machine (the A10 kit)

A window drawn once per eye paints twice; the measure is the processor time per frame for the same work, on small machines first. The lane's A10 kit (queue row 77 milestone 3) installs the staged set and the look after keeping every replaced `.deb` and the machine's holds and marks for its `restore.sh`, refuses an apt plan with a `Remv` line, and measures plasmashell's panel and desktop and Dolphin in nested Stereo KWin sessions on a virtual output (no screen touched, nothing in the home folder), 2D against 3D, both cards by `DRI_PRIME`, each card named from Qt Quick's `GL_RENDERER` line, with an idle sample before each window so the process's other work is taken out, the load and the k10temp temperature beside each row.
