# stereo-proof-rig: lessons from the lanes of 25 October to 6 November 2026

Harvested by ORDER 429 from the accepted lane reports; each line names the lane it came from.
A trap gives its symptom, its cause, its fix and how the cause was found; a recipe gives the commands and the result to expect.

## Recipes that worked

- Load a KCM into a test window: KQuickConfigModuleLoader::loadModule, then mainUi(), then load(). Test cases: red on the old build (4 passed 7 failed), green installed 11 passed 0 failed 2 skipped, refusal case shows the KWin reason and the view keeps panning (lane kscreen-wdisplays-parity)
- Real plasmashell popup measurement: one session per popup case, KWin script printing windowAdded lines into kwin.log, ScreenShot2 per eye differenced against a baseline of the same eye (noise about 1 to 3 px from shadows, clock, animations). ~170 sessions, 0 failed, 2 sessions at a time (lane popup-border-plasma-422)
- Lock-screen depth rig: one fresh private session per case (dbus-run-session, kwin_wayland --virtual 1280x800, scale 1, no network), preseeded kwinoutputconfig.json in a virtual 3D mode (anaglyph mode 4), stereoshowrc Enabled=false so a manual lock does not start the show at once. Depth runs only when hasStereoEyes(), which for the virtual output means a 3D mode (KWIN_VIRTUAL_STEREO_MODES=1) (lane wallpaper-disparity-284)
- AT-SPI reads pages as a screen reader does: gir1.2-atspi-2.0, QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1, roles button and slider; SHOWING tells hidden labels apart. Control on the old build: 2 passed 9 failed (every check gets nullopt because the object does not exist) (lane wallpaper-cost-notes-292)
- KWin from a read-only root under bubblewrap: root as lower layer of a tmpfs overlay (bubblewrap 0.13), KWIN_PLUGIN_OVERRIDE puts a publisher module under test over the root's. Root built with mmdebstrap in unshare mode as the container's root plus CAP_SYS_ADMIN (as uid 1000 newuidmap fails: "write to uid_map failed: Operation not permitted"). Smoke at 200 %: capabilities 27, capture 3840x2160, placement 12 of 12, movewindow 8 of 8 (lane displayxr-audit)

## Traps: the symptom, the cause, the fix, how it was found

- Symptom: a change to a built-in effect (the launch feedback) shows no effect in a rig that mounts only the new `libkwin.so` over the packaged one. Cause: built-in effects are static libraries linked into `kwin_wayland`, not into `libkwin`. Fix: mount the new `kwin_wayland` too, or install the package's `kwin-wayland` in the image (`dpkg -i --force-depends` of the four packages in a container, `docker commit --change 'ENTRYPOINT []'`, and the libkwin from the package mounted, because `libkwin6` refuses the install behind the other KDE packages); check which image a version's case runs on, a case named for the new build that runs on the old image proves the old behaviour (found twice on 2026-11-08).
- Symptom: the launch feedback never shows in a rig capture although the effect is loaded and an activation token was granted. Cause one: KWin hides the cursor while no pointing device exists, and the feedback with it; the fake input device lives only while a `fakeinput` client is connected, so keep one connected (`fakeinput m:X,Y s:600000` in the background) for the whole case. Cause two: `org.kde.KSplash` registered on the bus (its service file starts `plasma_waitforname`) tells the effect a splash is visible; leave `org.kde.KSplash.service` out of the bus's service folder. Cause three: a token request from an unprivileged client is refused (`not-granted-666`) while a window is active unless its serial is not older than the last input; the serial of a `wl_display.sync` callback is the compositor's current one. Found by: the effect's source (`start()` returns early on a visible splash or a hidden cursor) and `XdgActivationV1Integration::requestToken`.
- Symptom: a rig script fails with `syntax error near unexpected token done` on a line that was fine. Cause: the script was edited while a session started from it was still running (the shell reads a script as it goes). Fix: finish or stop the running cases first, or run a copy.
- Symptom: a "2D output" case measures depth. Cause: a saved output configuration with another size substituted keeps its stereo flags or loses its plain mode, and the capture reply says `stereo` true. Fix: take the 2D control from a configuration that was proven 2D (every window 0) at its own size, and put the check in the case's first line.
- Symptom: the host's crash handler logs SIGABRT dumps of `kded6` and `baloorunner` (dozens an hour) while a plasmashell rig runs, DrKonqi's host-side processor then waits for a user that does not exist, and a problem notice reaches the desktop of the machine the rig runs on, although every container has `--ulimit core=0`. Cause: the session bus activates `org.kde.kded6`, `org.kde.runners.baloo` and `org.kde.krunner` (krunner starts the baloo runner) by their service files, the programs abort in the throwaway container, and the kernel's `core_pattern` is a pipe to the host's `systemd-coredump`, which logs a crash whatever the limit (the limit only empties the stored core). Fix: start the session bus with its own configuration whose `<servicedir>` holds links to every service file but those three (`dbus-launch --config-file=` a copy of `/usr/share/dbus-1/session.conf` with `<standard_session_servicedirs />` replaced); nothing a proof needs is lost. Found by: `coredumpctl list --since -10min` on the host naming the container's cgroup, then `grep Exec /usr/share/dbus-1/services/*`. Confirm after a full run that the list shows no new row from the rig.
- Symptom: a right click or a key sent with `fakeinput` does nothing after a separate `fakeinput m:X,Y` call. Cause: the fake input device lives only while the client is connected, so a button sent by a new process has no pointer focus. Fix: one process per gesture (`fakeinput m:X,Y s:300 b:273 s:1200`).
- Symptom: `docker run IMAGE bash script` says `bash: /usr/bin/bash: cannot execute binary file`. Cause: an image made with `docker commit` from a container started with `--entrypoint bash` keeps that entrypoint. Fix: `docker commit --change 'ENTRYPOINT []'`, or `--entrypoint ''` on every run.
- Symptom: a three-output case with the person's order cannot be preseeded by hand. Fix: start KWin with `--output-count 3`, set the order with `kscreen-doctor output.NAME.priority.N`, stop KWin with SIGTERM so it saves its output configuration, start it again on the same config folder and map a window before any pointer motion (the order of the backend is the order of the connectors; the first active output used to be the backend's first).
- Symptom: an output configuration copied from a 1280x1024 session with other sizes substituted starts in a 2D mode (`stereo` false in the capture reply). Cause: the saved mode must be one KWin lists for the virtual output; a size KWin does not offer drops the 3D flags. Fix: use the size the virtual output was started with, and check `stereo` in the first capture of every case.
- Symptom: a "reproducible" test under libfaketime still differs. Cause: libfaketime also shifts stat() times, so file mtimes follow the fake clock. Fix: run with NO_FAKE_STAT=1. Found by: the first green attempt failed on include-binaries modes, then on mtimes (lane reproducible-sources-421)
- Symptom: total Perl test counts differ between two dpkg builds. Cause: sq alongside sqv adds 30 planned cases; the in-tree scripts/Build.PL adds one syntax and one taint test. Fix: keep the printed OpenPGP backend list and build layout when comparing totals. Also: a deferred package gate wrapper must be in the canonical source archive and invoked through CURDIR, not an external /work helper (lane lean-perl-quotelike-372)
- Symptom: a Wayland client that resizes itself (a window shrinking when its popup closes) comes back to its old size; the protocol log shows `popup_done`, then an `xdg_toplevel.configure` with the old size, the client's `set_window_geometry` with the new one, `ack_configure`, and the old size again. Cause: KWin's `sendRoleConfigure()` fills every configure with the move-resize geometry, and `maybeUpdateMoveResizeGeometry()` ignored the committed geometry for as long as any configure was scheduled, also one that only changes states (the activation after the popup closed). Fix: ignore it only while the scheduled configure asks for a size, recorded by `moveResizeInternal()` in its own member (`m_configureRequestsSize`, set for maximize, fullscreen, tiling, interactive and other resizes by KWin, cleared when the configure is sent). The first version keyed on `ConfigurePosition` in `m_configureFlags`, which a later `Window::move` clears while the size request still stands: KWin's resize was lost when it moved a resized window before the configure went out; the test `testResizeThenMoveKeepsRequestedSizeBeforeConfigure` (resize, move, old-size commit, dispatchEvents) fails on that version and passes on this one, and passes on the unfixed code. Read what else clears a flag before using it as a marker. Found by: the client's own protocol log in a guest (WAYLAND_DEBUG) read in order; then a KWin integration test. A configure that carries size 0x0 would also do (xdg-shell: the client decides), but the committed size is what the client chose. (lane mesa-stereo-followups-116, ORDER 459)
- Recipe: a race between a client commit and a scheduled configure, deterministic in a KWin integration test. The configure timer is a single-shot timer that fires when the loop is idle, so: have the client commit (`Test::render`, which flushes), call the server-side action that schedules the configure (`workspace()->activateWindow(window)`), then `waylandServer()->display()->dispatchEvents()` so the server reads the commit before the loop runs, then wait for the configure. A guard test next to it (maximize in the same place) shows that a size KWin imposes still wins. Run `testXdgShellWindow` under `dbus-run-session`. (lane mesa-stereo-followups-116)
- Symptom: a bench guest without busy loops hangs at shutdown of the load generators. Cause: `wait $pids` with an empty list waits for every child, the compositor included. Fix: guard the empty list. Also: VKMS in a loaded guest skips vblank log entries (frame-number gaps): check for gaps before calling a link-eyes or pair-boundary failure; mock DRM autotests hang about 1 run in 10 to 20, run them under a timeout (lane dp-stereo-257-m4b)
- Symptom: recipe tests fail in the package container: testMockDrmGlasses (needs four .bin EDIDs that package sources cannot carry), libkscreen testedid (needs pnp.ids), testTabBoxStereo (pre-existing), testScanout hang 0 to 20% depending on load. Cause: fixtures not in the source package / races. Fix: carry EDIDs in text form and build .bin at test time; run under a timeout. Also KWin reads installed protocol XML only when it has the stereo_l_depth_graphics, stereo_glasses and kde_stereo_depth_v1 interfaces, otherwise its in-tree copy (v29), so the KWin package must require the protocols package (lane dp-stereo-257-m4c)
- Symptom: a lane's wait loop proceeded too early. Cause: it matched the prefix "^base retained", which also matches "base retained source prepared". Fix: match the exact success line. Scripts that clean a root-owned work folder must use a container. (lane amdgpu-devcoredump-deadlock-417)
- Symptom: a running proof round fails on a cohort file. Cause: a hard link from a stage or cohort folder changes the file's ctime. Fix: copy, never hard-link. A stray empty `.git` directory above a build folder makes the copy recipe refuse builds under it; build outside it. (lane nvidia-stacks-gate-390)
- Symptom: a negative shell test cannot fail. Cause: bash `set -e` ignores a command inverted with `!`. Fix: use a `refute` helper. Also: `set -o pipefail` made a hardware dry run exit 100 when apt did not know the module. (lane cuda-source-pin-338)
- Symptom: translated text does not appear in a test. Cause: C locale. Fix: use an installed UTF-8 locale (pt_BR.UTF-8). Also an inherited PKEXEC_UID made the shared APTus helper deny the action; the helper must ignore an inherited value. Provenance stamping must not reintroduce contact addresses into a final sealed package; audit the final archive. (lane no-zram-kcm-360)
- Symptom: test-engine.py shows 8 failures. Cause: environmental (raw LOCAL27), identical on the previous lane's tip. Fix: compare against the parent tip before blaming a change. (lane fdk-local-rebuild-402)
- Symptom: `timeout` as PID 1 in a container exits 125 silently. Fix: `docker run --init`. Also a Wayland socket path must be under 108 bytes, so keep XDG_RUNTIME_DIR short (tmpfs); ECM KDEGitCommitHooks writes into .git/hooks at configure, so build from an exported tree (lane kwin-alpha-eye-319)
- Symptom: eye-equality tests fail under KWin autotests. Cause: autotests run with desktop depth on (sunk 10, popped 4, effects 30/12). Fix: set the depths to 0 in tests that need identical eyes (lane kwin-alpha-eye-319)
- Symptom: testTabBoxStereo never opens the switcher; log says "Could not create xkb keymap from configuration". Cause: not xkb (that warning is printed by every KWin test that sets KWIN_XKB_DEFAULT_KEYMAP). Real causes: no session bus (Alt+Tab reaches TabBox via the kglobalaccel KWin starts on the bus) and the kwin_windowswitcher package-structure plugin was not built ("kf.package: Invalid metadata for package structure KWin/WindowSwitcher"). Fix: run under dbus-run-session and build the kpackage plugin target. Found by: measuring both ways (lane kwin-screenshot2-0ea31ae7-330)
- Symptom: Display Settings "Show Screen Contents" says "Screen contents cannot be shown: The process is not authorized to take a screenshot"; D-Bus answer NoAuthorized. Cause: ScreenShot2 restricted-interface check keyed on a desktop file with X-KDE-DBUS-Restricted-Interfaces. Fix: carry upstream KWin 0ea31ae7 (drops the check, ships in +stereo3d41); the rig then needs only KWIN_WAYLAND_NO_PERMISSION_CHECKS (lane kwin-screenshot2-0ea31ae7-330)
- Symptom: KWin cancels every ScreenShot2 capture in a container started with runuser. Cause: runuser drops Docker's --group-add so the render node is unreadable. Fix: start the compositor with the render group kept (setpriv or docker --user) (lane kscreen-wdisplays-parity)
- Symptom: a Qt full-screen window never reaches the output it asks for on virtual KWin outputs. Fix: move it with a KWin script, workspace.sendClientToScreen. Also: ScreenShot2 of an empty output is transparent, not black; a virtual 3D side by side mode (KWIN_VIRTUAL_STEREO_MODES=1, kscreen-doctor output.Virtual-1.mode.7) captures as 2560x800 with stereo=1 (lane kscreen-wdisplays-parity)
- Symptom: changing the notification popup position live has no effect. Cause: plasmanotifyrc is read when plasmashell starts. Fix: write plasmanotifyrc before starting plasmashell (lane popup-border-plasma-422)
- Symptom: X11 popup lands at the wrong place at scale 1.5. Cause: Xwayland positions are device pixels. Fix: scale X11 test points by the output scale, and start kwin_wayland with --xwayland in the virtual rig. Measured at 1.5: border 10 logical = 15 device px; X11 menu right margin 10 against 0 on the old build (x 1110 to 1100) (lane popup-border-plasma-422)
- Symptom: a CJK locale capture shows English and tofu boxes. Cause: gettext ignores LANGUAGE under the C locale and no CJK font. Fix: generate ja_JP and the other locales, install fonts-noto-cjk. Also fake-input keys reach a window only after a fake pointer click activates it (lane wallpaper-cost-notes-292)
- Symptom: repeated backend reloads and stale output IDs. Cause: the backend name was written KWayland. Fix: use the exact lowercase name `kwayland` (lane kwin-wiz3d-outputs)
- Symptom: two tests in one KWin session measure each other's windows; a disturbed run leaves capture.py hung on its pipe. Fix: every test refuses to start over another run's windows, capture.py times out after 30 s (lane displayxr-audit)
- Symptom: the matrix container exits 127 before launching digiKam. Cause: the shared recorder preload lacked its libEGL link dependency and failed under `LD_BIND_NOW=1` eager binding. Fix: link the direct EGL references explicitly (`--no-as-needed`), and add an eager binding launcher load as a smoke check so a tooling failure is not mistaken for an application regression. Found by: `readelf` and the eager binding load test. (lane digikam-mimetype-250)
- Symptom: a headless capture that worked suddenly answers a plain 1920x1080 picture with `stereo 0`, and it looks as if KWin lost stereo. Cause: the program under test has exited, most often by a `timeout` in the harness that was shorter than the capture series, so the later captures show an empty desktop. Fix: keep the program alive for the whole series, and check its PID before each capture. Found by: the harness log, where `timeout -s INT 40` ended the program before capture three (lane 486).
- Symptom: a measured disparity is off by a constant fraction of a pixel (0.8 px in the case found) against the prediction. Cause: the prediction used the window's size, while a docked panel inside the program changed the aspect of the 3D viewport. Fix: predict from the viewport the program reports, never from the window. Found by: printing the program's own viewport beside the window geometry (lane 486).

- Symptom: a Python ScreenShot2 client prints a D-Bus cancellation traceback but never exits.
  Cause: its pipe reader is a non-daemon thread, and the exception bypasses release of the client’s duplicate write descriptor, so the reader never sees EOF.
  Fix: release the Gio UnixFDList in a `finally` block, bound the reader join, and make the reader a daemon as the final shutdown safeguard.
  Found by comparing the same rejected request before and after the cleanup change: the fixed negative control exits 1 in three seconds, and the render-node smoke capture still succeeds.
  Do not count the rejected capture as a stereo proof (lane craft-apps-232, 2026-11-10).
- Symptom: a virtual compositor says `Operation not permitted` before it logs anything.
  Check the binary’s file capabilities and the container’s capability boundary before changing KWin source.
  The test image carried `cap_sys_nice=ep`; removing that file capability in the disposable image allowed an unprivileged compositor to start, with identical executable bytes.
  A passwd entry for the test UID is also required by the private session bus.
  The subsequent no-render-node capture was cancelled; the authorized render-node control succeeded, confirming the existing render-node trap above rather than a client regression (lane craft-apps-232, 2026-11-10).

## Measured facts

- Symptom: KWin's log in a container given only the NVIDIA card through CDI starts with `Failed to open drm node /dev/dri/renderD128: No such file or directory`. Cause: none to fix; the virtual backend walks every DRM device sysfs lists (the other card too), its node is absent, and it opens the NVIDIA render node next. Found by: `org.kde.KWin.supportInformation`, `OpenGL renderer string: NVIDIA GeForce RTX 3060`. Also measured: the `zkde_screencast` output stream of a virtual output in its anaglyph twin is the left view in plain colours, not the anaglyph, and ScreenShot2 answers a two-eye capture on a plain 2D output while stereo content is on it; prove "left view only on a 2D output" with the 2D output's own screencast frame, and declarations with KWin's `WAYLAND_DEBUG=server` log (count `create(` and `set_content(`, not binds) (lane openxr-target-34)

- Output filter parity table against the reference wiz3D shaders: KWin MirrorRig covered and equal for all four reflection combinations (0 differences on 8 captures); checkerboard left-first equal; anaglyph optimized covered but different at 171,060 pixels max error 8; Crosseyed (swap plus letterbox) and complete device methods (frame sequential presenters, Leia weave) missing. ScreenShot2 rejected for output-filter checks because it rerenders eye views instead of reading the DRM filter result; capture the scanout in the guest instead (lane kwin-wiz3d-outputs)
- Symptom: key presses and clicks sent through KWin's fake input did nothing in the rig, although the pointer moved (ORDER 265 said so, ORDER 441 refuted it). Cause: the session script joined a line of steps with "$*" while IFS was a comma, so the client got one token and ran only its first step, answering ok. Fix: join with a space, make the client refuse a malformed step, stop the session when a step is refused, and read the program's own state after every input. Found by: the client's own step log, one line per step in the working runs and one comma-joined token in the failing ones. Also: xdotool needs `XwaylandEisNoPrompt=true` in the rig's kwinrc, or KWin silently drops Xwayland's XTEST events (details in input-delivery.md).

- Lock-screen greeter in the rig (lane lock-greeter-spin-487, 2026-11-09). Recipe: a real `kscreenlocker_greet` needs `layer-shell-qt` (without it the greeter dies with `No shell integration named "layer-shell" found` and KWin prints `Need to put Greeter in emergency mode`), the edition's `libkscreenlocker6`, `libstereo-declare1` and `libstereoshow1` of the same round (an older `libstereo-declare1` gives `undefined symbol: stereo_depth_wayland_unwatch`), `kwin_wayland` run with `--cap-add SYS_NICE`, and `dbus-send --session --dest=org.freedesktop.ScreenSaver /ScreenSaver org.freedesktop.ScreenSaver.Lock` for the lock (the image has no qdbus6). Read the greeter's CPU from `/proc/PID/stat` fields 14 and 15 over a fixed span (100 ticks per second), and per thread from `/proc/PID/task/*/stat`.
- Symptom: with KWin on the GPU the greeter dies at once, four times, then `Everything else failed. Need to put Greeter in emergency mode`; the log says `interface 'kde_stereo_depth_v1' has no event 1` and `The Wayland connection experienced a fatal error: Resource temporarily unavailable`. Cause: KWin's `StereoDepthSurfaceV1::sendState` sends `depth_limits` (event 1, `since="5"`) to a resource bound at version 3 (libstereo-declare binds 3, Qt binds 3), and libwayland-client 1.26 turns an event the client's table lacks into a connection error whose errno is a stale EAGAIN. How found: `WAYLAND_DEBUG=server` in KWin only (`KENV=WAYLAND_DEBUG=server`) showed `-> kde_stereo_depth_v1#62.depth_limits(10.0, 4.0)` on a version 3 object; `WAYLAND_DEBUG=client` showed `bind(52, "kde_stereo_content_manager_v1", 3, ...)`; gdb with breakpoints on `wl_display_get_error` showed the check in `QWaylandDisplay::checkWaylandError`. Rig stand-in for the version gate: a preload that drops event 1 of `kde_stereo_depth_v1` for a resource below version 5 (wrap `wl_resource_post_event`, which `qtwaylandscanner`'s `send_*` calls). The fix belongs in KWin: send `depth_limits` only when `resource->version() >= 5`. With KWin on no GL (no render node) the message appears but the greeter survives, so the GPU run is the one that shows it.
- Symptom: `LD_PRELOAD` has no effect on `kwin_wayland` (`ERROR: ld.so: object ... cannot be preloaded`), although it works for other programs. Cause: `kwin_wayland` carries a file capability (CAP_SYS_NICE), so it is a secure-execution program: ld.so ignores a preload with a slash, and takes a bare name only from a trusted directory and only if the library has the setuid bit. Fix, as root in the image build: copy the library into `/usr/lib/x86_64-linux-gnu`, `chmod 4755`, `ldconfig`, and set `LD_PRELOAD=name.so`. Pass it to KWin alone through a variable the session script expands (`env $KENV kwin_wayland`), never to the whole session.
- Symptom: `kscreen-doctor --dpms off` (or `output.Virtual-0.disable`) in the virtual KWin changes nothing: the greeter's frame, commit and callback rates are the same before and after. Cause: the virtual backend keeps `dpmsMode` as state only, while `DrmOutput` makes its pipeline inactive and calls `m_renderLoop->inhibit()` (drm_output.cpp), so a real output that is off paints no frames and sends no frame callbacks. The rig's "output off" is therefore not the A10's: to stand in for it, wrap `wl_callback_send_done` in KWin's process and drop it while a flag file exists (the greeter then idles, 0 % of a core), or run KWin's DRM backend on VKMS in a virtual machine ([vkms-stereo](../../vkms-stereo/SKILL.md)).
- Debugging a program the compositor starts, in a container with no gdb: copy `/usr/bin/gdb` and the libraries `ldd` lists from an image that has it into `/opt/gdb`, and replace the program with a wrapper script that `exec`s `env LD_LIBRARY_PATH=/opt/gdb/lib /opt/gdb/gdb -batch -ex 'unset environment LD_LIBRARY_PATH' -ex 'set sysroot /' -ex 'set startup-with-shell off' -ex 'set breakpoint pending on' -ex 'break FUNC' -ex run -ex bt --args /opt/real "$@"` into a file under the lane (the wrapper must be executable: a `COPY` of a non-executable file gives `Permission denied` and KWin only logs that the greeter exited). Without `set sysroot /` gdb prints `Error while mapping shared library sections: /proc/N/ns/mnt: Permission denied` for every library.

## Driving a file manager and a viewer by fake input (ORDER 551)

- Symptom: a click sent in a second call of the fake input tool lands nowhere, or a tooltip is gone from the capture.
  Cause: KWin's fake input device, and with it the seat's pointer, lives only while the client is connected.
  Fix: a click follows its move in the same call; for a tooltip, start the tool in the background with a long wait after the move and take the capture while it waits.
- Symptom: the same offsets that opened "3D Input Format" in one image open "Open With…" in another, and a dialog appears.
  Cause: the context menu gains an entry ("Open with <viewer>") when a program for that file type is installed, so every entry below it moves one row.
  Fix: capture each kind of file's context menu once in the image under test and read the row from the picture; a video and a picture differ.
- Symptom: a sub-menu's entries are not where the parent's offsets say.
  Cause: a sub-menu that does not fit to the right of its parent opens to the left, over the first menu.
  Fix: capture it open (leave the menus open: do not click the last entry) before clicking in it.
- Symptom: after "menu keys" sent to a viewer whose menu bar is hidden, a picture has an extended attribute it never had (`user.baloo.rating`).
  Cause: without a menu bar the keys go to the view, where a digit is a rating, and the viewer writes that into the file.
  Fix: show the menu bar first (Ctrl+M in a KDE program with a hamburger button; the setting is not kept when the program is killed), and read the file's state after every step, so a stray key is caught by the proof itself.
- Recipe, a file renamed through the file manager by keys: click the file, F2, type the new base name, Enter (evdev key codes: F2 60, Enter 28, Escape 1, Ctrl 29, Alt 56, Shift 42).
- Recipe, which file is which without reading positions: give every view of every fixture its own flat colour and count colours per eye; a file shown in 3D gives its left colour to the left eye only, a flat one both colours to both eyes, and a selected (tinted) icon counts as neither, so deselect before the capture.
- Symptom: a setting written into the test home's `.config` is ignored (tooltips stay off; a program's own state file is not read), with no error.
  Cause: the rig's session sets `XDG_CONFIG_HOME` to a folder of its own, fresh for every session, so the programs never look in `$HOME/.config`.
  Fix: write the file after the session is up, into `$XDG_CONFIG_HOME` as the session's environment names it.
  Found by: a case that copies a program's old state and expects it to be taken over did nothing, while the same file placed by hand in the session's folder worked.
- Symptom: a proof that passed yesterday fails at its first menu step: the store stays empty, the eyes do not change, and the capture shows the menu of the wrong file.
  Cause: the proof copies its fixture folder with a glob, and a fixture added for another case moved every icon after it in the view.
  Fix: a case names the files it copies; fixtures of a new case get a folder of their own. Compare a rerun with the accepted proof's text (times and image id taken out): an identical text is the quickest proof that a rebuild changed nothing a person sees.
  Found by: the capture taken at the failing step, which showed eight files where the proof expects six.
- Symptom: with a CJK font installed, the offsets that open one sub-menu open the one above it.
  Cause: the rows of a menu are taller in that font (about 25 px against 22 here).

- A file manager's cached thumbnail carries the per-file choice that was in force when it was made (`~/.cache/thumbnails`, keyed by the file's address and date: `Thumb::URI`, `Thumb::MTime`; a stereo one carries `X-KDE::Stereo3DLayout`).
