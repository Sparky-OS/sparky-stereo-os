# stereo-proof-rig: lessons from the lanes of 25 October to 6 November 2026

Harvested by ORDER 429 from the accepted lane reports; each line names the lane it came from.
A trap gives its symptom, its cause, its fix and how the cause was found; a recipe gives the commands and the result to expect.

## Recipes that worked

- Load a KCM into a test window: KQuickConfigModuleLoader::loadModule, then mainUi(), then load(). Test cases: red on the old build (4 passed 7 failed), green installed 11 passed 0 failed 2 skipped, refusal case shows the KWin reason and the view keeps panning (lane kscreen-wdisplays-parity)
- Real plasmashell popup measurement: one session per popup case, KWin script printing windowAdded lines into kwin.log, ScreenShot2 per eye differenced against a baseline of the same eye (noise about 1 to 3 px from shadows, clock, animations). ~170 sessions, 0 failed, 2 sessions at a time (lane popup-border-plasma-422)
- Lock-screen depth rig: one fresh private session per case (dbus-run-session, kwin_wayland --virtual 1280x800, scale 1, no network), preseeded kwinoutputconfig.json in a virtual 3D mode (anaglyph mode 4), stereoshowrc Enabled=false so a manual lock does not start the show at once. Depth runs only when hasStereoEyes(), which for the virtual output means a 3D mode (KWIN_VIRTUAL_STEREO_MODES=1) (lane wallpaper-disparity-284)
- AT-SPI reads pages as a screen reader does: gir1.2-atspi-2.0, QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1, roles button and slider; SHOWING tells hidden labels apart. Control on the old build: 2 passed 9 failed (every check gets nullopt because the object does not exist) (lane wallpaper-cost-notes-292)
- KWin from a read-only root under bubblewrap: root as lower layer of a tmpfs overlay (bubblewrap 0.13), KWIN_PLUGIN_OVERRIDE puts a publisher module under test over the root's. Root built with mmdebstrap in unshare mode as the container's root plus CAP_SYS_ADMIN (as uid 1000 newuidmap fails: "write to uid_map failed: Operation not permitted"). Smoke at 200 %: capabilities 27, capture 3840x2160, placement 12 of 12, movewindow 8 of 8 (lane displayxr-audit)

## Traps: the symptom, the cause, the fix, how it was found

- Symptom: a "reproducible" test under libfaketime still differs. Cause: libfaketime also shifts stat() times, so file mtimes follow the fake clock. Fix: run with NO_FAKE_STAT=1. Found by: the first green attempt failed on include-binaries modes, then on mtimes (lane reproducible-sources-421)
- Symptom: total Perl test counts differ between two dpkg builds. Cause: sq alongside sqv adds 30 planned cases; the in-tree scripts/Build.PL adds one syntax and one taint test. Fix: keep the printed OpenPGP backend list and build layout when comparing totals. Also: a deferred package gate wrapper must be in the canonical source archive and invoked through CURDIR, not an external /work helper (lane lean-perl-quotelike-372)
- Symptom: a bench guest without busy loops hangs at shutdown of the load generators. Cause: `wait $pids` with an empty list waits for every child, the compositor included. Fix: guard the empty list. Also: VKMS in a loaded guest skips vblank log entries (frame-number gaps): check for gaps before calling a link-eyes or pair-boundary failure; mock DRM autotests hang about 1 run in 10 to 20, run them under a timeout (lane dp-stereo-257-m4b)
- Symptom: recipe tests fail in the package container: testMockDrmGlasses (needs four .bin EDIDs that package sources cannot carry), libkscreen testedid (needs pnp.ids), testTabBoxStereo (pre-existing), testScanout hang 0 to 20% depending on load. Cause: fixtures not in the source package / races. Fix: carry EDIDs in text form and build .bin at test time; run under a timeout. Also KWin reads installed protocol XML only when it has the stereo_l_depth_graphics, stereo_glasses and kde_stereo_depth_v1 interfaces, otherwise its in-tree copy (v29), so the KWin package must require the protocols package (lane dp-stereo-257-m4c)
- Symptom: a lane's wait loop proceeded too early. Cause: it matched the prefix "^base retained", which also matches "base retained source prepared". Fix: match the exact success line. Scripts that clean a root-owned work folder must use a container. (lane amdgpu-devcoredump-deadlock-417)
- Symptom: a running proof round fails on a cohort file. Cause: a hard link from a stage or cohort folder changes the file's ctime. Fix: copy, never hard-link. A stray empty `.git` directory above a build folder makes the copy recipe refuse builds under it; build outside it. (lane nvidia-stacks-gate-390)
- Symptom: a negative shell test cannot fail. Cause: bash `set -e` ignores a command inverted with `!`. Fix: use a `refute` helper. Also: `set -o pipefail` made a hardware dry run exit 100 when apt did not know the module. (lane cuda-source-pin-338)
- Symptom: translated text does not appear in a test. Cause: C locale. Fix: use an installed UTF-8 locale (pt_BR.UTF-8). Also an inherited PKEXEC_UID made the shared APTus helper deny the action; the helper must ignore an inherited value. Provenance stamping must not reintroduce contact addresses into a final sealed package; audit the final archive. (lane no-zram-kcm-360)
- Symptom: test-engine.py shows 8 failures. Cause: environmental (raw LOCAL27), identical on the previous lane's tip. Fix: compare against the parent tip before blaming a change. (lane fdk-local-rebuild-402)
- Symptom: `timeout` as PID 1 in a container exits 125 silently. Fix: `docker run --init`. Also a Wayland socket path must be under 108 bytes, so keep XDG_RUNTIME_DIR short (tmpfs); ECM KDEGitCommitHooks writes into .git/hooks at configure, so build from an exported tree (lane kwin-alpha-eye-319)
- Symptom: eye-equality tests fail under KWin autotests. Cause: autotests run with desktop depth on (sunk 10, popped 4, effects 30/12). Fix: set the depths to 0 in tests that need identical eyes (lane kwin-alpha-eye-319)
- Symptom: testTabBoxStereo never opens the switcher; log says "Could not create xkb keymap from configuration". Cause: not xkb (that warning is printed by every KWin test that sets KWIN_XKB_DEFAULT_KEYMAP). Real causes: no session bus (Alt+Tab reaches TabBox via the kglobalaccel KWin starts on the bus) and the kwin_windowswitcher package-structure plugin was not built ("kf.package: Invalid metadata for package structure KWin/WindowSwitcher"). Fix: run under dbus-run-session and build the kpackage plugin target. Found by: measuring both ways (lane kwin-screenshot2-0ea31ae7-330)
- Symptom: Display Settings "Show Screen Contents" says "Screen contents cannot be shown: The process is not authorized to take a screenshot"; D-Bus answer NoAuthorized. Cause: ScreenShot2 restricted-interface check keyed on a desktop file with X-KDE-DBUS-Restricted-Interfaces. Fix: carry upstream KWin 0ea31ae7 (drops the check, ships in +stereo3d41); the rig then needs only KWIN_WAYLAND_NO_PERMISSION_CHECKS (lane kwin-screenshot2-0ea31ae7-330)
- Symptom: KWin cancels every ScreenShot2 capture in a container started with runuser. Cause: runuser drops Docker's --group-add so the render node is unreadable. Fix: start the compositor with the render group kept (setpriv or docker --user) (lane kscreen-wdisplays-parity)
- Symptom: a Qt full-screen window never reaches the output it asks for on virtual KWin outputs. Fix: move it with a KWin script, workspace.sendClientToScreen. Also: ScreenShot2 of an empty output is transparent, not black; a virtual 3D side by side mode (KWIN_VIRTUAL_STEREO_MODES=1, kscreen-doctor output.Virtual-1.mode.7) captures as 2560x800 with stereo=1 (lane kscreen-wdisplays-parity)
- Symptom: changing the notification popup position live has no effect. Cause: plasmanotifyrc is read when plasmashell starts. Fix: write plasmanotifyrc before starting plasmashell (lane popup-border-plasma-422)
- Symptom: X11 popup lands at the wrong place at scale 1.5. Cause: Xwayland positions are device pixels. Fix: scale X11 test points by the output scale, and start kwin_wayland with --xwayland in the virtual rig. Measured at 1.5: border 10 logical = 15 device px; X11 menu right margin 10 against 0 on the old build (x 1110 to 1100) (lane popup-border-plasma-422)
- Symptom: a CJK locale capture shows English and tofu boxes. Cause: gettext ignores LANGUAGE under the C locale and no CJK font. Fix: generate ja_JP and the other locales, install fonts-noto-cjk. Also fake-input keys reach a window only after a fake pointer click activates it (lane wallpaper-cost-notes-292)
- Symptom: repeated backend reloads and stale output IDs. Cause: the backend name was written KWayland. Fix: use the exact lowercase name `kwayland` (lane kwin-wiz3d-outputs)
- Symptom: two tests in one KWin session measure each other's windows; a disturbed run leaves capture.py hung on its pipe. Fix: every test refuses to start over another run's windows, capture.py times out after 30 s (lane displayxr-audit)
- Symptom: the matrix container exits 127 before launching digiKam. Cause: the shared recorder preload lacked its libEGL link dependency and failed under `LD_BIND_NOW=1` eager binding. Fix: link the direct EGL references explicitly (`--no-as-needed`), and add an eager binding launcher load as a smoke check so a tooling failure is not mistaken for an application regression. Found by: `readelf` and the eager binding load test. (lane digikam-mimetype-250)

## Perks of the part

- A headless audio rig for player timing: PipeWire + WirePlumber on a null sink at the user's clock rate and allowed rates, `pw-record` of the sink monitor, an analysis script (onset, gaps, jumps, lag spread) and a second one for the player's own drift view; works in a container with a passwd entry for the uid. (lane players-shared-layer)
- Rig habits: `timeout docker run` kills the client, not the container, so a hung case keeps running (seen with an FLTK case): `docker kill` on timeout; one fresh KWin per case, Wayland requests summarised, ScreenShot2 colour counts per eye. Existing skill covers WAYLAND_DEBUG filtering (stereo-proof-rig/SKILL.md:32) and pgrep self match (line 127). (lane magnum-stereo)

## Measured facts

- Symptom: KWin's log in a container given only the NVIDIA card through CDI starts with `Failed to open drm node /dev/dri/renderD128: No such file or directory`. Cause: none to fix; the virtual backend walks every DRM device sysfs lists (the other card too), its node is absent, and it opens the NVIDIA render node next. Found by: `org.kde.KWin.supportInformation`, `OpenGL renderer string: NVIDIA GeForce RTX 3060`. Also measured: the `zkde_screencast` output stream of a virtual output in its anaglyph twin is the left view in plain colours, not the anaglyph, and ScreenShot2 answers a two-eye capture on a plain 2D output while stereo content is on it; prove "left view only on a 2D output" with the 2D output's own screencast frame, and declarations with KWin's `WAYLAND_DEBUG=server` log (count `create(` and `set_content(`, not binds) (lane openxr-target-34)

- Output filter parity table against the reference wiz3D shaders: KWin MirrorRig covered and equal for all four reflection combinations (0 differences on 8 captures); checkerboard left-first equal; anaglyph optimized covered but different at 171,060 pixels max error 8; Crosseyed (swap plus letterbox) and complete device methods (frame sequential presenters, Leia weave) missing. ScreenShot2 rejected for output-filter checks because it rerenders eye views instead of reading the DRM filter result; capture the scanout in the guest instead (lane kwin-wiz3d-outputs)
- Symptom: key presses and clicks sent through KWin's fake input did nothing in the rig, although the pointer moved (ORDER 265 said so, ORDER 441 refuted it). Cause: the session script joined a line of steps with "$*" while IFS was a comma, so the client got one token and ran only its first step, answering ok. Fix: join with a space, make the client refuse a malformed step, stop the session when a step is refused, and read the program's own state after every input. Found by: the client's own step log, one line per step in the working runs and one comma-joined token in the failing ones. Also: xdotool needs `XwaylandEisNoPrompt=true` in the rig's kwinrc, or KWin silently drops Xwayland's XTEST events (details in input-delivery.md).
