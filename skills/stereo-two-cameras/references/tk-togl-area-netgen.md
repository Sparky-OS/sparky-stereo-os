# A Togl drawing area inside a Tk window, fitted to the person's limits (Netgen)

**For** anyone giving a Tcl/Tk program's OpenGL drawing area (a Togl widget) a stereo pair on the edition, where the program draws one picture upstream and we add the two cameras: which case it is, the route through Mesa's GLX child declaration, how the area reads the person's depth limits, the fit on a mesh, the options and what is told, the closed-form scene, the proofs and the traps.
Learned on Netgen 6.2.2606 (Debian 6.2.2606+dfsg1-3, queue row 50 step 5, November 2026), on Stereo KWin 6.7.4 +stereo3d59, Mesa 26.1.6 +stereo3d29 (patch 0045, a GL child declared once its window is viewable) and libstereo-declare 1.12.2.

## Which case it is

Grep upstream's own tree, never our patches: Netgen 6.2.2606 has a `viewoptions.stereo` flag (`-stereo` on the command line sets it, `vispar.stereo` reads it) and a "Stereo View" check box that is commented out in `ng/dialog.tcl`, but `ng/drawing.tcl` always makes the Togl widget with `-stereo false` and nothing draws into `GL_BACK_LEFT` or `GL_BACK_RIGHT`.
So it is a scene where we add the cameras: fitted to the person's limits, no separation setting (memory one-separation-one-place, stereo-two-cameras-scene-fit).
The edition's earlier patches (0001 to 0003) made `-stereo` ask Togl for a quad-buffer widget and draw the scene once per eye at a constant 3 % of the distance looked at; patch 0004 replaces the constant with the fit and makes Enable 3D the switch.

## The route

1. **Togl asks for a stereo visual only where the display offers one.** When Enable 3D is on (`stereo3d.enable 1` in `ng.opt`, the default) or `-stereo` is given, the script first asks the display (`glXChooseVisual` with `GLX_RGBA`, `GLX_DOUBLEBUFFER`, `GLX_DEPTH_SIZE 1`, `GLX_STEREO`, through a small command, `Ng_Stereo3DVisual`) and only then makes the widget with `togl .ndraw ... -stereo native`; on a desktop without a stereo visual (Xvfb, a 2D session) it makes the ordinary widget, so the person gets one picture with nothing said (Togl must never be asked there: see the first trap). If Togl still refuses the stereo widget where the display offers the visual, the script makes the ordinary one and the status bar says so.
2. **Mesa declares the drawing area, not the window.** Togl's window is a GLX child of the Tk window; the edition's Mesa lists it in the top level's `_KDE_NET_WM_STEREO_CONTENT_CHILDREN` and declares it (`_KDE_NET_WM_STEREO_CONTENT` 3) at its first swap of the eye buffers once its window is viewable (patch 0045: Tk draws the child before it maps its window). Stereo KWin redirects the child and writes `_KDE_NET_WM_STEREO_DEPTH_LIMITS` on it (declaration support 11). Menus, buttons and the status bar stay one picture in both eyes.
3. **The limits, in the area's own pixels.** In the draw callback, with Togl's context current: `stereo_depth_x11_get_buffer_limits(glXGetCurrentDisplay(), glXGetCurrentDrawable(), w, w, &limits)`, `w` the viewport's width (Togl's window is the buffer and is shown at its size). Keep the Xlib, GLX and libstereo-declare includes in a file of their own (`stereo3d.cpp`): Xlib's `Status`, `Bool` and `None` clash with Netgen's names. `-ENODATA` in the first frames is normal; draw identical eyes until the limits come.
4. **The fit, by pixels.** Netgen's camera is `gluLookAt` from 6 units onto the scene's centre, the model scaled by the inverse of its bounding radius, `gluPerspective(20°, w/h, ...)`; the zero-parallax distance `C` is 6. Before the two eyes, draw the scene once from the camera between them into `GL_BACK_LEFT` and read its depth (`glReadPixels`, `GL_DEPTH_COMPONENT`, `GL_FLOAT`; the cleared depth 1.0 is the background). Netgen draws its overlays (the coordinate cross, the logo, the colour bar, the title) with the depth test off, so they write no depth and do not count. With `D = B / ((2d - 1) + A)` (`A = P[10]`, `B = P[14]` of that pass's projection), `k` half the viewport's width times `P[0]`, the separation `t` (a fraction of `C`) is the smallest of `popped / (k (C/Dnear - 1))` and `sunk / (k (1 - C/Dfar))`; with nothing off the plane, infinity at the sunk limit. Each eye then moves sideways by `±t C / 2` with the frustum sheared back to meet at `C` (patch 0003's shift).
5. **A live change.** A Tcl loop (`after 250`) calls the library through a small command (`Ng_Stereo3DPoll`) and asks Togl for a new frame when the limits changed since the last one was drawn; the program needs no event of its own.
6. **The options.** "Enable 3D (applies the next time Netgen starts)" in View, Viewing Options, saved at once into `ng.opt` (every other line of the file kept), because Togl chooses its visual when the widget is made; a button "3D display settings..." runs `systemsettings kcm_kscreen`, else `kcmshell6 kcm_kscreen`, and says so when neither starts. No separation, no swap (a program that renders its own scene offers none).
7. **Tell, once:** limits not offered, not delivered after about two seconds, not readable, the depth not readable, or no stereo buffers on a desktop that offers them; each sentence once, in the status bar and on standard error, in the person's language through Tcl's `msgcat` (catalogue names are lower case: `pt_br`, `zh_cn`, `zh_tw`).
8. **Trace for the proof:** `NETGEN_STEREO3D_TRACE=1` prints each frame's limits, view size, `k`, `C`, the nearest and farthest distances, the separation and the predicted extremes in pixels.

## The closed-form scene

Two boxes in a CSG file, `orthobrick (-1, -1, 0.5; 0, 0, 1)` red and `orthobrick (0.2, 0.2, -1; 1, 1, -0.5)` blue: the bounding box is -1 to 1 on every axis, so the centre is the origin, the radius is the half diagonal `√12 / 2`, and a point at height `z` stands at `D = 6 - z / √3` from the camera.
The nearest pixel is the red front face (`D = 5.42265`), the farthest the blue box's back edges (`D = 6.57735`).
With the drawing area 991 pixels high, `k = (991 / 2) / tan(10°) = 2810.12` whatever its width, and at 10 sunk and 4 popped the popped limit decides: `t = 4 / (k (6 / 5.42265 - 1)) = 0.0133693`.
Predicted: red front -4.000 px; blue front (`z = -0.5`) +1.725; blue back edge +3.298. At 20 and 8: -8.000, +3.449, +6.596.
Which edges carry which depth: the blue box's left silhouette is its back edge (`z = -1`) and its right silhouette its front face; the red box's inner edge (`x = 0`) lies in the plane through the camera, so its column holds every depth from 5.42 to 5.71: measure the red left edge only.

## Traps

- **Togl 2.0 ends the program on a 2D screen when it is asked for a stereo visual.** **Symptom:** with Enable 3D on by default, Netgen dies at start on Xvfb (any display without a stereo visual): "X Error of failed request: BadWindow (invalid Window parameter)", "Major opcode of failed request: 3 (X_GetWindowAttributes)", "Resource id in failed request: 0xffffffff", exit status 1; with Enable 3D off it starts. **Cause:** Debian's Togl 2.0 (`libtogl2` 2.0-5), asked for `-stereo native` where no visual matches, leaves the Tk window without an X window, and Tk's input context (`XCreateIC`, from `Tk_MakeWindowExist`) asks the server about window 0xffffffff; Xlib's default error handler then exits, so no Tcl `catch` around the `togl` command can help. **Fix:** ask the display for a stereo visual first and give Togl `-stereo native` only when one exists. **How found:** gdb with `break exit` gave the stack (`_XDefaultError`, `XGetWindowAttributes`, `_XimSetICDefaults`, `XCreateIC`, `Tk_MakeWindowExist`, `libTogl.so.2`); then Togl alone in `tclsh` with `package require Tk` under Xvfb: a mono widget lives, a `-stereo native` one ends the interpreter with the same error. The development rows had never run on a 2D screen (the rig image had no Xvfb), so only the first package's 2D-screen row showed it. The same `XCreateIC` and `BadWindow` lines have a second cause on the stereo stack, a `libGLX_mesa` built alone against the package's `libgallium` ([x11-declared-child-limits-and-first-pair.md](../../native-linux/references/x11-declared-child-limits-and-first-pair.md), the stand-in build): tell them apart by whether a mono widget lives.
- **A 2D-screen row passed on a black picture.** **Symptom:** "2D screen: one view, nothing said" passed: the capture was 1920 wide and held no sentence, because Netgen had died before drawing anything; the rig's log also said "program alive before the end: yes". **Cause:** the verdict checked only the width and the absence of a sentence, and the rig's `kill -0 "${PID:-0}"` with no process found is `kill -0 0`, which succeeds (it signals the shell's own process group). **Fix:** the row requires the program's process to be found and alive at the end, its exit status not 1, and both boxes drawn in the picture (red and blue pixels counted); `[ -n "$PID" ] && kill -0 "$PID"`. **How found:** looking at the passing row's picture: one colour, black.
- **Editing a `.tcl` file changes nothing in Debian's build.** **Symptom:** a change to `ng/drawing.tcl` never shows. **Cause:** Debian builds with `USE_INTERNAL_TCL=ON`, which compiles the GUI scripts into the library from `ng/onetcl.cpp`, a generated file (`ng/onetcl.py` joins every script and drops what follows `#`). **Fix:** regenerate it and carry only the delta of your scripts in the patch; the shipped `onetcl.cpp` differs from the generator's output by a stale Togl 1 branch, so a whole regeneration is a bigger change than the patch needs. **How found:** the drawing area kept upstream's Togl line after the scripts were patched; `grep -n togl ng/onetcl.cpp`.
- **`ng/variables.tcl` has CRLF line ends** (upstream converted the tree to LF after 6.2.2606, in September 2026); a patch made with an editor that saves LF rewrites the whole file. Edit its bytes.
- **The window tree of a flat run has no drawing area in the proof rig's property list.** **Symptom:** a 2D control has no area to compare. **Cause:** `x11_props.py` records only windows that carry stereo or window-manager properties. **Fix:** save `xwininfo -root -tree` with every capture and take Togl's window from it (the nameless child as wide as the window, between the menus and the status bar).
- **Whole-pixel edges.** Netgen draws without antialiasing, so an edge's disparity is a difference of two rounded columns, within a pixel of the closed form (blue front +1.725 measured +2, +3.449 measured +4); the red front, at an exact -4.000, measures -4 in every row. Block matching with a parabola adds a quarter pixel near mesh lines (-4.28 against -4): count blocks inside the limits with half a pixel of tolerance.
- **Picking.** Netgen picks in a pass of its own with the projection current at the time; the eyes' shifted projections are restored to the mono one after the pair, so a double click finds the same element and point as a single view.

## Building the successor package

The successor of a staged edition source (`+stereo3d1+lc1` to `+stereo3d2+lc1`) is made with `repo/lc-successor.py --in-place --overlay DIR`; recipe `sparky-os/packages/netgen-stereo-2` (`prepare-source-stereo3d2.sh`, `build-stereo3d2.sh`).

- **An overlay that carries a whole `debian/control` adds every Debian maintainer's address to the build tree.** **Fix:** change Build-Depends with `--depends OLD NEW` (repeatable; each OLD must occur exactly once in the file, so anchor on a whole line with its newline: ` libswscale-dev,` was once, ` pybind11-dev,` twice).
- **A new patch in the recipe's `patches/` folder leaks into the previous version.** **Symptom:** none until a rebuild. **Cause:** the earlier version's `build.sh` copies every `patches/*.patch` into its series. **Fix:** keep the new patch only in the overlay.
- **`lc-successor: [Errno 13] Permission denied: '/lc-successor-...'`.** **Cause:** the tool makes its temporary folder beside OUT (`--work` or OUT's parent), and OUT was a mount at `/src`. **Fix:** give it a subfolder (`/src/source`) or `--work`.
- **`cp: cannot stat '.../netgen_6.2.2606+dfsg1.orig.tar.xz'`** right after the source was made. **Cause:** OUT holds only the new `.dsc` and Debian tarball (the orig tarball is the published one, unchanged). **Fix:** copy the orig tarball beside them before the build.
- **`<urlopen error [Errno 2] No such file or directory: '/dmo/pool/main/f/ffmpeg-dmo/libavutil61_9.0.2-dmo5_amd64.deb'>`** in `override_dh_builddeb`, after every package was built and verified. **Cause:** the link gate builds its own universe from the archives it is given, with no apt pin, so among the FFmpeg builds it takes deb-multimedia's newest (10:9.0.2-dmo5), while a frozen deb-multimedia mirror held only the files the rig's pinned installs had needed; the built packages stay in the gate's temporary folder and are lost. **Fix:** simulate the install of the program's packages on a bare base image with the same archives and the pin removed (`apt-get -s install ...`), then fetch exactly the deb-multimedia files its `Inst` lines name into the frozen mirror, each checked against the frozen index's SHA-256 and size; then build again from clean. **How found:** the gate's last line in the build log; the simulation on the builder image showed nothing to fetch, because the builder already has those libraries installed: the gate starts from an empty system, so simulate on one.
- **`dpkg-source: warning: diff '...0004-....patch' patches hard link ...`** while the source is packed: the in-place tree shares its upstream files with the unpacked old source, both temporary; harmless.
- **`dpkg-source -b` applies a series member that is not applied yet** (its `--no-preparation` turns that off), so a patch added at the end of the series needs no `--reapply-patches`.
