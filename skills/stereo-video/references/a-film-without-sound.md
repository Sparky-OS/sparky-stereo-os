# A film without sound says so (ORDER 579)

A film with a picture and no audio track shows a volume control at its usual level, which reads as a broken system (Daniel, 2026-11-14, "true, good measure!" to the proposal).
Every player the edition ships and maintains now says "This film has no sound.", in ten languages, and its volume control stays usable.

## The recipe

1. **One sentence, one rule, one place.** The stereo layer (stereo-layer 1.21.0) holds the sentence in its catalogue (`po/LANG/stereo-layer_qt.po`, context `Stereo::NoSound|`) and the rule: the tracks are known, there is a picture, there is no audio track (`Stereo::NoSound::applies(loaded, hasVideo, audioTracks)`, QML singleton `org.sparky.stereo` `NoSound` with `text` and `saysFor()`). Audio-only files are never said to have no sound; a file whose tracks are not read yet is not said anything.
2. **Each player keeps knowing its tracks the way its engine does** and tells the sentence in its own way, beside its volume control and once when the film opens, never as a dialog and never through sparky-stereo-problems:

   | Player | Where it learns the tracks | How it tells |
   |---|---|---|
   | Dragon Player | Qt Multimedia `MediaPlayer.hasVideo`, `audioTracks` | a Kirigami InlineMessage for 8 s; the volume button's tooltip and accessible description |
   | Plank Player | Qt Multimedia `Video.hasVideo`, `hasAudio` | a banner for 8 s; a label in the OSD (it has no volume control) |
   | Haruna | mpv's `track-list` in `MpvItem::loadTracks` (signal `tracksLoaded`) | its OSD once per file; tooltips of the volume slider and mute button |
   | Bino | `MetaData` video and audio tracks | the sentence on the picture for 6 s in place of a missing subtitle (its subtitle overlay); an info line in the Media menu |
   | sView | `StVideo::hasVideoStream`, `hasAudioStream` | a description box for 6 s; a line under the cursor on the volume button and bar; string 2115 in `StMoviePlayer/lang/*` |
   | VLC Stereo | Qt `InputManager`: `video-es` and `audio-es` choice counts | `vout_OSDMessage` once; the volume widget's tooltips |

   Dragon, Plank, Haruna and Bino take both sentence and rule from the layer. sView (its own toolkit and language files) and VLC (its own gettext catalogue) keep a copy, and `tests/no-sound-wording/check.py` in the build tree fails when a copy differs from the layer's in any language: `check.py --layer-po LAYER/po --sview-lang SVIEW/StMoviePlayer/lang --vlc-patch PATCH --self-test`.
3. **Fixtures** (the rig's `make-fixtures.sh`, ffmpeg and x264 of the edition): a marked full side-by-side film, video only (Matroska with StereoMode and the frame packing SEI; MP4 with the SEI), the same with audio (the control), audio starting 4 s late, two audio tracks, an audio-only file, a 2D film with and without audio.
4. **Proof rows**, each with a repeat command (`rig/drun.sh IMAGE OUT PLAYER LANG SCALE FILES STEPS`): said for the silent film; not said for the control; said again for the next silent file of a playlist and gone for the next with sound; German and Japanese read on screen; 100 % and 125 %; both eyes of the 3D film unchanged against the published build; the 2D film unchanged.

## Traps

- **Dragon's upstream disables the volume controls instead** (invent.kde.org/multimedia/dragon merge request 99, merged 2026-11-03, after the 26.04.0 base): silent, and it contradicts "nothing disabled to make the point". When Dragon rebases onto a release that has it, keep the sentence and give the disabled button a way to show it (a disabled button shows no tooltip).
- **A rule evaluated on a model that is cleared first flickers.** Haruna's audio track model is cleared and refilled at every load; a QML binding on its `rowCount` said "no sound" for every film. Decide once, from one signal sent after the tracks are loaded.
- **Symptom: Dragon's controls bar shows only the seek slider in the rig.** Cause: no Qt Quick Controls style (and no desktop name), so the buttons are not drawn. Fix: `QT_QUICK_CONTROLS_STYLE=org.kde.desktop` and `XDG_CURRENT_DESKTOP=KDE` (and `breeze-icon-theme`, `kdeglobals [Icons] Theme=breeze`). Found by loading the same bar with the style set.
- **The bar appears only when two pointer motions arrive within 50 ms** (Dragon's `mainHoverHandler` resets its first point after `veryShortDuration`): send the `m:X,Y` steps back to back, not with `s:` waits between.
- **Rig, `kwin_wayland: Operation not permitted`:** needs `--cap-add SYS_NICE`. **ScreenShot2 `Cancelled`:** no render node. **dbus "Could not get password database information":** the container needs a passwd entry for the uid. **No Qt Wayland shell integration:** install `qt6-wayland`.
- **`dpkg -i deb-multimedia-keyring` in an image breaks apt** (it needs gpgv): extract the key file with `dpkg-deb -x` instead.
- **Making the next source:** `repo/lc-successor.py --in-place --overlay DIR --next V --item TEXT [--depends OLD NEW]` adds a patch to a published `+lc1` source (its "patches hard link" warnings are harmless); it needs `DEBFULLNAME` and `DEBEMAIL` (`dch` prompts without them) and a source date. A native source (sView) and a source with a new orig tarball (the layer) are remade from their commit with `lean.debian_prepare` (it needs `sparky-os/packages/dpkg-stereo/LICENSE` in a sparse checkout). The build script must call `sparky_provenance_init` and pass `SPARKY_PROV_ARGS`, or `lean.release` says "release blocked: the build script did not call sparky_provenance_init".
- **A recipe in the build tree is not what ships.** The tree's sView recipe was at +stereo3d5 (ORDER 529, fork commit 41bddfc6) while +stereo3d4 was published and no +5 package was staged; the next version builds on the newest recipe, or it would regress it when +5 is published.
- **Symptom: Bino compiles the notice and shows nothing.** Cause: the picture shader draws the subtitle only when its `showOverlaySubtitle` flag says so, and the flag read `_frame.subtitle`, not the text the overlay was given. Fix: one `subtitleText()` for the overlay, the flag and the paint. Found by the green capture: the sentence was in the overlay and not on the picture.
- **Symptom: Plank Player never says it.** Cause: Qt Multimedia's QML `Video` type has no `mediaStatus` (only `MediaPlayer` has), so "loaded" was undefined and the rule never held; `Video.hasAudio`, `hasVideo` and `duration` exist. Fix: loaded is `duration > 0`. Found by reading `QtMultimedia/Video.qml` in the image (`property alias` lines).
- **Symptom: the sentence is English in German and Japanese in Dragon and Plank, and right in the layer's unit test.** Cause: the layer's catalogue is installed by a startup function of the library; a QML plugin loaded after the application exists can be read before it ran. Fix: `NoSound::sentence()` installs the catalogue of the program's language once when the lookup gave the source text back. Found by running the same row in the other languages.
- **Symptom: sView says a film with audio has no sound.** Cause: `hasAudioStream()` is true only when OpenAL opened a device, and the rig has none ("OpenAL: no playback device available"). Fix in the rig: `ALSOFT_DRIVERS=null`. On a machine without an audio device the sentence is true for what the person hears. sView also showed "X: could not open display" at random: wait for `/tmp/.X11-unix/X0` before starting it.
- **sView in Japanese draws boxes in the rig:** the string is loaded (one box per character) and the font sView picks has no CJK glyphs there; not fixed here.
- **A link gate that cannot see an unpublished sibling blocks the build:** `bino Depends libstereo-av1 (>= 1.21.0) ... [no choices]`. Give the gate the lane's own libraries (`SPARKY_LC_SIBLINGS_FILE`), except when building those libraries themselves (two supplied copies of one package are refused).
- **A QML program whose `${qml6:Depends}` names `org.sparky.stereo` fails with "Missing QML module org.sparky.stereo":** put `libstereo-layer1` in its Build-Depends so the module is installed; the generated Depends then names it.
- **A pin for the lane's flat folder:** apt keeps the published build (priority 1001 for the edition's repository) unless the folder is pinned higher (`Pin: origin ""`, 1002); read the `Inst` lines to see that it upgraded.
- **Comparing a published build with ours on live video:** a frame counter and moving shapes differ by timing, so "the same" is a share of pixels within 8 per channel (82 to 90 % for the 3D film, 100 % for a still 2D player) and the eyes' difference staying where it was; an exact comparison needs a paused or seeked frame. A 2D desktop capture is one picture 1280 wide, not two: split a capture only when it is 2560 wide.
- **Proof rows are repeatable:** `rig/rows.sh IMAGE TAG` runs fresh-session rows (silent, control, German, Japanese, 125 %, MP4, late audio, two audio tracks, audio only, 2D, playlists) and `rig/compare.py` the unchanged-picture table; `rig/mark_pns.py` writes the evidence stereo captures as `.pns` (sTER, mode 1, before IDAT) and reads them back.
- **VLC: the tracks of a kind are not `CHOICESCOUNT`.** Symptom: the Qt interface never decides "no sound". Cause: `video-es` and `audio-es` each carry a "Disable" choice (-1) the input adds, so the count is never 0. Fix: count the choices with `VLC_VAR_GETCHOICES` and skip -1; decide again when the picture is there (events arrive in either order). Found by printing the counts: `video 1 audio 0` for the silent film.
- **VLC: the title of the file is written on `VOUT_SPU_CHANNEL_OSD` as the picture starts and replaces a message on that channel.** Fix: register a channel (`vout_RegisterSubpictureChannel`), write with `vout_OSDText` at the top for 5 s, and tell 1.5 s after the picture starts. `vlc_osd.h` does not exist in 3.0: `SUBPICTURE_ALIGN_TOP` is in `vlc_subpicture.h`.
- **A development build with Lean Code is not what you edit:** the package step restores the authored source into the tree as root, so a host edit of a tree file is refused or lost; edit inside the container, as root (`rig/vlc-dev-remake.sh` does), run `make -C modules libqt_plugin.la` and copy the plugin into the image's install tree. The development plugin is a test, not a package; the lean gate of the package step is not run on it.
- **VLC in the rig does not translate even its menus** (published build included), so German and Japanese on screen were not reached; the catalogues were read back with `gettext.GNUTranslations` (all nine languages give the sentence). The cause is not found.
- **Symptom: the build tree's wiring test fails, "packs a source without normalizing its tree".** Cause: the builder ran a full `dpkg-buildpackage`, which packs the source again inside the build, so the staged `.dsc` and tarball were not the ones the source script made. Fix: `dpkg-buildpackage -b -us -uc` builds all the binaries from the supplied descriptor (the build record's `files` then names the staged `.dsc` and its sha256 matches). `edition-packaging` lessons, "Two staged works on one library", has the same trap.
- **Symptom: the same source script gives another tarball under another umask.** Cause: `tar -x` and `dpkg-source -x` as an ordinary user apply the umask to the modes in the new archive. Fix: the recipe sets `umask 022`; proof: run the script again under `TZ=Asia/Tokyo` and `umask 077` and `cmp` every `.dsc` and tarball (`rig/verify-stage.sh`).
- **A test only a lane knows is a test nobody runs:** the round's four pre-round checks are fixed; `tests/no-sound-wording/check.py` runs with no arguments from a clone (it keeps the layer's sentences in `layer-sentences.json` and reads the sView and VLC copies from the recipe's patches) but reaches the round only when its pre-round script calls it.
