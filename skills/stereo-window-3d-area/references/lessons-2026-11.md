# stereo-window-3d-area: lessons from the lanes of 25 October to 6 November 2026

Harvested by ORDER 429 from the accepted lane reports; each line names the lane it came from.
A trap gives its symptom, its cause, its fix and how the cause was found; a recipe gives the commands and the result to expect.

## Recipes that worked

- Menu chains, an applet pop-up and the launch feedback in a real plasmashell session (ORDER 464): one fresh session per case on a virtual Stereo KWin in an anaglyph mode (1920x1080, the person's PoppedLimit), `fakeinput` for the pointer and keys (one process per line: move, wait and button together), a KWin script that lists `workspace.stackingOrder` with each window's frame, type and `appletPopup`/`popupWindow` flags, ScreenShot2 for both eyes, and for each window the horizontal shift that makes the right eye equal the left on the part of its frame that no later window covers (device pixels, left minus right; positive is nearer). A test program with a chain of sub-menus (Qt Widgets, GTK 3 through python) opened from the menu bar (Alt+mnemonic, then Right) and from a right click (Down, then Right), `MENU_LEAVES` long enough for a menu taller than the output, block noise in the window so every part of it has a pattern to match. Run the same case on the packaged old and new kwin (an image per version with the packages installed) and read the two tables side by side.
- The launch feedback (the busy cursor) on Wayland starts when a client asks for an `xdg_activation_v1` token with an app id whose desktop file KWin can find and the client is privileged (it has bound `org_kde_plasma_window_management`, as plasmashell does): a 100 line C client does it, and the feedback lasts the effect's timeout (5 s), so capture while it runs and difference the capture against one taken just before.
- Popup border test (testStereoPopupBorder): red on +stereo3d43 with the two option lines removed = 5 passed 16 failed; green on +stereo3d44 = 21 passed. Corners (0,0)(260,0)(0,200)(260,200) -> (10,10)(250,10)(10,190)(250,190); a menu ending at the edge flips; X11 override-redirect popups moved once at track(), a program moving a mapped one itself is not corrected (lane kwin-popup-border-418)
- Faked 3D in shared QML (tab switcher) is doubled with Qt's Rotation/Matrix4x4 and matrices from KWin (TabBoxSwitcher.stereoRotation(), eyeOffset()), never new QML types, because X11 sessions read the same switcher QML. Motion is frame-time based with no timers: WorkspaceScene keeps one motion per window and one for the pointer, sets targets in prePaint(), asks the next frame in postPaint() (lane kwin-stereo-effects)

## Traps: the symptom, the cause, the fix, how it was found

- Symptom: a combo box's list or a menu opened inside a dialog sits flush with the dialog (Save As, a Settings page), at one popped limit. Cause: the chain's depth counted only windows `isPopup()` calls popups; a dialog is popped over its window (transient for the active window) but is no popup, so it counted nothing and its list counted one. Fix: count every window of the transient chain whose role is popped, from the window up, dialogs and a pop-up of the panel that holds a menu included: dialog 1, its list 2, a sub-menu of that 3 limits (and from the pinned window's level over a Keep Above window). Found by: review; the test makes a dialog (an xdg top level with a parent) with a list and a menu and sub-menu in it, plain and kept above, red on the first +50 (list 10 against 20).
- Symptom: opening a sub-menu moves its parent menu back (menu at 5 alone, 3 with a sub-menu at 5, at a popped limit of 5), and "two levels twice the separation, three levels three times" is not what the screen shows. Cause: the popped limit was shared among the chain by stacking order (limit / number of popups), so the step depends on the chain's length. Fix (ORDER 464, Daniel 2026-11-08): level n is n popped limits from its base, the screen for a plain window and the pinned window's level for a window kept above the others (5, 10, 15, 20 plain; 5 then 10, 15, 20 kept above, at a limit of 5), a menu alone at the limit, nothing above moved when a sub-menu opens, a chain that stops growing at six levels, a popup with no parent (an X11 override-redirect menu) the n-th such popup in the stacking order; notifications and on-screen displays keep ORDERs 424 and 442. Found by: a chain of one to four menus measured on the packaged +39 and +46 (3 5, 2 3 5, 1 3 4 5); the test opens each level and compares the parents' parallax before and after.
- Symptom: after a restart a prompt or a new window opens on an output that is not the person's first until the mouse moves. Cause: `Workspace::updateOutputs()` made `m_outputs[0]`, the order the backend lists the connectors in, the first active output (and `desktopResized()` the fallback), and the pointer started on the output that holds the workspace's centre; KWin master and Plasma/6.7 do the same. The screen marked main in Display Settings is the front of `outputOrder()` (priority 1, `kde_output_management_v2.set_priority`: "the order of outputs can be used to assign desktop environment components to a specific screen"; Daniel 2026-11-08: the pointer at login "should be done by the marked main on the display settings"). Fix: `Workspace::firstOutput()`, that screen, for the first active output, the fallback and the pointer's start; with no output marked, the front of the order. The test marks another screen main through the same `OutputConfiguration` priority that `set_priority` builds and reads the order; `KWIN_TEST_MAIN_OUTPUT` picks which screen the saved configuration marks. A virtual backend adds its outputs after the workspace exists, so KWin's placeholder route (`updateAfterScreenChange()` puts the pointer on `outputOrder().at(0)`) already gives the right answer there: the case cannot be reproduced on `--virtual` or in the autotest backend, only where the outputs exist when the workspace is made (DRM).
- Symptom: a menu opened from a menu with a sub-menu that does not fit (a long Open With, a long Create New) draws its sub-menu behind its parent, at the screen's level while the parent is popped. Cause: the edge rule, "a popped thing that touches the output's edge stays at the screen's level", applies to a menu taller than the room inside the 10 px border, which touches the edge whatever KWin does, so the share of the popped limit counted the parent alone (parent at the limit) and the sub-menu was flattened to 0. Fix: a popup larger than the room inside the border keeps its level (`edgeFlattens()` in `src/scene/stereodepth.cpp`), so the chain keeps one step per level above its parent. Found by: the same chain on a menu of 60 items on a 1080 output, +39 and +46 both showing parent 5, sub-menu 0 (the menus that fit were right on both, so a short chain proves nothing). A test needs a sub-menu taller than the output minus 2 x border.
- Symptom: with two windows the unfocused one sits at the wallpaper's depth ("dropping to the bottom"). Cause: the windows beneath the active one share the sunk range among them, the lowest at the limit, so a lone one is the whole limit; measured identical on the packaged +39 and +46 (two windows: -10, three: -10 and -5, six: -10 to -2, twelve: -10 to -1 at limit 10), so it was never a regression of one version. Fix (ORDER 464, Daniel's rule of 2026-11-08): the windows beneath step back one layer each, a layer being a fifth of the limit, the first right behind the screen, the sixth and the rest sharing the limit and never behind the wallpaper (Daniel chose that over letting the stack pass the limit, memory 2026-10-30: a wallpaper is the deepest layer). Before changing a stack rule, measure the old package: the code diff between the two versions was empty.
- Symptom: the busy cursor stays at the screen's depth while the pointer is over a window beneath the active one. Cause: the launch feedback effect draws its icon in `paintScreen` after the scene with no parallax, and the pointer is drawn by the scene at its own depth. Fix: the icon takes the pointer's plane through the same eased motion (`StereoDepth::Motion`) and `StereoDepth::eyeShift`; on an output that shows 3D the bounce is in depth only, from the pointer's plane up to the popped limit, and on a 2D output KDE's bounce is untouched. Found by: the capture of both eyes with the icon, which showed 0 parallax over a sunk window.
- Symptom: an effect's test cannot hold the animation at a frame. Cause: the startup feedback's clock follows real time and ignores the animation speed. Fix: a `frame` property on the effect for tests (a frame from 0 holds, -1 lets it run), as Fall Apart has `progress`.
- Symptom: a sub-menu parented to the panel popup raised over it and sat behind its parent in depth (+5/+3 at limit 5). Fix: "never behind what its own window popped up before it" (commit bf54a1ded0); with no room left it shares the level (lane kwin-stereo-effects)
- Symptom: depth state of two browser windows leaks: an inactive window draws popped and sunk boxes with depth when it must be a flat sheet; a window on a 2D output shows depth; after a drag back one window reads another's limits. Cause: `widget.wayland.stereo-depth.*` were process wide default prefs of the last window KWin told. Fix: each nsWindow keeps its own StereoDepthState (awake, limits, output edges, output width) from its kde_stereo_depth_v1 listener and passes it to the browsers shown in that window through a PBrowser message; out of process frames follow the top level window. Result table (inactive -7,-7,-7; active 3,-7,0; 2D output 0,0,0; 2D capture byte identical with the property on and off). (lane waterfox-stereo)
- Symptom: select lists, tooltips, autocomplete and permission prompts in the browser sit at the window's level (disparity 0) while the context menu pops (3). Cause: Gecko maps popups constrained by layout (and tooltips, panels, noautohide) with the UTILITY or TOOLTIP hint, which GTK 3.24.52 maps as wl_subsurface (`should_map_as_subsurface`); only POPUP_MENU becomes xdg_popup; Stereo KWin pops only xdg_popups. Fix: `widget.wayland.popups-as-xdg-popups` (default true, applies only when `kde_stereo_content_manager_v1` is offered): POPUP_MENU hint for all, hide place show for non move-to-rect popups. Proof: all kinds `get_popup` and disparity 3 equal to a Qt QMenu in the same KWin. Upstream bug 2012468 still open. Found by: WAYLAND_DEBUG=client showing `get_subsurface` and no `get_popup`. (lane waterfox-stereo)
- Symptom: the browser exits -11 (SIGSEGV) at quit whenever a subsurface popup is open (permission prompt, noautohide panel, select list). Cause: a deliberate crash: Gecko's WlLogHandler MOZ_CRASH on a Wayland protocol error; the wire log shows the window's xdg_toplevel/xdg_surface/wl_surface destroy and then `wl_subsurface.set_position(230, 71)` for its popup (bad_surface). Fix: do not move a popup whose window is gone (exit 0 in 5 red/green runs). Found by: `WAYLAND_DEBUG=client`; with libxul stripped and gdb without ptrace (`Operation not permitted`, file capabilities) an `LD_PRELOAD` shim on `wl_proxy_marshal_flags` plus one `fprintf` per call site gave the caller. Lesson: a quit that crashes with a compositor error line is a protocol violation, not a memory error. Same code in Mozilla main (no bug found), report drafted with the patch. (lane waterfox-stereo)
- Symptom: a window rule "popped element touching the output's edge stays at the screen" never fires in normal windows. Cause: the browser's viewport is inset from the window (kiosk 11,5; maximised 63,89), so the rule needs a flush viewport (page in full screen); tests must use `requestFullscreen` (`full-screen-api.allow-trusted-requests-only` false in the test profile). The URL bar list is in window DOM so only CSS `depth: popped` can raise it; a 10 px constant border applies for popped elements of the browser's own windows. (lane waterfox-stereo)
- Symptom: dev build tests for the WebRender compositor (xr6b) fail. Cause: dev builds (`obj-dev`) lack the package's preference defaults. Fix: set `gfx.webrender.compositor.force-enabled`; use the package runs as the cited ones. The cycle proofs also need `KWIN_OUTPUT_CONFIG=rig/kwinoutputconfig-capable-2d.json` (flat WebXR is offered only where an output shows or can show stereo). Small popups: ScreenShot2 diffs need a low run threshold (a tooltip is 33 px high) and a page background that differs from the popup's. (lane waterfox-stereo)

## Perks of the part

Not exercised: Task Manager jump lists, widget config windows, multi-output popups (lane popup-border-plasma-422)

(lane ingetrazo-stereo-296)
