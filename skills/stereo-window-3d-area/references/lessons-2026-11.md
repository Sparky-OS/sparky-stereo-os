# stereo-window-3d-area: lessons from the lanes of 25 October to 6 November 2026

Harvested by ORDER 429 from the accepted lane reports; each line names the lane it came from.
A trap gives its symptom, its cause, its fix and how the cause was found; a recipe gives the commands and the result to expect.

## Recipes that worked

- Popup border test (testStereoPopupBorder): red on +stereo3d43 with the two option lines removed = 5 passed 16 failed; green on +stereo3d44 = 21 passed. Corners (0,0)(260,0)(0,200)(260,200) -> (10,10)(250,10)(10,190)(250,190); a menu ending at the edge flips; X11 override-redirect popups moved once at track(), a program moving a mapped one itself is not corrected (lane kwin-popup-border-418)
- Faked 3D in shared QML (tab switcher) is doubled with Qt's Rotation/Matrix4x4 and matrices from KWin (TabBoxSwitcher.stereoRotation(), eyeOffset()), never new QML types, because X11 sessions read the same switcher QML. Motion is frame-time based with no timers: WorkspaceScene keeps one motion per window and one for the pointer, sets targets in prePaint(), asks the next frame in postPaint() (lane kwin-stereo-effects)

## Traps: the symptom, the cause, the fix, how it was found

- Symptom: a sub-menu parented to the panel popup raised over it and sat behind its parent in depth (+5/+3 at limit 5). Fix: "never behind what its own window popped up before it" (commit bf54a1ded0); with no room left it shares the level (lane kwin-stereo-effects)
- Symptom: depth state of two browser windows leaks: an inactive window draws popped and sunk boxes with depth when it must be a flat sheet; a window on a 2D output shows depth; after a drag back one window reads another's limits. Cause: `widget.wayland.stereo-depth.*` were process wide default prefs of the last window KWin told. Fix: each nsWindow keeps its own StereoDepthState (awake, limits, output edges, output width) from its kde_stereo_depth_v1 listener and passes it to the browsers shown in that window through a PBrowser message; out of process frames follow the top level window. Result table (inactive -7,-7,-7; active 3,-7,0; 2D output 0,0,0; 2D capture byte identical with the property on and off). (lane waterfox-stereo)
- Symptom: select lists, tooltips, autocomplete and permission prompts in the browser sit at the window's level (disparity 0) while the context menu pops (3). Cause: Gecko maps popups constrained by layout (and tooltips, panels, noautohide) with the UTILITY or TOOLTIP hint, which GTK 3.24.52 maps as wl_subsurface (`should_map_as_subsurface`); only POPUP_MENU becomes xdg_popup; Stereo KWin pops only xdg_popups. Fix: `widget.wayland.popups-as-xdg-popups` (default true, applies only when `kde_stereo_content_manager_v1` is offered): POPUP_MENU hint for all, hide place show for non move-to-rect popups. Proof: all kinds `get_popup` and disparity 3 equal to a Qt QMenu in the same KWin. Upstream bug 2012468 still open. Found by: WAYLAND_DEBUG=client showing `get_subsurface` and no `get_popup`. (lane waterfox-stereo)
- Symptom: the browser exits -11 (SIGSEGV) at quit whenever a subsurface popup is open (permission prompt, noautohide panel, select list). Cause: a deliberate crash: Gecko's WlLogHandler MOZ_CRASH on a Wayland protocol error; the wire log shows the window's xdg_toplevel/xdg_surface/wl_surface destroy and then `wl_subsurface.set_position(230, 71)` for its popup (bad_surface). Fix: do not move a popup whose window is gone (exit 0 in 5 red/green runs). Found by: `WAYLAND_DEBUG=client`; with libxul stripped and gdb without ptrace (`Operation not permitted`, file capabilities) an `LD_PRELOAD` shim on `wl_proxy_marshal_flags` plus one `fprintf` per call site gave the caller. Lesson: a quit that crashes with a compositor error line is a protocol violation, not a memory error. Same code in Mozilla main (no bug found), report drafted with the patch. (lane waterfox-stereo)
- Symptom: a window rule "popped element touching the output's edge stays at the screen" never fires in normal windows. Cause: the browser's viewport is inset from the window (kiosk 11,5; maximised 63,89), so the rule needs a flush viewport (page in full screen); tests must use `requestFullscreen` (`full-screen-api.allow-trusted-requests-only` false in the test profile). The URL bar list is in window DOM so only CSS `depth: popped` can raise it; a 10 px constant border applies for popped elements of the browser's own windows. (lane waterfox-stereo)
- Symptom: dev build tests for the WebRender compositor (xr6b) fail. Cause: dev builds (`obj-dev`) lack the package's preference defaults. Fix: set `gfx.webrender.compositor.force-enabled`; use the package runs as the cited ones. The cycle proofs also need `KWIN_OUTPUT_CONFIG=rig/kwinoutputconfig-capable-2d.json` (flat WebXR is offered only where an output shows or can show stereo). Small popups: ScreenShot2 diffs need a low run threshold (a tooltip is 33 px high) and a page background that differs from the popup's. (lane waterfox-stereo)

## Perks of the part

- Keep a symbolised libxul (separate debug info or dbgsym) for crash work; `compare-runs.py` compares two runs box for box so a regression shows in one line. (lane waterfox-stereo)

## Measured facts

- Full KWin suite after the change: 583 passed 0 failed 18 skipped; with the edition's Xwayland (2:24.1.13-1+stereo3d3) testX11Window runs 240 passed 0 skipped (10 skipped without it) (lane kwin-popup-border-418)
- 10 px inside the output edges for popups, popups beside a panel stay attached to it, 2D output and PopupBorder=0 give the same frames as before. A popup that overlapped the left panel moved x 8 to 44 because the border applies to the placement area. Not exercised: Task Manager jump lists, widget config windows, multi-output popups (lane popup-border-plasma-422)
- Measured wallpaper parallax at 1280x800: lock screen 88.9 px, desktop 82.5 px (sunk layer), desktop at depth 0 88.9 px. A marker behind the screen gets further away (-96.4 against flat -88.9). Greeter windows count as isLockScreen() because they come from the locker's connection (waylandwindow.cpp) (lane wallpaper-disparity-284)
- Stereo KWin's right eye differs for a 2D surface with alpha below 1 under an opaque region (568 px in IngeTrazo's main window); minimal reproducer `rig/alpha_probe.py`; fixed by ORDER 319. IngeTrazo extension proofs: captured eye equals handed eye (0 px) on Wayland AMD, X11 AMD, X11 NVIDIA, disparity median absolute error 0.14 px, 99 to 100 percent within 1 px, 24 tests with a negative control failing 11; no system plugin folder in the program so the extension stays a source repository. (lane ingetrazo-stereo-296)
