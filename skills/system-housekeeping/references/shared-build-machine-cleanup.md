# Cleaning a shared build machine by proof

A build machine shared by several lanes (people or AI partners working at once) fills with build trees, caches, extracted copies, Docker images and the same file copied many times.
Most of it can go, but the same folders also hold the only copy of a stage waiting for publication, the evidence of an open review, or commits that exist nowhere else.
This page is the recipe that frees space without losing any of those, measured on a station with five work disks in one pass: 181 GB removed (105 GB of it old lane folders on a hard disk), 30.5 GB shared by hard links with every path kept, 7.7 GB of Docker images and containers removed by name, every removal logged.

## Recipe

1. **Measure first, per filesystem.** `df -B1` before and after, and `du -x -B1 -d1` of each work area, bounded (`timeout`, `nice`, `ionice -c3`), never following symlinks (`du -x`, `find -P`). Keep the measurements as small text files: they are the table you hand back.
2. **Give every folder its owner and its status.** Map each scratch folder to its lane, read the first line of the lane's report (`accepted`, `done`, `review`, `waiting`, `paused`, `working`) and its "Kept" section, and look for `.keep` files anywhere inside (a stage folder carries its own). A running, paused, waiting or in-review lane keeps everything. An accepted lane can still have a next milestone that reuses its tree: read the last lines of its report before you treat "accepted" as finished.
3. **Say what each part is** before deciding: a build tree (`lc/source`, `_build`, `obj`), a link gate's cache of dependency packages (`link-scratch`, `scratch/sha256`), a download (an SDK, Gradle or Maven caches, apt archives, test samples), an extracted copy of an archive the lane also keeps, a source clone, a stage, packages, evidence (logs, captures, measurements) or a VM image.
4. **Packages are checked against the published repository by hash, not by name.** Build a `SHA256 filename` index from the repository's own `Packages` and `Sources` files, then hash every `.deb`, `.dsc` and source tarball in a stage. A stage whose files are all in the index is published and can go; a stage with unpublished files stays unless a newer published version supersedes it and nothing names it for the next round. A package that is in no other place stays, even when it looks old.
5. **Clones: keep every commit and change that is only local, then remove.** For each clone run `git worktree list` first (see the traps), then keep, outside the clone, a bundle of the refs that no remote-tracking ref contains (`git bundle create FILE REFS... --not --remotes`, then `git bundle verify`), the binary diff of uncommitted changes (`git diff --binary HEAD`) and a tar of untracked files that are not ignored. For a branch you claim is online, compare `git ls-remote URL refs/heads/BRANCH` with the local head: a remote-tracking ref only says what was cached.
6. **Remove with a log.** Each removal appends time, status, path, allocated bytes freed, file count and the proof (the report line, the hash check, the bundle) to one table. A path that cannot be removed completely (files owned by root because a container ran as root) is logged as partial with the bytes actually freed, and listed for someone with the right to remove the rest.
7. **Exact duplicates on one filesystem are shared by hard links, never deleted.** Hash only regular files of 1 MB or more with a link count of one, grouped by size first and by a hash of their first 64 KB before the full SHA-256. For each duplicate, recheck immediately before acting: both still regular files on the same device, the same owner, group and mode, the duplicate's link count still one, neither changed in the last hour, and both still giving the recorded SHA-256. Then link the kept copy to a temporary name beside the duplicate and rename it over the duplicate. Every path stays; only the second copy's blocks are freed.
   Never linked: files inside a Git database; Debian packages, source packages, `.changes` and `.buildinfo` files (a publication gate freezes each input's inode, size, mtime and ctime, and a new link or the later removal of one link moves the ctime); caches that a program rewrites in place (Mesa's shader cache index is written through mmap); files of a running lane; a lane's runner logs.
8. **Docker on a shared daemon, by name only.** List images and stopped containers, map each name to its lane and status, check that no container (running or stopped) uses an image and that no running lane's brief names it, then `docker rm NAME` and `docker rmi NAME:TAG` one by one, logging each. Never a loop over an unfiltered `docker ps -q`, never `docker system prune`, `image prune -a` or `builder prune`: every lane's proxy reaches the same daemon, with the shared services on it. Base images and shared proof rigs stay.
9. **Hand back a table:** path, what it was, bytes freed or kept, the proof; the totals per filesystem before and after; and the kept list with the reason for each.

## What is safe in a finished lane's scratch, and what stays

| Part | Goes when | Stays when |
| --- | --- | --- |
| Build tree of a package | its packages sit beside it or in a stage, and the lane is accepted | the lane's next milestone builds on it incrementally (an Android `OUT_DIR` rebuilds one module in minutes, a full build in hours) |
| Link gate cache, ccache, SDK, Gradle, Maven, apt archives | always (downloads) | the lane is paused or its report keeps them for a pending upstream review |
| Extracted copy of an archive | the archive is kept elsewhere, checked as a different inode | the "other copy" is a symlink to it (see the traps) |
| Clone of a fork | every local-only ref is bundled and verified, or `ls-remote` shows the same head | it is shallow or partial and has local-only commits: a bundle would carry the whole tree or fetch every blob |
| Stage | every file's hash is in the published index | anything in it is unpublished, or a `.keep` says why it waits |
| Evidence, reports, briefs, notes | never in a removal pass | always; large text logs can be compressed with `xz` beside the keep set |
| VM image | the lane is finished and its runtime is rebuilt by a script in the repository | another lane's next step boots it |

## Traps: the symptom, the cause, the fix, how it was found

- **Symptom:** after a removal, the lane folder holds dangling symlinks where its kit archives were. **Cause:** the lane folder's "copies" of four kit archives were symlinks into the scratch folder; `sha256sum` follows symlinks, so "equal to the lane's copy" compared the file with itself. **Fix:** before calling anything a second copy, test `[ ! "$a" -ef "$b" ]`, compare `stat -L -c '%d:%i'` and run `find LANEFOLDER -xtype l`; a lane's `.artifacts` line that says "lane symlink" is a warning. **Found by:** `ls -la` of the lane folder right after the removal.
- **Symptom:** a second checkout of a source tree has a `.git` file pointing to a folder that no longer exists. **Cause:** it was a linked worktree of the clone just removed; the bundle of the main clone holds its branch, but not its uncommitted changes. **Fix:** `git worktree list` before removing any clone, and run the keep step in every linked worktree too. **Found by:** the next `git-keep` call failed with "not a git repository"; the orphaned tree was then compared with the bundle's branch (`diff -rq`, 0 differences) before it went.
- **Symptom:** a removal loop stops after one path with nothing logged for it. **Cause:** `set -e` with `pipefail`: `du` exits non-zero on a folder it cannot read (root-owned files from a container), so the script ended before writing its log line. **Fix:** no `set -e` in a removal helper; read sizes with `du ... 2>/dev/null`, remove with `rm -rf --one-file-system`, then log `removed` or `PARTIAL` with the bytes measured after. **Found by:** a removal that `df` showed but the log did not.
- **Symptom:** a cohort list of the next publication round names stages you are about to remove. **Cause:** the list was the cohort of the round already published and had not been replaced. **Fix:** check each listed file against the published index by hash; when every entry is published, the list guards nothing. **Found by:** 263 of 263 entries were in the published pool.
- **Symptom:** `tar -T LIST -C DIR` fails with "Cannot stat: No such file or directory" for every name. **Cause:** GNU tar applies `-C` only to names that come after it, and `-T` was read first. **Fix:** `tar -C DIR --null --no-recursion -T LIST -cf -`. **Found by:** the tar error file named files that exist under DIR.
- **Symptom:** a clone shows tens of thousands of commits "on no remote". **Cause:** a shallow clone of a large project (a kernel, Mesa) with no remote history to compare with. **Fix:** do not bundle it (the bundle is the whole tree); prove its own commits by content against the carried patch series, or keep it and say so. **Found by:** `git rev-list --count --branches --not --remotes` beside `.git/shallow`.
- **Symptom:** a bundle of a partial clone runs for hours and the disk fills. **Cause:** in a `--filter=blob:none` clone, any command that needs file contents fetches every blob. **Fix:** in a partial clone ask only commit-graph questions; prove a branch online with `git ls-remote` and keep the clone otherwise. **Found by:** `git config --get extensions.partialclone` before bundling.
- **Symptom:** a cache folder is "duplicated" hundreds of times. **Cause:** each container gets its own copy of the same shader cache or package cache. **Fix:** remove caches of finished lanes instead of linking them; a cache may be rewritten in place, which would change every linked copy.

## Perks

- The largest single win on a machine with many lane clones is often the public documentation: one repository's photographs checked out in a hundred clones.
- A lane's `.artifacts` file lists what it says can be rebuilt; a finished lane's report says what to keep. Read both; trust neither alone.
- `git bundle create FILE --all` keeps a record repository (evidence committed to Git with no remote) in one verifiable file at about the size of its `.git`.
