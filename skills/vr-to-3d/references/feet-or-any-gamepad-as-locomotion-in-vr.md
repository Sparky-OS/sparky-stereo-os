# Feet or any gamepad as locomotion in VR

**For contributors checking foot or gamepad locomotion:** find the input a game consumes and measure it before adding a driver.

Start with the game. A title can read the kernel pad through its usual controller API, bind a runtime action, or use a Foottroller network client. An OpenVR program on a flat stereo display can also move its simulated view. Establish which input the title consumes before adding a driver. The Foottroller Hub exposes ordinary `ABS_X` and `ABS_Y` stick events through uinput. [Linux gamepad specification](https://docs.kernel.org/input/gamepad.html#analog-sticks) · [Foottroller Hub input and output proof](../../gamecontroller/references/a-hub-for-a-device-nobody-has-on-the-bench.md)

## Working recipe

1. Identify the device in evtest. Record neutral, signed deflection, release and disconnect. Use a separate bench system for a real uinput device.
2. Check a title that takes the stick directly before configuring XR input. The title's gamepad binding usually suffices. For a native Xbox action, look for an active `/user/gamepad` profile and read a bound vector action after `xrSyncActions`. For SteamVR Input, check the component in the Input Debugger, then the title's binding and action. For xrizer pose navigation, read the pose or compare motion in a stationary scene. [OpenXR 1.1.65, Semantic Paths and Input Actions](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/input.adoc#L705) · [Valve, Device Inputs](https://github.com/ValveSoftware/openvr/blob/0924064316de3effbcd1acf1e309182a2deb1c05/docs/Driver_API_Documentation.md#device-inputs)
3. Repeat with the feet idle or absent, both hands active, then both foot and hand inputs active. Keep runtime selection and settings per test and restore them. Record an unavailable path at the boundary where it ends.

## What reaches the game

| Route | What to check |
| --- | --- |
| SteamVR on Linux, title-owned controller input | If a title reads and binds the pad through its own gamepad API, select its left-stick movement. In Proton, Steam Input can provide an XInput path where the title needs it. [Valve, Proton controllers](https://github.com/ValveSoftware/Proton/blob/bc896217ffcd67f892f952b010f898fe7bd0f0a1/docs/CONTROLLERS.md) |
| SteamVR Input on Linux | Valve documents a gamepad add-on and gamepad bindings. For a selected build that shows the add-on, check **Startup / Shutdown → Manage Add-Ons**, then bind the enumerated stick to the title's locomotion action. As of the 2026-11-23 source review, generic Linux evdev intake and the exact built-in component path were unverified. A distinct treadmill driver can publish X/Y alongside the two hands. Bind those components per title or to a legacy axis for a title that reads it. For an action using both treadmill and hand inputs, Valve specifies greatest absolute value. [Valve hotfix 2.14.4](https://store.steampowered.com/news/posts/?appids=250820&enddate=1769029640) · [Valve, Controller roles](https://github.com/ValveSoftware/openvr/blob/0924064316de3effbcd1acf1e309182a2deb1c05/docs/Driver_API_Documentation.md#controller-roles) · [Valve, Binding Profiles](https://github.com/ValveSoftware/openvr/blob/0924064316de3effbcd1acf1e309182a2deb1c05/docs/Driver_API_Documentation.md#binding-profiles) |
| OpenVR through xrizer | At `a6c27cc`, xrizer's legacy joystick and manifest input resolve through OpenXR hand profiles. An Xbox OpenXR action has no translation here. | Native OpenXR on DisplayXR | The evdev branch turns a readable pad into an Xbox-profile device and separately offers pose navigation and emulated hands. Release `c96f08b` and upstream main `2c9e351` used a Linux stub on the checked date. For OpenXR, the Microsoft Xbox Controller profile applies to `/user/gamepad`. The specification lists the stick components `/x` and `/y`. Suggest the full stick identifier `/user/gamepad/input/thumbstick_left` for a vector action under the rules for binding the parent path of a vector source. [OpenXR, Suggested Bindings](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/input.adoc#L476) The specification allows a runtime to omit an input path. [OpenXR 1.1.65, Input Subpaths and Microsoft Xbox Controller Profile](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/semantic_paths.adoc#L1063)

## Check headless

Build the clean pinned Monado tree with CMake, `XRT_FEATURE_SERVICE=OFF`, `XRT_MODULE_IPC=OFF`, `XRT_MODULE_COMPOSITOR_MAIN=ON`, `XRT_MODULE_COMPOSITOR_NULL=ON`, `XRT_FEATURE_OPENXR_HEADLESS=ON`, `XRT_BUILD_DRIVER_SIMULATED=ON` and `XRT_BUILD_DRIVER_REMOTE=ON`. Build `openxr_monado`. Use the build-tree manifest in `XR_RUNTIME_JSON` and set `XRT_COMPOSITOR_NULL=1`, `SIMULATED_ENABLE=1` and `SIMULATED_LEFT=wmr` for the first run. A network-none container with lavapipe and no device bind mounts is enough. CMake needs `glslangValidator` even for this route.

Create an OpenXR client with `XR_MND_headless`, a gamepad vector action and a separate left-hand vector action. Suggest the Xbox vector above, plus `/user/hand/left/input/thumbstick` for the Microsoft motion controller and Valve Index profiles. Attach the set, begin at READY, wait for FOCUSED, synchronize and print current profiles, `isActive` and X/Y. The simulated WMR hand reads active at center. The Xbox suggestion returns success and the gamepad is inactive.

For a moving control, start a separate run with `P_OVERRIDE_ACTIVE_CONFIG=remote`. In the same isolated container send `r_remote_data` to loopback port 4242 using the source's `r_interface.h` ABI. Read the two initial records, retain the active left controller, and change its `thumbstick` to (+0.500, −0.250), (−0.750, +0.375), then (0, 0). The Index hand action should follow all three samples. Withhold the packets and confirm the movement assertion fails. The gamepad must stay inactive in both runs. This control exercises runtime device to action to client. The kernel ingress needs a separate bench row. [Monado remote driver](https://gitlab.freedesktop.org/monado/monado/-/blob/2069b76b3a66fb5916e3cedae84d9524c1ebab4a/src/xrt/drivers/remote/r_interface.h) · [OpenXR headless extension](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/extensions/mnd/mnd_headless.adoc) · [OpenXR, Syncing Actions](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/input.adoc#L1318)

## Traps

| Symptom | Cause | Fix | How found |
| --- | --- | --- | --- |
| Xbox binding succeeds and the stick never moves | Suggested binding validates the profile and path. No device is supplying the role. | Read the current profile, `isActive` and signed states after a focused sync. Check the runtime input producer. | Simulated Monado accepted the Xbox binding and reported no gamepad. The Index hand control moved independently. |
| A headless build fails to configure or link | The configure checks for glslang, and the in-process runtime target links `comp_main` even when null is enabled. | Install the shader tools, compile both compositors, select null at run time and use lavapipe. | The first builds stopped at `glslangValidator required` and `cannot find -lcomp_main`. The next build reached a focused session. |
| The xrizer scene moves but the game's locomotion action does not | DisplayXR's navigation device supplies a rig pose. xrizer binds the action through a separate hand input path. | Observe pose and action independently. Use the title's direct pad support or a reviewed action mapping for its input API. | Compared DisplayXR's navigation and Xbox devices with xrizer's legacy and manifest source. |
| The feet cause hands to lose their assigned input | DisplayXR gamepad emulation can hold the hand roles while the pad is active. | Set `EMULATE_CONTROLLERS=0` for the feet route. Prove both existing hands with foot motion on the bench. | Read the pinned DisplayXR provider settings and role description. |
| SteamVR sees a treadmill but a particular title stays still | Role registration, action binding and title consumption are separate. Some titles restrict action results by hand or inspect devices themselves. | Check the registered component and the title's action versus its observed movement. Leave the hand roles available. | Valve's Controller roles and Binding Duplication sections and the public [OpenVR treadmill report](https://github.com/ValveSoftware/openvr/issues/1553). |
