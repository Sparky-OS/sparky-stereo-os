# A Unity game's route to Stereo KWin when no Editor runs on our side

Read from Cosmic Shore (Froglet Games, MIT, branch bleeding-edge at 01c1200, 2026-11-10) with a partial clone: `git clone --filter=blob:none --no-checkout --depth 1`, then `git ls-tree -r --name-only HEAD` for every path and `git show HEAD:PATH` for the few files that matter. The whole tree is 4 GB; the files below are about 130 MB.

## The recipe

1. **Platforms and CI first.** `ProjectSettings/ProjectVersion.txt` (Unity version), `Packages/manifest.json` (render pipeline, Cinemachine, any `com.unity.xr.openxr` or `com.unity.xr.management`; the modules `com.unity.modules.xr` and `vr` are built in and are not an OpenXR plugin), `ProjectSettings/XRSettings.asset`, `ProjectSettings/ProjectSettings.asset` (`m_BuildTargetGraphicsAPIs` lists only targets with a manual choice), `.github/workflows/*.yml`, `Docs/BUILD*.md`. Cosmic Shore: Unity 6000.3.17f1, URP 17.0.4, Cinemachine 3.1.2, no OpenXR or XR Management package, an `XRSettings.asset` with two defaults, no stereo code (grep of file names), a Linux build profile only for the Editor, builds for Windows (IL2CPP, Steam), Android and iOS; no Unity runner since 2026-10-13, so CI compiles nothing and Linux is never built.
2. **Look for a second engine before planning a Unity build.** `git ls-tree` showed a `Port/` folder: a first-party C# on .NET 10 engine (Amoebius) that runs the game's own `Assets/_Scripts` and scenes, an OpenGL 3.3 core renderer (GL ES 3.0 on phones) on Silk.NET and GLFW, documented for Windows and Linux desktop, tested on Linux under xvfb, with `Camera.projectionMatrix`, `worldToCameraMatrix`, `rect` and a `stereoEnabled => false` stub. It needs no Unity Editor, licence or account, and every part is Froglet's own under MIT (Silk.NET MIT, GLFW zlib, OpenAL Soft LGPL as a replaceable library, FMOD proprietary, fetched from Git LFS). That is the route that keeps the build ours.
3. **Where the second eye goes.** Gameplay cameras are plain cameras under `CustomCameraController` with `CameraSettingsSO` assets; Cinemachine is only `CameraManager.mainMenuCamera`, and the Menu_Main camera left Cinemachine in August 2026. So one world, two cameras means two projections of the one camera pose (parallel axes, off-axis frustum, plane at the vessel or the crystal), each through its own post stack (bloom and Panini per eye, never over the packed picture), the 2D layer (uGUI, HUD) drawn once per eye at one depth, and the present pass writing the two eyes side by side, declared once.
4. **Unity's own route, if it is ever wanted.** URP takes a second camera with a viewport rect and `projectionMatrix` set off-axis, but Screen Space Overlay canvases ignore the rect (use Screen Space Camera per eye). The OpenXR plugin's manual (1.14) lists Windows, UWP and Android targets and no Linux standalone; check the 6000.3 version of the plugin before counting on it. Either way a Linux player needs Unity's Editor with the Linux build support and a licence on Froglet's or Daniel's side (`com.unity.toolchain.win-x86_64-linux-x86_64` is the cross toolchain for building Linux IL2CPP on Windows).

## Traps

- **A manifest that names `com.unity.modules.xr` has no OpenXR.** Symptom: a reader counts it as an XR game. Cause: the built-in modules ship in every project. Check `packages-lock.json` for `openxr`.
- **A project's CI file can describe a runner that no longer exists** (the `unity` job is skipped while a repository variable is unset). Read the comment block at the top and the date in it.
- **Debian has no .NET SDK** (apt-cache in a forky container: dotnet-sdk-8.0, 9.0 and 10.0 have no candidate); the engine builds with Microsoft's SDK, so the edition ships a self-contained `linux-x64` publish, not a dependency on a runtime package.
- **A bundled GLFW may be X11 only.** Silk.NET ships its own native GLFW; on Wayland the window would run through Xwayland unless the system libglfw3 (3.5.1, Wayland and X11) is used. Not tested yet.
